# super_candy

宇宙无敌超级棒棒糖！

**一个能在浏览器里打完一整通外呼电话的数字员工**：麦克风说话 → 云端识别成文字 →
状态机按六个环节推进 → 云端合成语音播回来 → 谈成了就结构化回写一张工单。

对应赛题「智语外呼」。同时它也是 5 人团队的协作骨架：把一条完整链路先跑通，
再由每个人各自替换其中一段。

> **⚠️ 用 zip 下载（而不是 `git clone`）跑的，先看这里再启动**：
> `config/secrets.json` **不会跟着 zip 走**——密钥文件被 `.gitignore` 排除（防泄漏的设计），
> 所以 zip 解压出来一定没有它。没配它，语音会自动降级成浏览器机械音、识别也不准，
> 而且事件库里只留一句"未配置 dashscope_api_key"，不熟的人很难查出原因。
> 配法只要 30 秒，见下文[「想听到真人声音（要配密钥）」](#想听到真人声音要配密钥)一节。

**2026-11-11（晚五）· 「您回一个字也行」换成推进型后缀 + 前端 PR 评审落地**：

用户圈着截图里那句「……缺了品牌方到一级经销商的逐级授权文件。您回一个字也行。」
问哪里奇怪。四个毛病：同义反复（授权链路不完整 = 缺逐级授权文件）；陈述与索要
回应硬拼；"回一个字"没有可执行答案；"也行"带预设、且客户刚"哦"过等于没听见。
根因又是词表打地鼠：模型说的是「没通过/授权文件」，`_SKIP_SUFFIX_MARKS`
（驳回/材料/授权书）一个没命中。这次不再加词，改成**按后缀意图分流**：
讨回应型讲完事实一律不加；推进型（`kind=advance`）讲完事实正是该问
「这一步您清楚怎么补吗？」的地方。quiet 规则按阶段收敛到 NEED/OFFER/CONFIRM，
不再有无差别 `"*"`；优化器候选池同步换掉。用户选定后半句 = 「这一步您清楚怎么补吗？」。

同时评审并落地 `feat/ui-simplify`（前端重做 PR）：方向对，但操作逻辑的根因是
**状态靠"看"不靠"算"**——3 个 MutationObserver 盯着 DOM 反推 + 7 处直接改按钮。
评审抓到的硬伤：挂断后事件链是死路（end_call 删会话，提示却让用户去看）、
两通对话混一个框、空 Enter 等于一次沉默轮、纯文字模式挂着永远点不动的
暂停键、`window.__textMode` 全局变量 + 两套绑定并存、startCall 无 try。
重构成一处理算：`UI_STATES` 5 态 + `render()`，删掉全部观察器，9 条全修；
新增 `scripts/ui_smoke.mjs`（playwright，23 条）全过——冒烟第 ⑦ 步还抓出
我自己引入的"挂断后找不到再打一通按钮"回归，已修。

结果：`verify` **260/260**（+3）、逐句复盘 **29/29**、性格基线 p9 → **p10**、
UI 冒烟 **23/23**。main `1362142` 已推送；`feat/ui-simplify` 已同步 main 并推送
（`a164c8e`），待前端负责人按 PR 流程合入。详见
[docs/46](docs/46_那句您回一个字也行与前端PR评审.md)。

**2026-11-11（晚四）· 别叫名字、别把「好吧」当没听见、别让客户等两秒**：

用户发来线上截图，三句话把三种错摆在一起看：「不要直接叫名字啊喂，你怎么确定
他说公司的那个部门的人，就敢说人名？」「而且我回好吧，应该是这个回复吗？」
「还有反应时间严重超过 2s，这还不算语音输入，是什么情况？」

**① 直呼姓名。** 模型把档案里的「联系人：晏青梧」直接当称呼放在了句首
（`晏青梧，您简单回我一句…`）。核身通过只能证明"这个号码对应这笔单"，
证明不了"接电话的人叫这个名字"——可能是同事、前台，也可能是打错的。
更糟的是客户只说了一句"是我"，客服就把姓名念给了一个还没确认身份的人。
修法三条：prompt 明确不许叫名字（"张经理"也不行）；出话后 `_drop_name_call`
只删**称呼位置**的姓名，句子中间讲事实的不动；规则层的承接句也不再把
档案姓名拼进「对，是您本人，{姓名}」——客户自己报了名字才复述。

**② 「好吧」被当成没表态。** 客户答「好吧」，客服又问一遍「您简单回我一句
清楚了或者还有疑问就行」，客户只好补一句「知道了」才闭环——而这两句是同一个
意思，系统认一个不认另一个。根因是 `WEAK_YES` 的置信度压在阈值下面，
设计初衷（营销场景里"好吧"等于"我不想跟你争了"）没错，但这一通问的是
**「清楚了吗」**，记的是 `merchant_understood`。修法：在 pop 场景的
`confirm_yes_words` 里补「好吧」「行吧」；营销场景不配，`test_intent`
那三条原样守。顺带把「您简单回我一句…」后面又挂「您回一个字也行」的
双重讨回应也堵了（`_SKIP_SUFFIX_MARKS` 补「回我一句/回一句/简单回」）。

**③ 2 秒。** 先拆口径：1369ms 是 ASR + 出话 + TTS 首段，不是模型一家。
再实测模型这一层，同一句：qwen-plus P50 **832ms**（1010/937/728/715），
qwen-flash P50 **425ms**（335/380/470/612）。还有一个坑：`llm.chat` 默认
`timeout=2.5, retries=1`，超时后 sleep 0.6 再试，**最坏 5.6 秒**——语音轮
P95 2289ms 和面板上那个"超时 1"就是这条长尾。改成 qwen-flash + 1.5s 超时 +
不重试 + 120 tokens，三个值进配置。改完真空跑一段（模型开着）：
439 / 599 / 5 / 387 / 529 ms，出话 P50 ~450ms，"好吧"那一轮直接闭环。

结果：`verify` **257/257**（新增 6 条）、88 条 **88/88**、逐句复盘 **29/29**、
对抗 31/34（与 11-08 基线同三条 AD02/AD03/L912，没新增）、
L2 基线 v40 → **v41**（10 通结果逐字未变，只对齐哈希）。
详见 [docs/45](docs/45_别叫名字别把好吧当没听见别让客户等两秒.md)。

**仍没解决**：TTS 还是整句合成，首段要等整句出来，真压到 1 秒内得改流式；
「好吧」靠场景词表放行，客户换个说法（"那行吧""行，就这样"）仍是含糊；
本地复跑还看到一个别的问题——客户问"要补什么材料"，骨架只回"请补齐后重新提交"，
三样材料的名字一个没念。

## 一、这个项目是干什么的

京东这类平台的客服外呼，难点不在"能对话"，而在三件事同时成立：

1. **流程必须走完**——自报身份、核验、问需求、讲权益、确认、回写，少一环就是不合格；
2. **说得快**——首字响应 P50 ≤ 2000ms，慢了用户就挂电话；
3. **说得对**——不能承诺没授权的权益，不能泄露完整手机号，用户拒绝也要留痕。

所以它不是"套个大模型聊天"，而是**状态机管流程、大模型管说话**：
环节推进由代码硬控（`modules/dialogue.py`），话术和判断才交给模型或规则。
每发生一件事都写成一条带时间戳的事件，落进 SQLite——转写、质检、时延、成本
全部从这一条事件流里派生，避免"几套数据对不上"。

> 想理解为什么这么设计：**[docs/01_架构与分工设计.md](docs/01_架构与分工设计.md)**

## 二、现在能做什么

### 已经真跑通的（每条都有断言或实测记录）

| 能力 | 说明 |
|---|---|
| **六环节走完** | 开场自报身份 → 身份核验 → 需求 → 权益 → 确认 → 结构化回写；走到回写真的建工单 |
| **语音采集** | 浏览器 AudioWorklet，16kHz / 单声道 / 20ms 一帧，每 8 帧上传一片，序号可校验 |
| **连续对话（免按键）** | 麦克风通话期间常开，前端逐帧判"像不像人声"（能量 + 过零率 + 谱倾斜，连续 40ms 才算开口），静音 700ms 自动提交，全程不用点按钮 |
| **随时打断（三段式）** | 播报时麦克风常开。能量超阈值只算「疑似」：先把音量压到 12%（约 60–80ms，用户已感觉客服让路），再把这段送去识别，**认出实义文字才真停**（约 660–780ms）。咳嗽、碰麦、`嗯`、白噪声都不会把客服打断 |
| **云端识别** | `qwen3-asr-flash`，真人说话能准确转文字（ITN 开启，"八八六六"→"8866"） |
| **云端合成** | `qwen3-tts-flash`，音色 Serena，服务端合成后返回音频链接，前端 `<audio>` 播 |
| **端点检测（Z6）** | 服务端不再"有字节就算说了话"：逐帧判定 + 起止聚合，九类噪声 0/9 触发；引擎优先 Silero，没装 onnxruntime 自动降级纯标准库谱特征门（两条都是 12/12 人声、0/9 噪声） |
| **含糊不当拒绝** | 第一次追问，仍含糊才记 `unknown`；用户改口会更正**同一张**工单 |
| **拒绝也回写** | 没谈成也要留痕，业务侧才知道这通电话的结果 |
| **沉默不伪造** | 记 `no_answer`，追问一次，连续两次才挂断 |
| **合规护栏** | 命中禁语整句替换，不打码；隐私字段入库前打码 |
| **质检五项** | 闭环、辱骂、虚假承诺、诱导、隐私、必说话术，判不了的标 `skipped` 而不是蒙一个 |
| **时延双口径** | 服务端处理耗时 + 浏览器实测首字响应（T4−T0），两个数分开统计，不混着报 |
| **失败不静默** | 识别两轮墙钟闸门 2s→3s（`urllib` 的 timeout 只管单次 socket，管不住总时长）；429 限流退避重试；合成失败回落浏览器播报；断连会重试而不是直接没声 |
| **指标看板** | `/dashboard` 一个页面看完：时延双口径、闭环分布、事件类型、逐通摘要、质检汇总、库体积。只读，15 秒缓存 |
| **多场景切换** | `config/scenes/` 放多套话术，`APP_SCENE=xxx` 或 `POST /api/scene` 运行时切；切之前会告诉你**有几通电话正在用旧场景** |
| **成本闸门** | 日成本上限 + 每分钟轮次限制，**默认关闭**（演示前不动配置就等于没有这一层） |
| **Mock 业务系统** | `mock_business/` 独立起一个服务（:8100）：查客户 / 查订单 / 建工单，幂等 + 错误码 |
| **事件归档** | `scripts/archive_events.py` 把 N 天前的数据搬到 `data/archive/`，**校验写成功才从主库删** |
| **WebSocket 双向通道** | `/ws/call`：音频帧从 HTTP 分片改为 WS 直推，TTS 分段"就绪即推"（不再轮询 `/api/tts/rest`），`barge_in` 走协议事件；前端保留 HTTP 回退 |

### 还没做的（不是忘了，是排期在后面）

- **Real provider 没接真实京东接口**（`modules/adapters/real.py` 有了，但地址与鉴权没接过真环境）。
  现在默认走 Mock 档案（188 条 CSV，覆盖官方 68 场景）+ `mock_business/` 沙箱服务，演示与评测都够用。
- ~~实时字幕没做~~ **已做（Z7）**：默认开启，半句字幕 + 整句落袋，见上表与 `docs/16`。
  仍有的边界：字幕只对"正在说的这一句"负责，跨轮的整段历史在对话日志里，不在字幕条上。
- **说话人只做到"影子模式"**：能判"像不像开场应答那位"（EER 16%），但**没有开拦截**——
  数字全部来自 TTS 五个音色，不是真人。缺一次真机录音标定（本人 5 句 + 换人 5 句）才能改
  `mode: "enforce"`。另：旁人抢在**第一句**接电话这条挡不住（拨号前没有可比模板，任何方案都挡不住）。
  跨性别几乎不会错（0.20~0.26），同性别近音色（夫妻/同事）才是风险区（0.64~0.70）。
- **语义级合规没做**：禁语仍是词表匹配，换个说法就漏（3 号）。
- **`_take_identity_slots` 只认"我叫/姓X"**：商家说"就是晏青梧"这类自然表述会被漏掉，
  模拟跑批已把它刨出来（标 `needs_code`），属代码缺陷、尚未修。
- **"没听明白"仍被当"拒绝整改"回写**：`_stage_confirm` 的分支要收紧，同样是代码缺陷。
- **L2 只进到文本层**：模拟器不模拟声学误差（噪声/口音/断句），10 个画像覆盖有限，
  候选是单轮补丁而非多轮搜索；L3 权重微调（SFT/LoRA）**不做**——数据量不够、不可复现、合规难审计。
- **评测集口径**：`run_eval` 30 条仍与判定规则同源（过拟合风险写在 `docs/06` 第 7 节）；
  另有对抗集 9 批与 10 条模拟画像，但不能代替 80–120 条独立标注集（3 号）。

## 三、怎么用

### 最快的方式

按系统选一个入口（效果一样，都是启动本地服务并自动开浏览器到 `http://127.0.0.1:8000`）：

- **Windows**：双击项目根目录的 **`启动.bat`**
- **macOS**：双击 **`启动.command`**。首次若提示“无法验证开发者”，在 Finder 里**右键 → 打开**；
  如果双击被文本编辑器打开，先在终端执行一次 `chmod +x 启动.command` 再双击。
  也可以直接命令行：`cd 项目目录 && python3 app.py`
- **Linux / 通用命令行**：`python3 app.py`

启动后 → 点「开始通话」。

点完「开始通话」就不用再碰按钮了：**直接说话**，说完约 0.7 秒自动提交；
客服说话时**可以直接插话打断**，它会立刻闭嘴。想安静一下可以点「暂停聆听」（等于电话的静音键）。

零第三方依赖，Python 3.9 以上。关掉黑窗口就是停止服务。

### 让它自进化（不用敲命令）

- **Windows**：双击项目根目录的 **`自进化.bat`**
- **macOS**：双击 **`自进化.command`**。首次若被文本编辑器打开，先在终端执行一次
  `chmod +x 自进化.command` 再双击；提示「无法验证开发者」时右键 → 打开。

黑窗口会按 **1 体检 → 2 读基线 → 3 提案 → 4 闸门 → 5 上架** 逐条打印，
**三条链各跑一遍**：L2 话术链、性格链、自适应对抗链。第 1 步会重跑对抗基线
复算分数，代码或模拟器改过却没重定基线就直接中止，不许把别处的收益算到
话术候选头上。第 5 步只给出上架命令，**不会自己改线上话术**。等价的命令行写法是
`python scripts/auto_evolve.py`：默认用本地确定性模板起草，不联网、不花钱、不依赖密钥；
想改由大模型起草，在终端加 `--llm`，起草坏的文案仍由本地模板兜底。
空草稿会就地重做并填好，不会再停在「话术还空着」而进不了闸门。

**反复双击不会让客服自动变聪明**：脚本只负责防劣化、留证据、可回滚。
分数要真涨，得先有新的失败样本——**第 0 步的真实通话体检里「仍会复现」的条目**
就是最值钱的样本（用户真踩到的），其次是往 `eval/personas_adversarial.json` 加更难的
画像（独立挑战集，不动 10 通与 12 画像的分母），或修掉只改代码那几簇里的缺陷；
改完先重定基线，再双击同一个文件。

### 从真实用户对话里学（真实通话体检）

```bash
python scripts/mine_calls.py mine            # 扫 data/events.db → 缺陷 → 聚类 → 报告
python scripts/mine_calls.py mine --verify   # 再加一步：用当前代码重放，判「是否还会犯」
python scripts/mine_calls.py replay --code real_repeat   # 逐轮看改前 vs 重放后的原话
python scripts/mine_calls.py compare --since 2026-11-09T12:00:00  # 上线后按时间对比
python scripts/mine_calls.py check           # 11 项反向自测
```

判据在 `modules/real_audit.py`：沉默复读、相邻复读、三轮循环、已给数字又要一遍、
指代含糊、用错核身凭证、答非所问。真实通话没有模拟器那套动作名与 `expect.closed`，
所以判据只用两类证据——**逐字文本**与**事件结构**；报告只留脱敏原话（数字打码、
「某某女士/先生」打码），原文用于「这句是否还在配置里」的比对后即丢弃。

一条纪律：真实数据里的话术可能来自旧版本。报告给每个缺陷码标状态——
`否（已修）`= 原话已不在当前配置；`重放已消`= 原话还在但当前代码重放不再犯；
`是`= 现在仍在犯。只有前两种之外的那一类值得开新候选。

### 对抗自进化（客户不断上难度）

已经并进上面那个双击入口；下面这四步是单跑对抗链时的等价写法。
`一键自进化` 的画像参数固定；`scripts/adversarial_evolve.py` 用 `AdversarySim`，
客户按客服暴露的弱点主动把压力从 L1 升到 L4，专门攻击复读、答非所问、
已给的信息又被要一遍、指代含糊、把提问当成含糊。四步：

```bash
python scripts/adversarial_evolve.py run        # 对抗基线（报告是生成物，不进仓库）
python scripts/adversarial_evolve.py propose   # 失败簇 → 候选骨架，并列出只改代码/待归因项
# 填好候选里的 patches[].value
python scripts/adversarial_evolve.py gate config/evolution/candidates/adv001.json
python scripts/adversarial_evolve.py check     # 10 项反向自测
```

画像集 `eval/personas_adversarial.json` 与 10 通基线、12 性格画像完全分开；
闸门多一道「按难度分组无回退」，只留档、**不自动上线**。失败里凡是需要改代码
或归因器没覆盖的，都单独列出，不交给话术优化器。挑战集目前 16 通画像
（A01～A10 原始集 + A11～A16 挑战集：低耐心 confirm 考零浪费轮次、
高耐心 offtopic 考长通话韧性、2 个留出集只验收）。

**想在网页上看训练过程**：首页最上面的「训练回放」卡片，选画像点「开始训练」，
逐轮播放这场对抗电话并红标每轮被抓住的弱点。接口是 `GET /api/train/personas`
和 `POST /api/train/run`；训练在独立临时事件库 + 强制模板话术下真跑一场，
不写生产数据、不调大模型、有通话进行中会被拒绝。等价的命令行写法是
`python scripts/test_train_api.py`（隔离与恢复共 10 项自测）。

> **不要双击 `web/index.html`**：它需要后端才能工作，双击只会看到一堆失败请求。
> 正确入口永远是 `http://127.0.0.1:8000`。

### 想听到真人声音（要配密钥）

不配也能跑，但识别走占位实现（返回固定句）、声音是浏览器机械音。配了才是真的：

1. 注册阿里云百炼，拿一个 **API Key**（`sk-` 开头，**不是** `LTAI` 开头的 AccessKey）；
2. 写进 `config/secrets.json`（已 gitignore），或设环境变量 `DASHSCOPE_API_KEY`；
3. 验一下：`python scripts\check_key.py`
4. **重启服务端**（Python 不会热加载，不重启等于没改）

详细步骤（含费用、限额、踩坑）：**[docs/15_开通云ASR.md](docs/15_开通云ASR.md)**

同一把 key 同时管识别和合成，不用开通第二个服务。

## 四、注意事项（踩过的坑，别再踩）

**关于密钥**
- 只认 `sk-` 开头的 API Key。`LTAI` 开头的是 AccessKey，不能用，也不会自动转。
- `config/secrets.json` 已在 .gitignore 里。**不要写进 `scene.json`、不要发群、不要截图**。
- 万一 AccessKey 泄露了，去控制台**禁用并删除**，不是改密码就完事。

**关于声音**
- **用外放时把音量调低或戴耳机。** 以前 TTS 是浏览器念的、服务端不出声，不会有回声；
  现在服务端真发声，播报声可能被麦克风收进下一轮上行音频。
- 音色是 `Serena`（温柔女声）。开场白写的是"客服中心的小采"，换成男声记得同时改话术。

**关于速度（30 轮基准实测，服务端口径）**

| 指标 | P50 | P95 | max |
|---|---|---|---|
| 识别 | 390ms | 630ms | 642ms |
| 首段合成 | 457ms | 795ms | 804ms |
| 服务端总响应 | **974ms** | 1210ms | 1417ms |

- **30/30 轮在 2000ms 门槛内。** 门槛卡 P50，P95 也还有约 800ms 余量。
- 浏览器实测还要加一个网络往返 + 播放启动（约 100–250ms），所以真实首字约 **1.1–1.4 秒**。
  这两个口径**不能混着报**，混着报就是编数据。
- 跑过两轮同样的基准，P50 都在 1 秒左右，但**长尾是偶发的**：第一次首段合成
  撞过一次 4556ms（4 秒闸门超时后重试成功），第二次一次都没撞上。
  机制上兜得住，但演示时赶上的概率不为零。
- 合成按句切两段，服务端**只等第一段**就返回，剩余段落后台串行合成
  （`/api/tts/rest`）。所以"最后一句特别长"不再拖慢首字。
- 复现：`python scripts/bench_voice.py`。方法与局限见
  **[docs/04](docs/04_时延打点规范.md)** 第 8 节。
- 为什么不做流式：分段已经把头段压到几百毫秒，而流式要换 WebSocket 双向通道，
  收益递减。真要再快，下一步是流式而不是继续切句子。

**关于数据**
- **`run_eval.py` 的 30/30 不能拿去汇报。** 用例和规则是互相照着写的，
  过拟合风险写在 `docs/06` 第 7 节，汇报前必读。
- 事件库里存的是打码后的文本（尾号变 `****`），但原始音频不落盘，只在内存里过一遍。
- **跑批和基准都写临时库，不碰 `data/events.db`。** 这一点很关键：测试用例的
  识别耗时是 0ms，一旦混进生产库，首字 P50 会被拉到几十毫秒——看着漂亮，实际是假的。
  已经踩过一次（305 个会话里 300 个是跑批产物），清理工具是 `scripts/clean_events.py`。

**关于评测与自检**
- `run_eval.py` 跑批时**不会**调云端合成（离线隔离），不会花钱、没有密钥也能跑。
- 自检和跑批都用临时库，不会污染 `data/events.db`。
- 查库：`python scripts/clean_events.py`（只预览，不动数据）。它会按"识别耗时是否大于 0"
  分出真人通话和跑批产物，并列出每通真人通话说了什么。

**关于欠费**
- 云端识别和合成共用同一把 API Key。**余额用尽时两边都会报 400 Arrearage**，
  现在会直接提示"账户欠费"，而不是含糊的"接口返回 400"。
- 欠费时系统不会崩：识别回落成空文本（走"没听清"分支），合成回落成浏览器播报。
  但演示前一定要确认余额，否则评委听到的是机械音。

## 七、怎么验证我改的东西没坏

```bash
python scripts/verify.py       # 209 条行为断言，用临时库，不污染 data/
python scripts/run_eval.py     # 30 条用例跑批（离线，不调云端）
python scripts/sim_eval.py     # 10 类模拟用户跑完整通话 + 逐轮归因（不调云端）
python scripts/evolve.py status            # 现在线上是哪一版话术、分数多少、能不能回滚
python scripts/check_mock_bundle.py --self-test   # mock 数据包七类校验 + 6 种变异反向测试
python config_loader.py        # 配置结构与占位符校验（一秒出结果）
python scripts/archive_events.py --stats   # 事件库体检：体积、行数、索引
```

`verify.py` 每条都打出**实际事件链和字段值**，不是只打个 PASS——
结论可以被伪造，原始输出不能。

想复现"话术进化"这一整套（不是只看结果，是自己跑一遍）：

```bash
python scripts/evolve.py rollback                     # 退回上一版（回滚点永远留着）
python scripts/sim_eval.py --tag baseline \
       --json eval/reports/sim_baseline.json --report eval/reports/sim_baseline.md
python scripts/evolve.py init --scene config/scenes/pop_reject.json \
       --baseline eval/reports/sim_baseline.json      # 基线必须与场景内容哈希对得上
python scripts/evolve.py propose --out config/evolution/candidates/c001.json
python scripts/evolve.py gate config/evolution/candidates/c001.json   # 五道闸门
python scripts/evolve.py promote v2                   # 过闸门才允许上线
```

> `gate` 会拒绝三类候选：train 掉分、holdout 掉分、没有实际收益。
> 它也会拒绝**基线来源不明**的跑批结果——基线绑定场景内容哈希，
> 拿改过话术之后的分数当"没改过的标准"会直接被拦下（这条负向测试验过）。

也可以双击：Windows **`验证.bat`** / macOS **`验证.command`**。
