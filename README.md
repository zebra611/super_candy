# super_candy

宇宙无敌超级棒棒糖！

**一个能在浏览器里打完一整通外呼电话的数字员工**：麦克风说话 → 云端识别成文字 →
状态机按六个环节推进 → 云端合成语音播回来 → 谈成了就结构化回写一张工单。

对应赛题「智语外呼」。同时它也是 5 人团队的协作骨架：把一条完整链路先跑通，
再由每个人各自替换其中一段。

> **⚠️ 用 zip 下载（而不是 `git clone`）跑的，先看这里再启动**：
> `config/secrets.json` **不会跟着 zip 走**——密钥文件被 `.gitignore` 排除（防泄漏的设计），
> 所以 zip 解压出来一定没有它。没配它，语音会自动降级成浏览器机械音、识别也不准，
> 而且事件库里只留一句"未配置 dashscope_api_key"，不熟的人很难查出原因。
> 配法只要 30 秒，见下文[「想听到真人声音（要配密钥）」](#想听到真人声音要配密钥)一节。

**2026-11-08 · 官方 QA 接进对话（27 条原话真的能回答商家了）**：
上一轮把官方资料包转成了 `config/mock/qa.json`，但只做到"接口可查"——
商家在电话里问"在职证明有哪些"，客服仍然回 `reply_unknown`。这轮把它接进状态机，
**六个阶段、七个提问出口**都改了，代价是全套断言要重跑一遍。

接的时候发现四个必须当场定的问题（都记在 [docs/34](docs/34_mock数据包.md) §8）：

- **官方优先于 `kb.json`**：官方是审核员原话，能逐字复述；kb 是我们自己的口径。
  同一句两边都能答时，能复述原话的优先。
- **原话不过措辞层**：`_reply` 里只要带 `qa_hit` 就冻结 nlg 改写。
  改一个字就不再是"官方原话"，被追问依据时站不住。
- **占位答案整条不播**：官方 27 条里 **5 条**带未填的 `XX`（"在商标状态变为XX后重新提交"），
  `kb_pop.json` 里 **96 条**驳回话术带 `【】` 槽位。逐字播报会让 TTS 念出
  "叉叉""左右括号"；自己补词就是编造口径。改成不播 + 记进 `answer_blocked`，
  补完数据就自动生效，不用改代码。
- **同一句不重复播**：按 `qid` 和**原文**双重去重——`kb_pop` 里有几条是照官方原文抄的，
  只按 id 去重的话第二次会从 kb 那边把同一句话原样再念一遍。

顺手修掉两个真实缺陷：

- **CONFIRM 阶段把提问当成了含糊**：商家问"这个会不会影响我店铺评分"，
  旧路径回"您简单回我一句清楚了或者还有疑问"，两轮后工单记 `unknown` 转专员。

## 一、这个项目是干什么的

京东这类平台的客服外呼，难点不在"能对话"，而在三件事同时成立：

1. **流程必须走完**——自报身份、核验、问需求、讲权益、确认、回写，少一环就是不合格；
2. **说得快**——首字响应 P50 ≤ 2000ms，慢了用户就挂电话；
3. **说得对**——不能承诺没授权的权益，不能泄露完整手机号，用户拒绝也要留痕。

所以它不是"套个大模型聊天"，而是**状态机管流程、大模型管说话**：
环节推进由代码硬控（`modules/dialogue.py`），话术和判断才交给模型或规则。
每发生一件事都写成一条带时间戳的事件，落进 SQLite——转写、质检、时延、成本
全部从这一条事件流里派生，避免"几套数据对不上"。

> 想理解为什么这么设计：**[docs/01_架构与分工设计.md](docs/01_架构与分工设计.md)**

### 已经真跑通的（每条都有断言或实测记录）

| 能力 | 说明 |

| **六环节走完** | 开场自报身份 → 身份核验 → 需求 → 权益 → 确认 → 结构化回写；走到回写真的建工单 |

## 三、怎么用

### 最快的方式

按系统选一个入口（效果一样，都是启动本地服务并自动开浏览器到 `http://127.0.0.1:8000`）：

- **Windows**：双击项目根目录的 **`启动.bat`**
- **macOS**：双击 **`启动.command`**。首次若提示“无法验证开发者”，在 Finder 里**右键 → 打开**；
  如果双击被文本编辑器打开，先在终端执行一次 `chmod +x 启动.command` 再双击。
  也可以直接命令行：`cd 项目目录 && python3 app.py`
- **Linux / 通用命令行**：`python3 app.py`

启动后 → 点「开始通话」。

点完「开始通话」就不用再碰按钮了：**直接说话**，说完约 0.7 秒自动提交；
客服说话时**可以直接插话打断**，它会立刻闭嘴。想安静一下可以点「暂停聆听」（等于电话的静音键）。

零第三方依赖，Python 3.9 以上。关掉黑窗口就是停止服务。

### 让它自进化（不用敲命令）

- **Windows**：双击项目根目录的 **`自进化.bat`**
- **macOS**：双击 **`自进化.command`**。首次若被文本编辑器打开，先在终端执行一次
  `chmod +x 自进化.command` 再双击；提示「无法验证开发者」时右键 → 打开。

黑窗口会按 **1 体检 → 2 读基线 → 3 提案 → 4 闸门 → 5 上架** 逐条打印。
第 5 步只给出上架命令，**不会自己改线上话术**。等价的命令行写法是
`python scripts/auto_evolve.py`：默认用本地确定性模板起草，不联网、不花钱、不依赖密钥；
想改由大模型起草，在终端加 `--llm`，起草坏的文案仍由本地模板兜底。
空草稿会就地重做并填好，不会再停在「话术还空着」而进不了闸门。

> **不要双击 `web/index.html`**：它需要后端才能工作，双击只会看到一堆失败请求。
> 正确入口永远是 `http://127.0.0.1:8000`。

### 测试台：随机预览 / 纯文字模式（不花钱、不用麦）

### 想听到真人声音（要配密钥）

不配也能跑，但识别走占位实现（返回固定句）、声音是浏览器机械音。配了才是真的：

1. 注册阿里云百炼，拿一个 **API Key**（`sk-` 开头，**不是** `LTAI` 开头的 AccessKey）；
2. 写进 `config/secrets.json`（已 gitignore），或设环境变量 `DASHSCOPE_API_KEY`；
3. 验一下：`python scripts\check_key.py`
4. **重启服务端**（Python 不会热加载，不重启等于没改）

详细步骤（含费用、限额、踩坑）：**[docs/15_开通云ASR.md](docs/15_开通云ASR.md)**

## 四、注意事项（踩过的坑，别再踩）

**关于密钥**
- 只认 `sk-` 开头的 API Key。`LTAI` 开头的是 AccessKey，不能用，也不会自动转。
- `config/secrets.json` 已在 .gitignore 里。**不要写进 `scene.json`、不要发群、不要截图**。
- 万一 AccessKey 泄露了，去控制台**禁用并删除**，不是改密码就完事。

**关于声音**
- **用外放时把音量调低或戴耳机。** 以前 TTS 是浏览器念的、服务端不出声，不会有回声；
  现在服务端真发声，播报声可能被麦克风收进下一轮上行音频。
- 音色是 `Serena`（温柔女声）。开场白写的是"客服中心的小采"，换成男声记得同时改话术。

**关于速度（30 轮基准实测，服务端口径）**

| 指标 | P50 | P95 | max |
|---|---|---|---|
| 识别 | 390ms | 630ms | 642ms |
| 首段合成 | 457ms | 795ms | 804ms |
| 服务端总响应 | **974ms** | 1210ms | 1417ms |

- **30/30 轮在 2000ms 门槛内。** 门槛卡 P50，P95 也还有约 800ms 余量。
- 浏览器实测还要加一个网络往返 + 播放启动（约 100–250ms），所以真实首字约 **1.1–1.4 秒**。
  这两个口径**不能混着报**，混着报就是编数据。
- 跑过两轮同样的基准，P50 都在 1 秒左右，但**长尾是偶发的**：第一次首段合成
  撞过一次 4556ms（4 秒闸门超时后重试成功），第二次一次都没撞上。
  机制上兜得住，但演示时赶上的概率不为零。
- 合成按句切两段，服务端**只等第一段**就返回，剩余段落后台串行合成
  （`/api/tts/rest`）。所以"最后一句特别长"不再拖慢首字。
- 复现：`python scripts/bench_voice.py`。方法与局限见
  **[docs/04](docs/04_时延打点规范.md)** 第 8 节。
- 为什么不做流式：分段已经把头段压到几百毫秒，而流式要换 WebSocket 双向通道，
  收益递减。真要再快，下一步是流式而不是继续切句子。

**关于数据**
- **`run_eval.py` 的 30/30 不能拿去汇报。** 用例和规则是互相照着写的，
  过拟合风险写在 `docs/06` 第 7 节，汇报前必读。
- 事件库里存的是打码后的文本（尾号变 `****`），但原始音频不落盘，只在内存里过一遍。
- **跑批和基准都写临时库，不碰 `data/events.db`。** 这一点很关键：测试用例的
  识别耗时是 0ms，一旦混进生产库，首字 P50 会被拉到几十毫秒——看着漂亮，实际是假的。
  已经踩过一次（305 个会话里 300 个是跑批产物），清理工具是 `scripts/clean_events.py`。

**关于评测与自检**
- `run_eval.py` 跑批时**不会**调云端合成（离线隔离），不会花钱、没有密钥也能跑。
- 自检和跑批都用临时库，不会污染 `data/events.db`。
- 查库：`python scripts/clean_events.py`（只预览，不动数据）。它会按"识别耗时是否大于 0"
  分出真人通话和跑批产物，并列出每通真人通话说了什么。

**关于欠费**
- 云端识别和合成共用同一把 API Key。**余额用尽时两边都会报 400 Arrearage**，
  现在会直接提示"账户欠费"，而不是含糊的"接口返回 400"。
- 欠费时系统不会崩：识别回落成空文本（走"没听清"分支），合成回落成浏览器播报。
  但演示前一定要确认余额，否则评委听到的是机械音。

## 七、怎么验证我改的东西没坏

```bash
python scripts/verify.py       # 209 条行为断言，用临时库，不污染 data/
python scripts/run_eval.py     # 30 条用例跑批（离线，不调云端）
python scripts/sim_eval.py     # 10 类模拟用户跑完整通话 + 逐轮归因（不调云端）
python scripts/evolve.py status            # 现在线上是哪一版话术、分数多少、能不能回滚
python scripts/check_mock_bundle.py --self-test   # mock 数据包七类校验 + 6 种变异反向测试
python config_loader.py        # 配置结构与占位符校验（一秒出结果）
python scripts/archive_events.py --stats   # 事件库体检：体积、行数、索引
```

`verify.py` 每条都打出**实际事件链和字段值**，不是只打个 PASS——
结论可以被伪造，原始输出不能。

想复现"话术进化"这一整套（不是只看结果，是自己跑一遍）：

```bash
python scripts/evolve.py rollback                     # 退回上一版（回滚点永远留着）
python scripts/sim_eval.py --tag baseline \
       --json eval/reports/sim_baseline.json --report eval/reports/sim_baseline.md
python scripts/evolve.py init --scene config/scenes/pop_reject.json \
       --baseline eval/reports/sim_baseline.json      # 基线必须与场景内容哈希对得上
python scripts/evolve.py propose --out config/evolution/candidates/c001.json
python scripts/evolve.py gate config/evolution/candidates/c001.json   # 五道闸门
python scripts/evolve.py promote v2                   # 过闸门才允许上线
```

> `gate` 会拒绝三类候选：train 掉分、holdout 掉分、没有实际收益。
> 它也会拒绝**基线来源不明**的跑批结果——基线绑定场景内容哈希，
> 拿改过话术之后的分数当"没改过的标准"会直接被拦下（这条负向测试验过）。

也可以双击：Windows **`验证.bat`** / macOS **`验证.command`**。
