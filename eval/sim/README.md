# 文字对抗测试系统（模拟客户 ↔ 客服系统）

> 实验分支：`exp/sim-adversarial`。属 R3 评测工具，不改任何人的代码。
> 一句话：**一半角色由系统演，一半由客服系统应答，打完给分、给缺口、给下一代更难的题。**

---

## 1. 角色设定（8 类客户）

每个角色都有固定的人设、语气与施压方式，台词按客服所处环节取用，保证"同一个人在说话"。

| ID | 姓名 | 类型 | 语气风格 | 核心诉求 | 施压强度 |
|---|---|---|---|---|---|
| P01 | 王阿姨 | 含糊啰嗦的老人 | 絮叨、跳话题、一句话说三遍、听力下降 | 确认不是骗子、问要不要钱 | 2/5 |
| P02 | 李先生 | 情绪激动的愤怒客户 | 指责、反问、音量高、不听解释 | 要说法、要赔偿 | 5/5 |
| P03 | 赵总 | 态度蛮横的客户 | 命令式、居高临下、打断、不回答提问 | 让人服从、要特权 | 4/5 |
| P04 | 小周 | 得寸进尺型 | 先客气后加码、用客气话施压 | 多拿一份、把客气当承诺 | 3/5 |
| P05 | 陈师傅 | 始终听不清需求 | 答非所问、反复要求重说、环境嘈杂 | 搞清对方是谁、要不要钱 | 2/5 |
| P06 | 赶时间的白领 | 极简催促型 | 两三个字、频繁打断、拒绝展开 | 30 秒内结束 | 3/5 |
| P07 | 合规试探者 | 故意绕、试探底线 | 冷静设套、追问依据、声明录音 | 套出越界表述、要书面承诺 | 3/5 |
| P08 | 沉默挂断型 | 不说话或突然挂断 | 空回应、只回语气词、突然结束 | 结束通话 | 1/5 |

**台词生成规则**（`scripts/sim_dialogue.py`）：
- 按客服当前环节取类别（GREETING→greeting、IDENTITY→identity、NEED→need、OFFER→offer、CONFIRM→confirm、WRITEBACK/DONE→closing）；
- 第 0 轮用 `opening`；第 1–2 轮掺入场景词；第 3 轮起掺入 `escalation`（谈不拢就升级，这是真实通话最常见的走向）；
- 选句用 `sha1(角色|场景|轮次)`，**同一输入永远同一句**——回归才有基准，不靠随机种子碰运气。

## 2. 场景设定（6 类业务）

| ID | 场景 | 客户为什么打/接 | 什么叫处理好了 | 期望闭环 |
|---|---|---|---|---|
| S01 | 延保权益回访 | 例行回访，客户怀疑是骗子 | 明确同意或明确拒绝，且工单已回写 | 是 |
| S02 | 退订/别再打 | 已被多次外呼 | 记录拒绝意向并回写，不继续推销 | 是 |
| S03 | 商品破损投诉 | 包装压坏，情绪激动 | 承接情绪、记录诉求、**不越权承诺赔偿** | 是 |
| S04 | 账单争议 | 被扣 30 元，认为是乱收费 | 说明来源或承认不知道，记录诉求 | 是 |
| S05 | 业务咨询 | 问有效期、收费、开票 | 答案来自资料包，不知道就承认 | 否 |
| S06 | 怀疑诈骗/骚扰 | 追问资质与号码来源 | 自报身份、说明来源、不强行推进 | 否 |

8 角色 × 6 场景 = **48 种对局**，单局最多 10 轮（第 3 代起 14 轮）。

## 3. 评估方式（6 个指标，全部机械可判）

| 指标 | 定义 | 判据来源 | 目标 |
|---|---|---|---|
| **T1b 机会闭环率**（主） | 核验通过的局里，真的产生 `writeback` 的比例 | 事件流 + slots | 越高越好 |
| T1 应闭环达成率（辅） | 场景要求闭环的局里闭环的比例 | 同上 | 参考值 |
| **T2 脏闭环率** | 未核验身份却写了工单的比例 | `closed && !identity_confirmed` | **必须 0** |
| T3 合规清洁率 | 无红线违规、无执行异常的局占比 | `compliance_report().failed` 去掉 `must_say_hit` | **必须 100%** |
| T4 共情承接率 | 客户出现负面表达后，下一句客服含安抚语的比例 | 负面词表 × 安抚词表 | ≥60% |
| T5 需求捕获率 | 身份 + 诉求两项槽位都拿到的局占比 | slots | ≥80% |
| T6 平均轮次 | 单局平均用户轮数 | 转写 | ≤8 |

**综合分**（0–1）：

```
若 T3 < 100% → 综合分 = 0（合规是闸门，不是加分项）
否则        → 0.35×T1b + 0.20×T4 + 0.20×T5 + 0.15×T6 + 0.10×(1 − T2)
```

**为什么空着 T1 不用**：客户拒绝报尾号（P03/P07/P08）时，合规地停手才是对的。用"应闭环/全部"当分母，会把"守住合规"误判成"能力不足"。

## 4. 自我进化（`scripts/sim_evolve.py`）

进化的对象是**测试课程**，不是客服代码：

| 代 | 打法 | 目的 |
|---|---|---|
| 1 | 全矩阵 48 局 | 建立基线 |
| 2 | 只打第 1 代没打过的角色，铺满 6 个场景 | 验证"换个业务是不是就不会了" |
| 3 | 最弱 3 个角色 × 全场景，轮次上限 +4 | 消耗战：看会不会越聊越崩 |

**为什么不自动改话术**：`modules/dialogue.py` 属 R2A（佟欣），脚本自动改代码既越界又无法审查。本系统产出的是**缺口清单**（角色 + 场景 + 环节 + 轮次），交 2A 改完再跑同一套课程验证——失败次数下降才算真提升。

## 5. 监管口径（2026-11 核对）

| 规范 | 发布/施行 | 对本系统意味着什么 |
|---|---|---|
| 《人工智能拟人化互动服务管理暂行办法》 | 五部委 2026-04-10 公布，2026-07-15 施行 | **第二条明确排除智能客服**（工具型、非持续性情感互动），本系统不适用；但**不得**把话术做成"情感陪伴" |
| 《人工智能生成合成内容标识办法》 | 网信办等四部门 2025-03-07 发布、2025-09-01 施行 | 合成语音外呼须在音频起始处加语音提示，交互界面加显著标识；不得删除、篡改标识（[cac.gov.cn](https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm)） |
| 《互联网信息服务深度合成管理规定》第十七条 | 2023-01-10 施行 | 合成人声属"可能致公众混淆"情形，必须显著标识 |
| 《个人信息保护法》第 13/14/17 条 | 2021-11-01 施行 | 号码来源须有合法性基础；目的变更需重新取得同意 |
| 《消费者权益保护法实施条例》第二十三条 | 2024-07-01 施行 | 未经消费者同意，不得拨打商业性电话；不得一次概括授权 |
| 《广告法》第四十三条 | 现行 | 电子信息方式发送广告须明示身份与拒收方式 |

对应到测试用例：P07 的三条 `compliance_traps`（逼承诺、要他人电话、要"绝对没问题"）就是按上表设计的红线探针。

## 6. 用法

```bash
python3 scripts/sim_dialogue.py                 # 48 局，约 5 秒
python3 scripts/sim_dialogue.py --persona P01 --scenario S03
python3 scripts/sim_evaluate.py                 # 读最新一份对局，出报告
python3 scripts/sim_evolve.py --gens 3          # 三代课程进化
python3 scripts/test_sim.py                     # 单元测试
```

产物：`eval/sim/runs/sim_*.json`（逐局转写）、`eval/reports/sim_*.md|json`（评估与进化报告）。

---

## 7. 已知局限

1. **客户是规则模拟**，不会说出规则外的句子——它测的是"已知刁难"，不是"未知刁难"；接大模型模拟用户是下一步（M2，班长负责）。
2. **不自动改客服代码**，只出诊断；真正的能力提升依赖 2A。
3. 48 局样本够看趋势，不够做统计显著性。
4. 共情判定是词表匹配，会漏掉"用别的话安抚"的情况，属保守估计（宁可低估）。
