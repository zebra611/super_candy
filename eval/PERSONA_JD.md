# 京东售后对抗人物库（personas_jd.json）

> 由 `eval/persona_factory_jd.py` 生成，**勿手改**。改词表 → 重新生成 → 跑测试。

## 一、覆盖规模

| 维度 | 数量 | 说明 |
|---|---|---|
| 人物 | **320** | `JD0001`–`JD0320`，四维组合，去 id 后 **320 条内容两两不同** |
| 职业 | **178** | 制造/服务/专业/农业/新兴行业，见生成器 `PROFESSIONS` |
| 语气 | **60 种 × 3 档强度 = 180 种组合** | 标签如"阴阳怪气""强压怒火""慢条斯理"，强度分轻微/明显/激烈 |
| 态度 | **30** | 愤怒/焦虑/冷漠/礼貌/咄咄逼人/委屈/怀疑……（→ 4 档信任） |
| 语言与方言 | **20** | 普通话 + 粤语/闽南/四川/东北/河南/湖南/上海/天津/陕西/客家/山东/湖北/江西/广西白话 + 英/日/韩/俄/西 |
| 场景 | **10** | 包裹丢失、快递丢失、错发、漏发、破损、商家不发货、退款未到账、发票、物流停滞、疑似假货 |

每 3 条里有 2 条普通话、1 条方言或外语，防止方言样本把整体带偏。

## 二、单条结构

```json
{
  "id": "JD0004",
  "scenario": {"id": "S04", "name": "漏发配件", "need": "补发缺失配件",
               "hassle": "平时没空清点装箱",
               "reply_guide": "按装箱清单逐项核对，缺件补发不走退货，避免让用户整单退回"},
  "profession": "水暖工",
  "tone": {"label": "阴阳怪气", "intensity": "激烈", "level": 3, "note": "已经压不住情绪"},
  "attitude": "讽刺",
  "language": {"code": "zh-sichuan", "name": "四川话",
               "features": ["儿化与叠词多", "语速偏快", "爱用反问"],
               "markers": ["要得", "搞啥子", "莫得问题", "晓得咯"]},
  "utterances": ["要得，我先说清楚，我有个漏发配件的事要问。", "我是做水暖工的，平时没空清点装箱，搞啥子。",
                 "莫得问题，你们到底怎么处理？", "我挺讽刺的，要求很简单：补发缺失配件。"],
  "expect": {"closed": true, "consent": false},
  "tags": ["jd", "s04", "zh-sichuan"]
}
```

**`reply_guide` 是这份库的核心**：只给"客户怎么闹"，模型学不到"该怎么答"；给了要点，才能把对抗结果转成话术改进。

## 三、怎么扩

| 想加什么 | 改哪里 | 注意 |
|---|---|---|
| 新职业 | `PROFESSIONS` 末尾追加 | 用空格分隔；**职业名内部不能有空格**（「UI设计师」不能写成「UI 设计师」，否则会被切成两个伪职业） |
| 新语气 | `TONES` 追加 | 必须与已有标签不重复（测试会查唯一性） |
| 新方言/外语 | `LANGUAGES` 加一条 | 至少给 3 个 `markers`，`utterances` 会取前三个 |
| 新场景 | `SCENARIOS` 加一条 | 必须写全 `need`、`hassle`（台词第二句的「为什么重要」）、`reply_guide`，缺一个测试不过 |

改完执行：

```bash
python3 eval/persona_factory_jd.py --n 320
python3 scripts/test_persona_jd.py      # 11 条，覆盖广度/唯一性/可复算
```

## 四、怎么跑起来（适配层已提供）

```bash
# 生成人物库，同时产出一份 sim_eval 能直接吃的画像
python3 eval/persona_factory_jd.py --n 320 --sim-out eval/personas_jd_sim.json
python3 scripts/sim_eval.py --personas eval/personas_jd_sim.json
```

映射规则（`to_sim_persona()`，全部显式、可复算，不让模型猜）：

| 人物库字段 | sim 画像字段 | 规则 |
|---|---|---|
| `tone.level` 1/2/3 | `traits.patience` | 6 / 4 / 2（越激烈越没耐心） |
| `tone.level` | `traits.verbosity`、`catchphrase_rate` | 0.4/0.3/0.2、0.55/0.70/0.85 |
| `attitude` 30 种 | `traits.trust0` | 四档：敌意类 0.12、怀疑类 0.22、弱势类 0.34、中性 0.28 |
| `language.code` | `traits.hearing` | 普通话 1.0，方言/外语 0.9 |
| `utterances` | `catchphrases` | 原句直接用，不二次拼接 |

## 五、已知边界

1. **转换只覆盖「语气 / 态度 / 方言」三个维度**：`goal` 统一 `confirm`、`expect.closed` 统一 true。这批人物回答的是"换个说法、换个脾气，客服还答不答得上"，**不是**"拒绝型客户覆盖率"——模拟器的拒绝是耐心/信任耗尽逼出来的，台词里写一句「我不要」演不出来。要测拒绝必须另写画像（参考 `eval/personas_profession.json` 里 `goal=refuse` 的写法，并让 `expect.closed` 跟着改 false）。
2. **方言台词是"标志词拼接"**，不是真正的地道语料。转出来的 `hearing=0.9` 只是"模拟器按概率糊掉关键要素"，不是识别率。它能测"系统听不听得出是方言表达"，但**不能证明**方言识别准确率——那需要真实录音。
3. **`expect` 统一是 `closed=true, consent=false`**：售后场景里客户要的是解决问题，不是"同意领权益"，consent 恒为 false 更贴近真实。

### 6.1 适配层跑出来的数字怎么看（重要）

按上面的命令把 320 条全部转成 sim 画像、注进当前**唯一可评测场景**（POP 资审）实测：

```
总通过：81/320 = 25%｜责任分布 {"none": 81, "unexplained": 217, "agent": 22}
239 通失败全部是 end_by=agent_end:hangup（客服主动挂断）
```

**这个 25% 不能当"客服水平"用**，三个原因都很硬：

1. **业务对不上**：这批人物的诉求是京东售后（包裹/发票/退款），客服在问的是
   "商家资质审核为什么被驳回"。客户答不上来是设计使然，不是客服问得差。
2. 模拟器把「口头禅 + 动作文本」拼成一句再送进去（`"谢谢，你们到底怎么处理？，您好，听着呢"`），
   真正表态（"听着呢"）被埋在前半句后面，客服按关键词判意图就判不出来。
   这是 `modules/user_sim.py` 的拼装问题，不是本库的台词问题。
3. 客服对「始终没有明确表态」的客户按设计挂断（`GREETING/identity_retry` → `hangup`），
   所以"没闭环"不等于"答错了"；217 条 `unexplained` 大部分是这一类。

**要用它得出有意义的结论**，必须先给售后场景接外呼名单与画像（见
`docs/36_1109线上实测与场景隔离修复.md` 的场景隔离说明），并让模拟器把
"口头禅"与"动作回复"分开送两轮。在那之前，这批数据只适合看**单条对话**：
比如 JD0075 那种"客户一句话里既有职业抱怨又有尾号"的输入，能暴露
客服判意图时被无关信息带偏的样本——那才是这份库真正的价值。
