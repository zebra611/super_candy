> 由 `eval/persona_factory_jd.py` 生成，**勿手改**。改词表 → 重新生成 → 跑测试。

## 一、覆盖规模

| 维度 | 数量 | 说明 |
|---|---|---|
| 人物 | **320** | `JD0001`–`JD0320`，四维组合，全量唯一 |
| 职业 | **180** | 制造/服务/专业/农业/新兴行业，见生成器 `PROFESSIONS` |
| 语气 | **60 种 × 3 档强度 = 180 种组合** | 标签如"阴阳怪气""强压怒火""慢条斯理"，强度分轻微/明显/激烈 |

每 3 条里有 2 条普通话、1 条方言或外语，防止方言样本把整体带偏。

## 二、单条结构

```json
{
  "id": "JD0004",
  "scenario": {"id": "S04", "name": "漏发配件", "need": "补发缺失配件",
               "reply_guide": "按装箱清单逐项核对，缺件补发不走退货，避免让用户整单退回"},
  "profession": "水暖工",
  "tone": {"label": "阴阳怪气", "intensity": "激烈", "level": 3, "note": "已经压不住情绪"},
  "attitude": "讽刺",
  "language": {"code": "zh-sichuan", "name": "四川话",
               "features": ["儿化与叠词多", "语速偏快", "爱用反问"],
               "markers": ["要得", "搞啥子", "莫得问题", "晓得咯"]},
  "utterances": ["要得我不管，我有个漏发配件的事要问。", "我是做水暖工的，平时没空盯物流，搞啥子。",
                 "莫得问题，你们到底怎么处理？", "我讽刺要求很简单：补发缺失配件。"],
  "expect": {"closed": true, "consent": false},
  "tags": ["jd", "s04", "zh-sichuan"]
}
```

**`reply_guide` 是这份库的核心**：只给"客户怎么闹"，模型学不到"该怎么答"；给了要点，才能把对抗结果转成话术改进。

## 三、怎么扩

| 想加什么 | 改哪里 | 注意 |
|---|---|---|
| 新职业 | `PROFESSIONS` 末尾追加 | 用空格分隔，别加标点 |
| 新语气 | `TONES` 追加 | 必须与已有标签不重复（测试会查唯一性） |
| 新方言/外语 | `LANGUAGES` 加一条 | 至少给 3 个 `markers`，`utterances` 会取前三个 |
| 新场景 | `SCENARIOS` 加一条 | 必须同时写 `need` 与 `reply_guide`，否则测试不过 |

改完执行：

```bash
python3 eval/persona_factory_jd.py --n 320
python3 scripts/test_persona_jd.py      # 11 条，覆盖广度/唯一性/可复算
```

## 四、已知边界（别当成能直接跑）

1. **schema 与 `sim_eval` 的 `personas_*.json` 不同**：那套要 `knows/willing/traits` 三个字段来驱动状态机，本库是"人物描述 + 台词素材"，**不能直接 `--personas` 注入**。要跑模拟，需要一个适配层把 `tone/attitude` 映射成 `traits{patience,trust0,verbosity}`、把 `utterances` 当 `catchphrases` 用。这一步没做，原因是映射规则应由跑批侧定义，硬塞会污染现有画像体系。
2. **方言台词是"标志词拼接"**，不是真正的地道语料。它能测"系统听不听得出是方言表达"，但**不能证明**方言识别准确率——那需要真实录音。
3. **`expect` 统一是 `closed=true, consent=false`**：售后场景里客户要的是解决问题，不是"同意领权益"，consent 恒为 false 更贴近真实。
