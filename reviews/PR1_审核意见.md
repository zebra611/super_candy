## 三、必须改（P0，改完再合）

### P0-1 `_is_loopback()` 在线上完全失效，`/api/scene` 等于公开可写

`_is_loopback()` 只看 `client_address[0]` 是不是 `127.0.0.1`。
线上是反向代理，后端看到的源地址就是 `127.0.0.1`。

**实测证据**（打线上，不带任何凭证）：

```
GET https://voice-agent-skeleton.app.workbuddy.host/api/sessions?sharecode=...
→ http=200，返回了 10 个 session_id 和各自的事件数
```

也就是说这道"只允许本机"的门，在线上是开着的。

- `/api/sessions`（既有接口）：泄露会话列表，是**既有缺陷**；
- `/api/scene`（本 PR 新增）：**写操作**，任何拿到分享链接的人可以切换全局场景，
  影响所有正在进行的通话。风险比前者高一个量级。

**建议修法**（任选一，推荐第 1 个）：

1. 检测到部署环境（存在 `PORT` 环境变量）就直接禁用这些运维接口，返回 403。
   线上根本不需要切场景，本地开发才需要。
2. 校验 `X-Forwarded-For` / `X-Real-IP`，取真实客户端 IP 再判断。
   注意：这两个头客户端可以伪造，要在反代层剥掉原值才安全。
3. 加运维 token（启动时生成、打印在控制台），运维接口必须带。

不管选哪个，`/api/sessions` 要一起修——它是同一个洞。

### P0-2 `/api/scenes` 泄露服务器绝对路径

实测返回：

```json
"path": "C:\\Users\\17591\\Desktop\\北地\\校外活动\\北京市人工智能+\\_pr1_review\\config\\scene.json"
```

暴露了开发者的本机目录、用户名、项目结构。线上部署后会暴露沙箱内部路径。

**建议**：对外只返回 `id`（如 `service_outbound`），需要完整路径的字段
只在本地模式返回，或者干脆去掉——前端要用路径切场景的话，用 `id` 就够。

## 四、建议改（P1，合并前尽量处理）

### P1-1 文档编号撞车

本 PR 新增 `docs/17_事件流与看板.md`，但 main 上已经有 `docs/17_任务2接口契约.md`
（今天下午刚加，是佟欣和潘柏亦的开工依据）。

合并后 docs 目录会有两个 17，README 索引也会指错。

**建议**：PR 的 5 份文档整体改为 18–22（`17→18`、`18→19`、`19→20`、`20→21`、`21→22`）。

### P1-2 PR 落后 main 两个提交，4 个文件冲突

`git merge-base` 显示分叉点在 `577c473`，main 之后又有了：

- `9bc8621` fix: 打断没记耗时（改了 `app.py`）
- `4c874a6` feat: 任务2 契约落地（改了 `app.py`、`config/scene.json`、`config_loader.py`、`modules/dialogue.py`）

预测冲突：`README.md`、`app.py`、`config/scene.json`、`config_loader.py`。

**其中 `app.py` 最需要注意**：main 新增了 `/api/asr/probe`（打断探针）和
`barge_in` 的 `latency_ms` 字段，PR 新增了 4 个路由。两边都在 `do_POST` 里加分支，
rebase 时**不要整段覆盖**，要保留两边的路由。

### P1-3 看板接口无鉴权

`/api/cost` 和 `/api/dashboard/summary` 直接返回数据，不要 token。
泄露的是全站成本、闭环率、会话量——对比赛演示不算致命（看板本来就是给评委看的），
但要在文档里**写明"这两个接口不鉴权、只应部署在内网/演示环境"**，
而不是让人误以为有保护。

### P1-4 场景切换没有活跃会话保护，会串台

这不是 bug——`set_scene()` 的 docstring 明确写了"已开始的会话不会回滚……
适合演示时现场对比两套场景"。设计意图是清楚的。

但我实测了一通电话中途切换：

```
开场白    ：您好，我是京东客服中心的小采，请问是张先生本人吗？
（切换场景到 retail_recall）
下一轮回复：了解了，我们给会员准备了一份到店礼包，含 20 元无门槛券……
```

同一通电话，前半段是"服务类外呼"，后半段变成"会员复购召回"。
用户会听到两个完全不同的业务。

**演示场景下这个风险很实**：误点一下，正在演示的那通电话就废了。

**建议**：切换时检查有没有活跃会话，有就二次确认（或在响应里带
`active_sessions: N` 让前端提示"当前有 N 通电话在进行，切换会影响它们"）。
不需要禁止，只要让人知道后果。

### P1-5 `启动全部.bat` 内容含中文，偏离项目约定

项目踩过一次坑：`.bat` 内容含中文会让 cmd 按 GBK 解析截断。
现有 `启动.bat` 是纯 ASCII（只用了英文提示）。

`启动全部.bat` 第 7–9、20–25 行都是中文。虽然有 `chcp 65001` 打底、
且关键路径用了引号，风险比当初低，但仍建议改成英文提示，和 `启动.bat` 保持一致。

## 五、可以不改（P2）

1. `config/scene.json` 结尾丢了换行符（diff 里 `\ No newline at end of file`）。
2. `events._connect()` 的注释说"线程处理完请求后连接一直留着，下个请求直接用"——
   但服务端用的是 `ThreadingHTTPServer`，**每个请求一个新线程**，线程结束连接就没了，
   所以"省掉开关销"的收益接近于零。真正有价值的是 WAL（读写不互斥），这个是真的。
   建议把注释改准确，避免后来人据此做错误优化。
3. `archive_events()` 建议加一步"搬完校验归档库行数 == 主库删除行数"，
   再删主库。现在顺序是对的（先写归档再删），但没有校验回读。
