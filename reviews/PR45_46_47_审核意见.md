## 二、PR #46：京东人物库（320 人）

### 2.1 必须改 ①：320 条里只有 180 条不同

`PERSONA_JD.md` 表格写的是「320 人，四维组合，**全量唯一**」。复算：

```
去 id 后唯一内容: 180   总条数: 320
重复内容组: 140 组，涉及 280 条
JD0001 与 JD0181 除 id 外完全相同: True
```

原因在生成器的周期：`profession=(idx*7)%180`、`tone=(idx*11)%60`、
`attitude=(idx*13)%30`、`intensity=(idx//60)%3`，四项的最小正周期都是 180，
所以 `idx` 与 `idx+180` 产出**逐字节相同**的条目。`320 = 180 + 140`，
后 140 条是前 140 条的副本，只改了 id。

影响：所谓「320 人」买到的覆盖面是 180；答辩时说 320 会被现场复算打脸。
要么把 `--n` 默认改成 180 并按 180 写文档，要么给四个维度加真正的互质步长
（例如 `attitude=(idx*7+idx//180)%30`）让周期 ≥ 320。

### 2.2 必须改 ②：确定性测试是同义反复

```python
def test_rebuild_is_identical(self):
    self.assertEqual(F.build(50), F.build(50))     # 永远成立
```

`build()` 是纯函数，两次调用必然相等——这条测试**在任何情况下都不会红**。
真正的口径应该是「**生成器重建 == 库里的文件**」。

反向变异（把注释里说「已修」的强度轮换改回旧写法）：

```
intensity = INTENSITY[idx % 3]      # 注释：「若强度取 idx%3，180 种组合会塌缩成 60 种」
→ test_persona_jd.py：Ran 11 tests — OK   ← 全绿
→ 但 build(320) 与库内已有 214 条不一致
```

即：**生成器已经和 15k 行的数据文件分叉了，测试还在报绿**。
这条必须改成 `self.assertEqual(F.build(320), load())`（顺带把 `--n` 也锁住）。
其余覆盖类断言读的是**磁盘上的文件**，永远发现不了生成器变质。

### 2.3 必须改 ③：两个职业被空格切成碎片

`PROFESSIONS` 用 `"""...""".split()` 切词，而源串里有多词职业：

```
"UI 设计师" → "UI"、"设计师"
"4S 店销售" → "4S"、"店销售"
```

结果 8 条画像的职业是伪职业：

```
JD0008  职业=4S   │ 我是做4S的，平时没空盯物流，麻烦您。
JD0134  职业=UI   │ 我是做UI的，平时没空盯物流，麻烦您。
JD0111  职业=店销售 │ 我是做店销售的……
```

改法：用 `、`/换行分隔，或把这两个词写成 `UI设计师`/`4S店销售`；再加一条断言
「职业里不得出现纯 ASCII 或长度 ≤2 的碎片」。

### 2.4 必须改 ④：台词模板和场景打架

第 2 句模板固定是「我是做 X 的，平时没空盯物流」，但场景里有发票、退款、假货：

```
96 条「发票问题 / 退款未到账 / 疑似假货」的客户在说「平时没空盯物流」
JD0008 发票问题    │ 我是做4S的，平时没空盯物流
JD0010 疑似假货    │ 我是做专利代理人的，平时没空盯物流，晓得。
```

第 4 句把态度标签直接塞进句子，语法不通：

```
我愤怒要求很简单：找回包裹或按规则赔付。
我无助要求很简单：确认是否丢件并要求补发。
```

作为「台词素材库」这还能用；但它同时自称能转成画像去跑评测（见 2.5），
台词不通会直接变成「客服答非所问」的假缺陷。建议每类场景给一句自己的
「为什么这通电话重要」（物流/发票/退款各一句），第 4 句改成「我要求很简单：…」。

### 2.5 需要作者明确表态的一点

`PERSONA_JD.md` 自己写了「**schema 与 sim_eval 不同，不能直接注入**」——
这点很诚实，值得肯定。但同时 `test_persona_jd.py` 也没有任何「能否注入」的断言，
于是这份 15k 行数据的现状是：**不进任何评测链路，也不产出任何数字**。
要么补一个适配层（`tone/attitude → traits`、`utterances → catchphrases`），
要么在文件头明确写「素材库，不参与评测」，避免以后有人拿它当覆盖率证据。

### 3.3 必须改 ②：构建产物不可复算（Windows 上必然脏）

```
$ md5sum eval/ui/preview.html          → 0344001e…（库内）
$ python scripts/build_ui_preview.py
$ md5sum eval/ui/preview.html          → 80cadbc5…（重建后）
$ git status --short                   →  M eval/ui/preview.html
```

1447 行**全部**不同，字节数 372660 → 373107（+447，正好等于行数）——是 CRLF。
`build_ui_preview.py` 里 `open(args.out, "w", encoding="utf-8")` 没写 `newline="\n"`，
Windows 下按平台换行写，而仓库里存的是 LF。本仓库既有规矩是「所有文本 LF」
（之前 `personas_adversarial.json` 混进 CRLF 也是同样问题）。

`test_build_is_deterministic` 看不到这个：它比的是**两次内存构建**，
而问题出在**落盘那一步**。修法两步：
1. `open(..., "w", encoding="utf-8", newline="\n")`；
2. 加一条断言「磁盘上的 `preview.html` == 重建结果」，否则每次重建都脏一次工作区，
   而 364KB 的生成物入库本身就容易产生无意义 diff。

### 3.4 建议 ③：注释与实现相反

```python
# 首屏 <img src> 也换成内联，避免 JS 未执行时空白
...
# 首屏 src 统一换成 1px 占位：真图由 renderStaff() 立刻填入。
```

第一行说的是「内联首屏图以免 JS 未执行时空白」，实现是把首屏换成 1px GIF——
**JS 没执行时恰恰就是空白**。实现没错（省 180KB 是合理取舍），错的是注释，
两句话互相取消，后来人只会更糊涂。删掉第一句，或改成「首屏先用 1px 占位，
JS 执行后由 `renderStaff()` 填入；代价是 JS 关闭时首屏无头像」。
