# 63 · 把换声这件事真正融进代码：三个场景包的价格、试听工具的族与分段

**2026-11-13 下午（第二轮）**。用户一句话：「我们改了声音，融进去，交 PR」。

主干 `0b684b2` 已经把 TTS 换成 `cosyvoice-v3-flash` + `longanhuan_v3`（龙安欢 V3），
`tone-polish` 分支 merge 过主干，所以"换模型"这件事本身早就在了。
这一轮做的是**另一半**：换声之后，那些"跟着声音走"的地方有没有一起走。

答案是三处没走，其中两处会真的坏事。

## 一、四个场景包只改了一个价格

`0b684b2` 的提交说明写着「四个场景 tts 段同步……漏一个就会主场景换了、切场景变回去」，
`test_tts_cosy.py` 里那条价格断言也写着同一句话。但两边都只覆盖 `config/scene.json`：

| 文件 | 改前 | 改后 |
|---|---|---|
| `config/scene.json` | 0.08 → **0.1**（主干已改） | 0.1 |
| `config/scenes/pop_reject.json` | 0.08（漏） | **0.1** |
| `config/scenes/retail_recall.json` | 0.08（漏） | **0.1** |
| `config/scenes/service_outbound.json` | 0.08（漏） | **0.1** |

为什么算真问题：`budget.price_per_1k_chars_tts` 是 `app.py` 每轮估成本用的
（`turn_cost = asr + tts_chars/1000*单价 + tokens`）。默认场景读 `config/scene.json`
所以看起来是对的，可一旦换场景（跑批、售后、演示切包），单价就回到旧模型的 0.08，
**每通电话成本少算 20%**——看板上的数字不会报错，只会偏低，属于最难发现的那类错。

改法上顺手把三个包的 `_todo` 也改成和主配置同一句话（写明"换回 qwen3-tts 要改回 0.08"），
免得下次换模型又只改一处。

## 二、试听工具：整张候选表都是旧模型的音色

`scripts/audition_tts.py` 存在的唯一目的就是"换声音之前先听一听"，
它的候选表是 `Kai / Eldric Sage / Maia / Katerina / Ethan / Serena / Moon`——
**全是 qwen3-tts 的音色**。换模型之后拿这张表去打 CosyVoice 端点，
会一条一条被拒（百炼页面那句"所选音色须在当前模型的音色列表中"是硬约束），
而工具只会说"失败"，看着像接口坏了。

改法：

- 候选表按模型族分组：`CANDIDATES = {"qwen3-tts": [...旧表...], "cosyvoice-v3": [longanhuan_v3]}`。
  旧表留着是因为"换音色是配置决策"，回滚到 qwen3-tts 时还要能试听。
- `family_of(model)` 与 `voice.tts_request_body` 的族判断同源（都看 `cosyvoice` 前缀）。
- 表里没有的名字用 `--voices 名字1,名字2` 点名（从百炼音色列表复制即可），
  不用为了试听一个名字去改代码。
- 想临时听另一族：`--model qwen3-tts-flash`，此时把 `endpoint` 置空让族默认值接管
  （配置里的端点是属于原来那一族的，拿着打新音色必错）。

## 三、更早的一个坑：试听工具读不懂"分段"

改完族的问题，真跑一次，仍然失败："没有拿到音频链接"。

查下去发现跟音色无关：合成早就是**按句分段返回**（`mode="segments"`，每段一个链接），
只有"恰好一段且没有后续"时才走 `mode="url"`。而试听工具写的是

```python
if got.get("mode") != "url" or not got.get("audio_url"):
    raise RuntimeError(...)
```

于是一整句话被切成两段时报错，任何音色都听不到。这个工具大概从分段合成上线起就是坏的，
只是没人跑过——它不在任何自动化里，README 也一直写着"能用"。

改法：

- `audio_urls(got)` 同时认 `mode="url"` 与 `mode="segments"`；退回浏览器播报
  （`mode="browser"`）时把 `error` 原样抛出来，别再吞成"没有链接"。
- 几段音频按顺序下载后接成一条：第一段保留 ID3 头，后面几段用 `strip_id3()`
  剥掉（10 字节头 + syncsafe 长度）。直接首尾相接会在第二段开头冒出 `ID3` 字节，
  播放器要么跳过要么当场停。
- 产物扩展名从 `.wav` 改成 `.mp3`（内容本来就是 mp3，两个模型族都给 mp3，
  写 `.wav` 属于长期名不副实）。

真跑结果（用项目自己的 key，一句话 26 字）：

```
1) longanhuan_v3  女·欢脱元气（当前线上）   597 ms   92 KB   2 段  01_longanhuan_v3.mp3
$ file audition/01_longanhuan_v3.mp3
Audio file with ID3 version 2.3.0 ... MPEG ADTS, layer III, v2, 160 kbps, 24 kHz, Monaural
```

首段 597ms，与 `docs/61` 记的 580ms 同一量级。

## 五、把漏掉的那条断言补成"四个文件"

`test_tts_cosy.py` 的价格断言原来只读 `config/scene.json`——这就是 0.08 能活下来的原因。
现在遍历 `SCENES` 四个文件，失败信息带上文件名：

```
AssertionError: 0.08 != 0.1 : TTS 单价没跟着换模型：config/scenes/retail_recall.json
```

变异验证：把 `retail_recall.json` 改回 0.08，这条精确变红（只红这一条）。

另加 6 条不联网断言，锁住这一轮修的两个坑：

| 断言 | 守的是什么 |
|---|---|
| CosyVoice 族默认表 == `["longanhuan_v3"]` | 线上音色必须能被试听 |
| 旧表里仍有 `Serena`、且不许混进 CosyVoice 表 | 回滚可用 + 不跨族 |
| `--voices` 覆盖生效 | 表外名字不用改代码 |
| `mode="segments"` 能取出多个链接 | 分段不是失败 |
| `mode="url"` 仍可用 | 短句路径不回归 |
| `mode="browser"` 抛出原始原因 | 失败不再被吞 |
| `strip_id3` 去掉标签、无标签原样返回 | 几段拼接可播 |

`test_tts_cosy.py`：9 → **15** 条。
