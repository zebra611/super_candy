# 32 真实用户模拟与 L2 自进化

> 对应赛题要的："失败聚类与归因，自动优化提示词/业务话术/检索知识/工具调用策略，
> 借助版本管理、回归验证和安全回滚"。
>
> 本轮只做**话术层**（`stages.*`）的自进化。流程逻辑与权重训练不在范围内，
> 理由见第七节——那条线不是"保守"，是"改错了没人拦得住"。

---

## 一、先说前提：为什么原来的"模拟用户"不能用

`eval/personas_generated.json` 是**固定台词回放**：每个 persona 按
"开场→核身→诉求→异议→收尾"排好句子，跑批时顺着念，完全不看客服上一句说了什么。

你们自己的 `docs/28` 已经把它判了：40 条里 24 条失败，其中 5 个人设
"台词里根本没有可核身信息"却要求闭环——**失败是模拟器造出来的，不是系统缺陷**。

拿这种失败去聚类，聚出来的是模拟器的口音，不是系统的问题；
再拿它去调话术，就是对着哈哈镜改妆。

所以顺序必须是：**先让用户像人，再谈进化**。

---

## 二、真实用户的三条约束

不是"更聪明的台词"，而是三条**限制**。限制才是真实感的来源——
真人之所以是真人，恰恰因为他不知道、听不清、会不耐烦。

### 1. 受知（epistemic limit）

他只知道自己知道的。

- 事实（尾号/姓名/单号/公司名）**全部来自本通电话真正拨出去的那条档案**
  （`start_call()` 回传的 `outbound_target`），不是另编一套；
- 画像声明 `knows: {phone_tail: false}` 的，`derive_facts()` 里索性不出现这个键，
  渲染层拿不到值，只能回答"我记不住"；
- 结构上**不可能**出现"模拟器随手报出正确尾号"这种假绿。

### 2. 受听（perceptual limit）

他只对**听到的那句话**反应。

- 模拟器拿不到 `stage` / `intent` / `slots`，只能从客服话术里**推测**被问了什么
  （`detect_asks`）。真实商家听不出"现在进入 IDENTITY 阶段"，只听得懂
  "他让我报号码"；
- 因此"客服没问、用户却先报了尾号"这种诡异剧情在结构上不会发生；
- 听错按 `hearing` 概率发生，而且**同一要素只错一次**——真人让人重复一遍通常就听清了，
  不会一直听不清。

### 3. 受耐心（patience / trust）

挂断是**被逼出来的**，不是脚本写死的。

| 触发 | 代价 | 为什么 |
|---|---|---|
| 客服原地重复同一句 | 耐心 −2 | 真人最烦这个 |
| 重复要同一条信息 | 耐心 −1 | "我刚不是说了吗" |
| 我问了、你没答 | 耐心 −1 | 问了不答最招人烦 |
| 客服自报身份/说明来意 | 信任 +0.35 | 这是"凭什么信你"的解法 |

信任低于 `trust_gate` 就不肯报个人信息；`willing: refuse` 的需要安抚到 0.8 才肯给，
`never` 的永远不给。**这三档的区别是"门槛"，不是"说/不说"的开关**——
上一版把 `refuse` 写成"永远拒绝"，商家被安抚两次还在反问，那不是谨慎，是模拟器不会改主意。

## 三、它是怎么跑起来的

```
客服说了一句
   ↓ ① 感知：_perceive()  —— 按 hearing 概率听漏关键要素（只错一次），记下 missed
   ↓ ② 理解：detect_asks() —— 从听到的文本里认出"被问了什么"（字面，不看 stage）
   ↓ ③ 决策：_decide()     —— 有限动作集，顺序即优先级
   ↓ ④ 表达：_render()     —— 只有这里能产出事实值，别的分支一律不碰 facts
用户说了一句（带 action 标签 + 耐心/信任/证据）
```

动作集是**标签**不是台词（`answer_tail` / `cant_remember` / `refuse_info` /
`ask_why` / `mishear` / `hangup` …）。这一点很关键：归因和聚类都按标签分组，
自由文本没法归因。

**确定性**：随机源按 `(persona_id, turn)` 单独播种，不用全局 random。
同一画像 + 同一段客服话术 → 逐字节一致，回归才有基准。

## 四、归因：L2 能不能信的分水岭

聚类之前必须先判**责任在谁**，否则高频"缺陷"全是假的。四类：

| 责任 | 含义 | 例子 |
|---|---|---|
| `agent` | 系统真的做错了 | 用户报了尾号，下一句还在问后四位 |
| `case` | 用例不可行 | 画像嘴里根本没有系统需要的那条信息 |
| `sim` | 模拟器设定导致的合理结局 | 秒挂、打错人、拒绝提供 |
| `unexplained` | 期望没达成、又找不到可证实的缺陷 | 单列待查，不硬扣帽子 |

**只有 `agent` 类进优化池。** 这是 `docs/28` 那次教训的直接产物。

为什么用规则不用 LLM 判官：归因结论要能逐条复算、能被队友当场回放质疑。
这几类缺陷的判据其实很确定（"用户报了尾号，同一轮回复还在问后四位"），
LLM 判官在这里既慢又会漂。每条缺陷都带 `evidence`（客服原话片段），报告里直接展示——
结论可以被伪造，原话不能。

已实现的缺陷码：

```
agent_slot_loss            用户交了信息，客服没接住/又问一遍
agent_noise_on_question    用户提问被当成"有杂音没听清"（Q1-D1 的机器可测版）
agent_loop                 连续三轮重复同句话术
agent_no_progress          多轮不推进阶段且不给新信息
agent_premature_writeback  "没听明白"被当成"拒绝整改"，直接回写
```

## 五、L2 闭环与三道闸门

```bash
python scripts/evolve.py init --scene config/scenes/pop_reject.json \
    --baseline eval/reports/sim_baseline.json
python scripts/evolve.py propose --out config/evolution/candidates/c001.json
#   填 value（人填，或 --llm 起草）
python scripts/evolve.py gate config/evolution/candidates/c001.json
python scripts/evolve.py promote v2
python scripts/evolve.py rollback           # 出事就退回上一版
python scripts/evolve.py status
```

闸门（任一不过就不许上线）：

1. **train 不降** —— 调参集通过数不得下降
2. **holdout 不降** —— 留出集降了就是过拟合，赛题点名禁止
3. **有实际收益** —— 总通过数增加，或系统缺陷会话数减少
4. **无个体回退** —— 没有任何一通电话从"通过"变成"不通过"
5. **缺陷总数不增**

> 第 4 条一开始我写的是"不得出现新的缺陷类型"，这是错的。
> 候选让通话走得更远，自然会**露出**更深层的坑（本轮 v2 就露出"报了姓名却不收"）。
> 惩罚这种"发现"，等于奖励"别往下走"，也会逼着优化器只改安全的表面话术。
> 现在新暴露的类型照常打印、记入待办，但不阻断上线。

**上线不是整份覆盖**：`config/scene.json`（默认场景）与
`config/scenes/pop_reject.json`（场景包）是同一套业务的两份文件，
只改一份，另一份还在说旧话术——演示时就是"改了没生效"。
所以 `promote` 只同步**改动过的键**，保留两份各自的开关
（默认场景 `nlg.provider=dashscope`，跑批 `template`）。整份覆盖会把引擎开关一起带过去。

**基线必须绑定场景内容哈希**（本轮加的护栏，因为真踩过）：
v2 上线后我"重跑了一次基线"，拿到的其实是 8/10 —— 用考过的卷子当没考过的标准，
后面闸门就永远显示"没有进步"。
现在 `sim_eval` 会把场景的**内容哈希**（规范化 JSON，不是文件字节——
同一套场景两份文件缩进不同，字节哈希只会造假警报）写进结果；
`evolve.py init` 比对不上就**直接拒绝**，缺哈希也拒绝（第一版只打警告，负向测试当场放进了错基线）。

负向验证过：

```
$ python scripts/evolve.py init --scene config/scenes/pop_reject.json \
      --baseline eval/reports/sim_v2.json
基线结果和要初始化的场景内容不一致，拒绝初始化：
  基线来自：config/evolution/versions/v2/scene.json（sha=e85255776621401a）
  当前场景：config/scenes/pop_reject.json（sha=969f14f7c685ea03）
```

## 六、本轮实测（可复算）

```bash
python scripts/sim_eval.py --json eval/reports/sim_baseline.json \
    --report eval/reports/sim_baseline.md --tag baseline
python scripts/evolve.py gate config/evolution/candidates/c001.json
```

| 指标 | v1 基线 | v2 候选 | 判 |
|---|---:|---:|---|
| 总通过 | 7/10 | **8/10** | +1 |
| train | 5/7 | **6/7** | +1 |
| holdout | 2/3 | 2/3 | 持平 |
| 系统缺陷会话 | 4 | 4 | 持平 |
| 缺陷总数 | 8 | 8 | 持平 |

候选只有两句（纯话术，不动代码、不动事实）：

| 键 | 改前 | 改后 |
|---|---|---|
| `IDENTITY.reply_ask_identity` | 您问的这个问题我记下了，稍后专员给您详细解答… | 您的号码是商家入驻时预留的联系方式，我们这边是官方审核，只用来核对这笔资质申请，不会外传… |
| `IDENTITY.reply_offtopic` | 嗯，您说的我记下了。咱们先把申请单核对一下，方便说一下预留手机号的后四位吗？ | 没关系，记不住号码也正常。您说个联系人姓名，或者申请单编号后六位，任意一个我都能核对上… |

**回滚也实测过**：`rollback` → 7/10；`promote v2` → 8/10。指针挪动，快照保留。

### 本轮刨出来的三个真缺陷

| # | 现象 | 类型 | 状态 |
|---|---|---|---|
| 1 | 商家问"你哪来的我号码"，客服回"记下了稍后解答"并重复索要 → 绕圈 5 轮后商家挂断 | 话术 | **v2 已修** |
| 2 | 商家说"记不住尾号"，客服只说"记下了"又把同一条要求重复一遍 → 卡死 | 话术 | **v2 已修** |
| 3 | 商家报了姓名"就是晏青梧"，系统**不收**（`_take_identity_slots` 只认"我叫/姓X"），接着又问尾号 | 代码 | 待办 |

第 3 条是 v2 上线后**新暴露**的：v1 里商家根本走不到"报姓名"这一步。
它不属于话术层，`evolve.py propose` 会把它标成 `needs_code` 并且**不生成候选**——
拿一句"我再解释一遍"去糊一个槽位问题，只会把错误藏进另一句话里。

## 七、边界（必须说清楚，否则答辩会被问穿）

**做**：话术文案（`stages.*`）的候选生成、双跑闸门、版本快照、指针回滚。

**不做**：

| 不做 | 原因 |
|---|---|
| 自动改流程逻辑 | 阶段推进/槽位轮换改的是代码，必须走评审与全量自检。一个能自动改流程的优化器，迟早把"没听明白"优化成"听到拒绝"——指标好看了，业务结论错了 |
| 自动改事实字段 | 公司名/单号/尾号由档案提供，改文案不能改事实（`validate_candidate` 会拦掉丢占位符的候选） |
| 模型权重自进化（SFT/LoRA） | 百来通数据不够、要 GPU、不可复现、合规难审计。赛题要的是提示词/话术/检索/工具策略的迭代，不是炼丹 |
| 让模拟器"自由发挥" | 动作必须来自有限集合，否则无法归因；自由文本生成的失败，聚类聚不动 |

**还没做的**（诚实记账）：

- 模拟器只做**文本层**，不模拟声学误差（口音、噪声、ASR 错字）——那是语音线的活；
- 只有 10 个画像，覆盖不到"方言/多人抢话/情绪剧烈波动"；
- 候选目前靠人填或 LLM 起草，**没有做多轮搜索**（一次只提一版，闸门过了就上线）；
- 聚类是标签精确分组，没有做"同一根因跨阶段合并"的语义聚类。
