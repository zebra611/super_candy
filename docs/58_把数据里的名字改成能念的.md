# 把后台数据里的名字改成人能念出来的

> 2026-11-13 上午。起因是用户一句截图反馈：
> 「能不能把后台的名字改的稍微正常点，现在你说这些名字我都读不出来」。

---

## 一、问题在哪

页面右侧「本次目标」那一栏、开场白里的公司名、客服复述的品牌名，全都来自
`config/mock/applications.json` 和 `applications_catalog.json`。这两份数据由两个脚本生成：

- `scripts/gen_mock_applications.py`（120 条）
- `scripts/gen_mock_catalog_applications.py`（官方 68 场景 × 1 条）

它们的词池全是**生僻字自造词**——当初是为了"绝对不像真实企业"，选的都是
「霁川、砚舟、青葙、葭芦、蘋汀、葳蕤、霈泽、璆野、玳梁」这类词。文档里看着雅，
现场就出问题：

- 演示时客户（或我们自己）念不出来，也记不住；
- 语音核身是要**念一遍、听一遍**的，名字读不出来，客户复述时必然走形，
  系统听着像"客户报错了"，其实是这个名字根本没法用嘴说；
- 名字越生僻，ASR 越容易给成别的字，又回到同音字那条老问题。

一句话：**核身靠嘴，数据就得用嘴能念的字。**

---

## 二、改法：换词池，不动结构

只改两个脚本的词池，生成逻辑、随机种子、字段结构一个字没动：

| 池 | 原来 | 现在 | 容量 |
|---|---|---|---|
| 公司字号 `SIZI` | 霁川/砚舟/青葙… | `华美、佳品、优源、家选…`（30 首字 × 15 尾字） | 140 |
| 品牌 `BRANDS` | 栖光/砚白/松序… | `小日子、好生活、鲜果园、暖时光…`（24 前缀 × 12 词） | 137 |
| 姓氏 `SURNAMES` | 柏/沈/陆/岑/裴/晏/殷/虞… | `张赵刘黄徐马胡郭高林罗梁谢宋唐曹彭曾田董` | 20 |
| 名 `GIVEN_NAMES` | 砚川/见微/听澜/知珩… | `斌芳娜敏静丽强磊军洋勇艳杰娟涛明超霞平刚` + 建国/志强/春燕/文博/佳怡/宇航/思远/晓东/海燕/建华 | 30 |
| 目录字号 `CATALOG_SIZI` | 柏庐/岑溪/岱屿… | `京华、京选、京通、海丰…` | 68 |
| 目录品牌 `CATALOG_BRANDS` | 柏序/岑光/岱青… | `臻颜、臻食、素居…` | 68 |
| 目录姓氏 | 欧阳/上官/司马… | `钱孙李周吴郑王冯陈褚卫蒋韩杨朱秦尤许何吕` | 20 |

**池容量刻意保持原值**（140 / 137 / 20 / 30 / 68 / 68 / 20）。原因不是好看：
生成器里 `rng.shuffle(pool)` 消耗的随机数个数与池长相关，池长一变，后面
尾号、驳回原因、类目的分配全跟着变，那就不只是"改名"，而是换了一份数据。
这次只换字面，所以：

- 单号 `QZ202611060001…` 还是那些；
- 尾号 `0086 / 1111 / 1234 / 0007 / 9876` 还是前五条；
- 每条档案的类目、驳回原因、外呼状态、边缘标签**逐条不变**。

前后对比（第 1/3/19 条）：

```
#1  北京市川上商贸有限公司 / 闻樾 / 晏青梧 / 尾0086  →  北京市安食商贸有限公司 / 暖时光 / 马涛 / 尾0086
#3  天津市静姝百货经营部   / 辛夷 / 殷烟汀 / 尾1234  →  天津市优品百货经营部   / 鲜集市 / 胡建华 / 尾1234
#19 广东省降真百货经营部   / 杜若 / 澹台溪亭/ 尾9403 →  广东省甜源百货经营部   / 鲜工坊 / 田思远 / 尾9403
```

驳回原因、类目、尾号三项完全一致——这是"只改名"的验收标准。

## 三、改完立刻撞出来的五件事

改名看着是换字符串，实际把一批"写死数据"的地方全照出来了。

### 1. 同音变体与别的档案撞名

生成器有个边缘标签 `homophone_name_like`，做法是把姓名最后一个字换成「宴」
（模拟"同音近形"）。旧池子里没人叫「高宴」，新池子里有——于是

```
FAIL 字段 contact_name 有 1 个重复值
```

改成：从「滔/陶/桃」里挑一个没被占用的，再兜底扫一遍未用姓名。

### 2. 黑名单命中「张伟」

`check_mock_applications.py` 的 `REAL_INFO_BLACKLIST` 里有「张伟」「李娜」
（怕误用真实姓名）。新名池里「张」×「伟」正好能组合出来：

```
FAIL 第 34 条混入真实信息关键词：张伟
```

把名池里的「伟」换成「斌」。**没有放宽黑名单**——那条规则是对的，
要改的是数据。

### 3. 逐句复盘 3 条红：fixture 里写死了旧公司名

`scripts/test_train_replay.py` 的 `_base11` 第一句是

```python
"对，就是广东省降真百货经营部，我叫澹台溪亭。",
```

数据改名后，客户自报的家门和档案对不上 → 核身不过 → 后三轮全跑偏，
`客户重申尾号要复述` / `第三次报信息后不许逼表态` / `「是我公司」要接成「您公司」`
三条一起红。**这三条红得对**：它们测的是"客服能不能接住客户的话"，
前提是客户说的跟档案一致。

顺带把第 21 条串单用例也换了标的：原来报 `9673` 命中"青海梧丘"，
现在改用 `3465`（青海优里 / 暖星球 / 食品饮料），断言跟着换成"不许念出暖星球"。

### 4. verify 一条红：`晏经理` 不再是"客户姓名"

`_drop_name_call` 只认档案里那个姓名，fixture 里写的是「晏经理」——
联系人改成马涛之后，这个称谓不再被识别成客户名，于是"漏删"。
改成「马经理」。这条也说明该函数的行为是**按档案判断**，不是按字面。

### 5. 目录档案"不可复算"

`applications_catalog.json` 生成时会读原集词池求差集，
**必须先重生成 `applications.json`、再重生成目录档案**。顺序反了，
`check_mock_bundle.py` 就报"不可复算（重新生成后内容不一致）"。
顺序对了就过。

另外 `data/customer_cards.json` 是编译产物，改完数据要重跑
`python -m modules.customer_data`，否则 verify 报"档案卡已过期"。

## 四、验证

```bash
python scripts/gen_mock_applications.py            # 120 条
python scripts/gen_mock_catalog_applications.py    # 68 条（必须在上面之后）
python scripts/check_mock_applications.py          # 全部通过
python scripts/check_mock_bundle.py                # 全部通过（含可复算）
python -m modules.customer_data                    # 重编译档案卡
python -m modules.customer_data --check            # 一致

python scripts/verify.py                           # 269/269
python -m scripts.test_identity_verify             # 23/23
python -m scripts.test_correction                  # 21/21
python -m scripts.test_repeat_explain / test_tts_split / test_scene_isolation / test_llm_layer
EVAL_SCENE=pop_reject python scripts/adversarial_run.py --cases eval/adversarial_c4_batch01.json --rounds 1
```

## 五、没改的，以及为什么

| 没改 | 原因 |
|---|---|
| `docs/55`–`docs/57` 里的旧名字 | 那几篇是**当时线上实录**的复现记录，改成新名等于伪造证据。要看新数据看这篇 |
| `config/evolution/versions/*`、`persona/versions/*` | 进化链的基线快照，改一个字 sha 全变，"基线漂移"检查立刻失效 |
| `config/mock/customers.json` 的 12 个售后客户 | 本来就是张伟/李娜/王强这类常见名，念得出 |
| 官方资料包 `competition/` | 官方原文，不动 |
| 黑名单（含「张伟」「李娜」） | 规则正确，改数据不改规则 |

---

## 六、一句话总结

名字读不出来不是审美问题，是**核身这个动作依赖嘴和耳朵**。
生僻字自造词让"客户报姓名"这条路在物理上就跑不通——客户念不出、ASR 认不准、
客服复述也跟着错。换成熟字之后，这条路上少了一个必然的失败源。
