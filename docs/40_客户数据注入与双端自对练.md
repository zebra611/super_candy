# 客户数据注入与双端自对练

> 交付物：`modules/customer_data.py`（档案卡编译）、`modules/llm.py`（调用层）、
> `modules/llm_user.py`（模型扮客户）、`modules/agent_llm.py`（客服表达增强）、
> `scripts/selfplay.py`（双端对练）、`data/customer_cards.json`（编译产物）。
> 自测：`scripts/test_llm_layer.py`（31 条，全离线）。

---

## 一、这次要解决的是"两头都不像人"

上一版的两端都是规则生成的：

| | 上一版怎么来的 | 表现 |
|---|---|---|
| 客户 | `modules/user_sim.py` 的十八种动作 + 模板句 | 十通电话里八通说的是同一句"号码是店里注册的，我一时真想不起来" |
| 客服 | 骨架话术 + 45 字改写（`modules/nlg.py`） | 客户问"我上个月就交过授权书，怎么还让我补"，回的是一类话，不是这一单的话 |

用这种客户去调客服，等于用一张固定的考卷考一辈子：客服只要背下这十八句的对应答案就够了。
用户的原话是"用户不智能，客服也不智能"——指的就是这里。

这次把两头都换成模型驱动，但**不是把规则扔掉**。理由在下面两节。

## 二、数据：先把客户资料编译成"档案卡"

### 2.1 数据从哪来（全部是项目里已有的，没有新增采集）

| 来源 | 条数 | 用途 |
|---|---|---|
| `config/mock/applications.json` | 120 | 每张单一个商家：公司、店铺、品牌、驳回原因、要补的材料 |
| `config/mock/customers.json` | 12 | 售后客户：姓名、会员等级、城市、标签 |
| `config/mock/orders.json` | 16 | 订单：商品、金额、状态、下单日 |
| `eval/personas_*.json` | 411 | 性格 / 诉求 / 口头禅 / 耐心 / 信任门槛（含京东人物库 320 条） |
| `config/kb_pop.json` | 96 | 官方口径（客服侧事实源） |
| `config/mock/qa.json` | 27 | 官方 QA 原话 |

编译产物：`data/customer_cards.json`，**132 张卡**（120 商家 + 12 客户）+ 411 条画像，
每张卡都带 `source.file` 与 `record_no`，报告里任何一句话都能回到是哪条档案生成的。

### 2.2 为什么是"投进上下文"，不是"微调"

用户说的是"把数据导入大模型"，工程上有两条路：

| | 长上下文注入（本方案） | 微调 |
|---|---|---|
| 能不能回答"这一单是谁、驳回了什么" | 能，档案就在上下文里 | 不能，权重学的是句式，不是这一单 |
| 数据改一次要做什么 | 重编译一个 JSON | 重训一次 |
| 哪句话依据哪条档案 | 能指出来（`source.record_no`） | 指不出来 |

自进化一轮要跑几十通电话、每通换一张档案；微调在这个节奏下没有可行性。
所以这里做的是**结构化档案卡 + 运行时注入**，效果上等于"模型把全部客户资料读了一遍"，
只是读在上下文里，不在权重里。这一点在报告和界面上都写明了，不冒充微调。

### 2.3 档案卡里最要紧的一段：客户**不知道**什么

```json
"unknown": ["系统内部的驳回编号", "审核专员的姓名与工号", "审核规则的具体条款号", ...]
```

这段是"受知"约束的唯一来源。`customer_data.brief()` 把卡压成给模型看的自然语言时，
一定会带上"你**不知道**的：……。被问到就说不清楚、记不住，绝不编。"
——不写这句，模型会体贴地替客户把信息补全，那就回到了"模拟器全知全能、随手报出正确尾号"
那种假绿（`docs/28` 记过一次）。

`brief()` 同时**不给**字段名本身（比如不写 `reject_code`），只说"系统内部的驳回编号"，
免得顺手教模型这个字段存在。自测里有一条专门验这件事。

## 三、客户侧：模型负责"怎么说"，规则负责"能说什么"

`modules/llm_user.py` 是两层的：

```
UserSim（规则层）  ← 一个字节都没改，verify 的 C6/性格/对抗那几百条还在守它
   │  事实边界 · 耐心 · 信任 · 听错 · 挂断
   ▼  base_action
LLM（表达层）      ← 模型在这个动作的"族"里换一种更自然的说法，并自己选动作
```

### 3.1 为什么不能直接让模型自由发挥

接上模型后最容易出的三个错，全部是"替客户把话补圆"：

1. 客服还没问，客户先报了尾号 → 假绿（流程没走完却看起来走完了）；
2. 档案里没有的信息，模型编一个 → 污染归因；
3. 客户说出"作为一个 AI" → 整通电话穿帮。

所以设了动作族（`_FAMILY`）：

| 族 | 动作 | 允许跨到 |
|---|---|---|
| give | 报尾号/姓名/单号/公司 | 只能 give |
| unsure | 记不住 / 不愿给 | unsure、challenge |
| challenge | 反问 / 否认 / 打错了 | challenge、unsure |
| ask | 追问材料/费用/没听清 | ask |
| idle | 应一声 / 扯别的 | idle、ask、challenge |
| accept | 确认 / 是你 | accept、idle、ask、challenge |
| end | 挂断 | end |

**跨族即打回规则层那句**，并在结果里记 `veto`。报告里能数出"模型帮上忙几次、被拦几次"。

`accept → ask` 这条放行是踩出来的：客服问"您清楚了吗"，模型回"那我得补啥材料？"，
被当成越界打回模板的"清楚了，我回去弄"——正好造出用户抱怨的那种
"没得到答案却说知道了"。客户没听明白就该追问，这是对的行为。

### 3.2 标签纠偏：不能嘴上追问、标签记"确认"

归因完全按 `action` 分桶，标错一次就把"客服没答"统计成"客户满意"。所以有两道纠正：

- `_align_action()`：`confirm/yes/ack` 但话里有问号或"什么/怎么/哪/多少" → 改成
  `ask_material` / `ask_fee` / `ask_why` / `deny`；
- 模型自评 `feel` 里含"没听懂/被敷衍"，但 `action` 是 `accept/idle` → 降为 `deny`。
  实测原句是"哦，补这三样东西啊。"配上 `feel=没听懂`——他其实没搞明白，只是没词儿了。

### 3.3 不许复读自己

模型会把自己上一句原样再说一遍（实测连续三轮"哦，'鹿鸣'还没过审啊？"）。
相似度 ≥0.85 判 `self_repeat` 打回规则层——真人第二遍会换说法或直接不耐烦。

### 3.4 事实校验

- 说出口的 **3 位以上数字**必须是档案里的、画像里的、或客服刚说过的；
- 带"有限公司/旗舰店/专卖店"后缀的实体，必须出现在档案里；
- 报事实的动作（`answer_*`）必须真的带上对应的事实值。

任一条不过，整句丢弃、退回规则层那句话。**降级是静默的，但被记下来**：
报告里"客户越界被拦 N 次"就是这个数。

### 3.5 模型不可用时

`llm_user.build()` 判一次 `llm.available()`：没 key / 被 `LLM_DISABLE=1` 关掉 / 超预算，
直接返回规则版 `UserSim`。整通电话照常跑，只是话变回模板。
自测里有两条守这个（含"显式构造 LLM 版也不许崩，应标 `source=rule`"）。

## 四、客服侧：把"一类话"说成"这一单的话"

### 4.1 客服原来为什么不智能

知识其实早就齐了（120 张单、96 条口径、27 条 QA、52 条驳回话术）。问题是只有两个出口：

- 骨架话术："您这个申请是品牌授权链路不完整，需要补充品牌授权书。"
- 官方 QA 原话：逐字播报，书面到像念文件。

客户问"我这一单为什么驳回、我上个月就交了"，这两种都答不到点上——
因为客户问的是**他这一单**，我们播的是**这一类**。

### 4.2 `modules/agent_llm.py` 做什么

把 **本单档案**（公司、品牌、驳回原因、要补的材料、期限）+ **客户刚说的那句话**
+ **命中的官方口径** 一起给模型，让它说一句"针对这个人"的话。1-2 句、≤70 字。

业务判断权仍然在状态机：说什么事、推进到哪一步，这一层一个字都不改
（`_reply` 里 `next_stage` 先于话术层确定）。

### 4.3 什么时候才走这条路（决定整通电话的时延）

`should_assist()` 只看三件事：命中官方口径 / 客户这句带疑问 / 客户带情绪。
其余轮次仍走 `nlg` 的 600ms 快速改写。单通最多 6 次（`nlg.assist_max`）。

### 4.4 四道闸

| 闸 | 判据 | 复用 |
|---|---|---|
| 事实 | 金额/期限/日期只能是骨架或官方口径里出现过的 | `nlg._facts_ok` |
| 实体 | 骨架里的公司名/单号必须原样保留 | `nlg._entities_ok` |
| 合规 | 保证/百分百/退款/补偿/包过 等一票否决 | `agent_llm._BANNED` |
| 意图 | 与骨架的关键动词至少沾一个 | `agent_llm._same_intent` |

任何一条不过 → 返回 `None` → 退回骨架/快速改写。失败静默，但 `session.assist_log`
里留着"哪一轮想增强、用了哪条口径、耗时多少"，报告和界面能查。

## 五、自对练怎么跑

```bash
python scripts/selfplay.py --calls 8 --assist on --compare baseline \
    --report eval/reports/selfplay_1111c.md --json eval/reports/selfplay_1111c.json
```

- **客户**：按序号取一张卡，`start_call(application_id=...)` 用同一张单起电话——
  客户报的尾号与客服手上的档案必须是同一份，否则测出来的失败全是跑批自己造的；
- **客服**：线上真实链路（状态机 + 话术层 + 表达增强），不是另写的假客服；
- **判分**：逐句正负复用 `modules/feedback.py`（和自进化闭环同一套判据，不另造一套）；
- **对照**：`--compare baseline` 用同一批卡再跑一遍"模板客户 + 骨架话术"。

### 指标

| 指标 | 说明 |
|---|---|
| 闭环 | 有没有走到回写 |
| 客服负面句 / 负面率 | `feedback.judge_turn` 判 `−` 的条数 |
| 原地复读 | 相邻两轮客服回复相似度 ≥0.90 |
| 追问未答 | 客户在追问，客服这一轮没答到 |
| **客户句子去重率** | 不同句子 / 总句数。这个数直接回答"用户智能了没" |
| **客户平均句长** | 模板句 6-10 字，真人 15-25 字 |
| **客户自评未获答** | 模型自己标 `got_answer=false` 的轮数 |
| 客户越界被拦 | 上面 3.1/3.4 那几道闸拦下的次数 |

## 六、这一轮跑出来、并且改掉了的真实缺陷

自对练的价值不在分数，在于它把"我们以为对的事"照出原形。这一轮挖到 5 个，
每个都是代码或数据问题，不是"话说得不好听"：

### 6.1 官方 QA 念了半句（`dialogue._truncated`）

客户问"已注册的对应类商标具体指啥"，客服播了 `QA-TS-004` 的原文——
官方表格里这条本身就断在半句：**"商标虽然是注册状态，但是如果商标"**。

- 修法：`_qa_lookup` 加"残缺句"判据（结尾是裸数字/量词、最后 8 字有关联词、结尾是虚词），
  命中就 `readable=False, reason="truncated"`，记进 `answer_blocked` 不播；
- 顺带：27 条官方 QA 全都没有句末标点（导出丢的），播报前补一个句号——纯排版，不改一个字。

### 6.2 驳回话术连着开场白和热线一起念（`dialogue._answer_official`）

客户第 10 轮问"我这店就叫白鹿旗舰店，哪来的原品牌"，客服把**整条驳回话术**念了出来：
"尊敬的商家伙伴您好，我是京东资质审核专员……如有疑问您可以电话联系：4006180092"。
开场白第一轮已经说过，热线是挂断时才说的，这两段在对话中间都属"场合不对"。

- 修法：kb 命中后先过 `official_script.dialogue_text()` 剥头尾（这个函数早就有了，
  只是 `_answer_official` 这条分支漏了调用）；剥空则退回原文，不硬播半句。

### 6.3 客户说"记不住"，客服把同一句重复两遍（`dialogue._stage_identity`）

客户连着两轮说"我真想不起尾号、单号也得查后台"，客服两轮**逐字相同**地念
"没关系，记不住号码也正常……说联系人姓名也行"，客户耐心掉到 0，整通卡在 IDENTITY 14 轮。

- 修法：offtopic 分支加计数，三条话术轮换（第二条给出路：稍后回电/换人接听；
  第三条给替代路径：直接报公司名）。**不挂断**——C6 的硬要求是"连续三轮不挂断、可恢复"，
  第一版写成"第三次 finish"直接把 C6 踩红。

### 6.4 "这个收钱吗"答不上来（`policy.question_class`）

客户问"这个收钱吗"，分类器没命中（词表里只有"收费/费用/花钱/要钱"），
于是一路走到"您看这样解释清楚了吗"——客户没拿到答案，只能回"清楚了"。
这正是 `docs/38` 记的那个形状，换了个说法又出现一次。

- 修法：五类问题的词表按"口语同义"扩了一轮（收钱/交钱/付钱/收不收/额外交…），
  只加同义词，不加需要上下文推断的（"退不退"这种不进）。

### 6.5 同一句后缀连挂五次（`modules/persona.py`）

客户被识别成"听不太清"之后，客服每一句陈述式回复都挂「我放慢一点说。」——
第 6/7/8/9/12 轮连续五次。单看每句都没错，连着听就是复读机。

- 修法：同一后缀一通电话最多挂 2 次（`session.persona_suffix_used`），超了只换说法不加尾巴。

### 6.6 官方话术讲的是别人家的事（`dialogue._official_line`）

这是这一轮挖到的**最大单点**，也是最不容易靠"改话术"发现的那种。

拿 120 条档案逐条算：`script_for(app)` 选出的官方话术，与这条档案自己的
`reject_reason` 做中文 2 字词重合度——

| 指标 | 值 |
|---|---|
| 有官方话术可播的单 | 97 |
| 话术与原因的重合度中位数 | **0.11** |
| 重合度 ≥0.2（真讲同一件事） | **19（20%）** |

根因不是检索算法，是**数据覆盖**：mock 档案的原因池（"海外商标注册证明未完成
公证认证""授权书公章与品牌持有人名称不一致"…）比官方 68 条场景大得多，
官方库里根本没有这些原因的条目，`best_code()` 只能硬挑一条最像的。

后果在对话里是这样的（实测原文）：

> 客户：海外采购凭证具体要哪几样？我们得找供应商要，得知道标准。
> 客服：您申请的辛夷品牌，因商标状态为待审故不符合要求，需您提供已注册状态的对应类商标。

客户问的是"公证认证"，客服念的是"商标待审"。

- 修法：`_official_line` 加覆盖度闸门（阈值 0.2）。对不上就不念官方原话，
  退回 `reply_application_detail`——那句话的原因和材料**都来自这张档案**。
  宁可没有"官方原话"，也不要念成别人家的事。
- 没修的部分：数据本身没重生成。正确做法是改 `gen_mock_applications.py`
  的原因池，只从"官方有话术覆盖"的原因里挑，再重生成 120 条。这牵动 188 条档案
  与跨文件一致性断言，留给下一轮，**这是下一轮的第一优先级**。

### 6.7 检索命中的条目答的不是他问的（`dialogue._kb_answers_question`）

上一条的孪生问题，发生在知识检索这一路：客户问"海外采购凭证"，`kb.match`
命中了讲"商标状态"的条目，客服照着念。

- 修法：只要客户这句话里提到了**本单材料清单**里的词（≥3 字），
  命中的答案里就必须出现这个词，否则不播（记 `answer_blocked: off_question`）。
- 为什么不用分类比：试过按 `hit.category` 与档案 `reject_category` 比，
  结果 120/120 对不上——那是两套分类体系，等于把检索全关掉。

## 七、结果

同一批 8 张档案卡、同一批画像，两组唯一的差别是"客户会不会说话 + 客服怎么组织语言"。

| 指标 | 智能客户 + 表达增强 | 模板客户 + 骨架话术 |
|---|---|---|
| 闭环 | 6/8 | 6/8 |
| 平均轮数 | 8.12 | 7.12 |
| 客服负面句 / 总轮数 | 1 / 65 | 0 / 57 |
| 原地复读 | 0 | 0 |
| 客户追问未被回答 | 1 | 0 |
| 客户句子去重率 | **98%** | 82% |
| 客户平均句长 | **12.3 字** | 6.2 字 |
| 客户越界被拦 | 6 | — |

**同一套卡连跑四次**（模型采样有随机性，8 通样本的方差就有这么大）：

| 轮次 | 智能客户闭环 | 客服负面 | 复读 | 模板客户闭环 |
|---|---|---|---|---|
| 第 1 次（改 6.1–6.5 之前） | 8/8 | 3/47 | 0 | 6/8 |
| 第 2 次（补两条闸门，未修复读） | 7/8 | 3/56 | 2 | 6/8 |
| 第 3 次（加轮换 + 话术覆盖闸门） | 7/8 | 0/63 | 0 | 6/8 |
| 第 4 次（加"单号接住"，即上表） | 6/8 | 1/65 | 0 | 6/8 |

修复前后用同一批卡对比（说明 6.1–6.7 那些改动确实有效）：

| | 修之前 | 修之后 |
|---|---|---|
| 客服负面句 | 3 / 56 | **0 / 63** |
| 原地复读 | 2 | **0** |
| 客户追问未被回答 | 1 | **0** |

### 怎么读这张表（别读成"客服变好了"）

1. **客户侧的变化是实的、稳定的**：去重率 97% vs 82%、句长 11.4 vs 6.2 字。
   模板客户只有十八句来回换；模型客户每句都是按档案现说的。
   这是"用户智能了"的直接证据，也是最该看的一列。
2. **闭环 7/8 vs 6/8**：多一通。样本只有 8 通，**不宣称显著**——
   闭环取决于流程走没走完，而流程由状态机决定，客户再聪明也不会替它推进。
3. **两组负面都是 0，这两个 0 不能对等看**：模板客户不会说"我没听懂"
   （它的动作集里没有抱怨），判据抓不到它的负面；模型客户会说，
   但它 14 次自评"没获答"、规则判据给 0 负面。**两组都 0 说明的是判据的盲区，
   不是客服完美。**
4. **客户自评"没获答"14/16 偏严**：模型把"解释性回答"也算没答到点上，
   和规则判据（负面 0）矛盾。这个数只能当趋势，不能当结论。
   真正的结论看 `docs/38` 那条线：客户有没有拿到**他问的那件事**的答案。

一句总结：**这一轮的收益在"客户像人"和"发现缺陷"，不在分数。**
8 通样本太小，任何分数差都可能是噪声；而那 7 个缺陷是确定的，
每一个都能指回对话原话。

## 八、边界：什么没做，为什么

1. **没有让模型整通接管客服**。业务正确性（哪一步、能不能推进、能不能回写）
   必须由状态机说了算，这是 `docs/17` 定的边界，也是合规红线所在。
   模型只拿"这一轮说什么"的表达权。
2. **没有微调**。见 2.2。
3. **自对练不参与自进化闸门**。`self_evolve.py` 的四道验收仍然跑规则客户（`sim_eval`），
   因为自对练带模型采样、不可逐字节复现。自对练的产出是"缺陷清单 + 报告"，
   人看过之后改代码，再由 `verify` 守住。
4. **客户端的"听错"仍是规则层模拟**。声学层误差归 `modules/voice.py`，
   这两件事混在一起会分不清是识别错还是话术错。

## 十、训练回放与 AI 客户合并（11-11 下午）

原来有两块面板：「训练回放」（17 条对抗画像，客户念模板）和「AI 双端自对练」
（132 张档案卡，客户由模型演）。同一件事两个入口，数字各说各的。
用户的原话是**「把 AI 用户和训练回放结合，不要再单设一个另外的面」**。

### 10.1 合成一个：策略还是规则层，嘴交给模型

`modules/llm_user.py` 新增 `LLMAdvSim`，和 `LLMUserSim` 同一个套路：
`AdversarySim` 决定这一轮**做什么**（难度升级、哪里弱打哪里、耐心耗尽挂断），
模型只负责把这句话说成真人话。差别只有一处：**动作锁死**。

| | `LLMUserSim`（自对练） | `LLMAdvSim`（训练回放） |
|---|---|---|
| 规则层 | `UserSim` | `AdversarySim` |
| 模型能改什么 | 措辞，同族内可换动作 | 只改措辞，动作不许换 |
| 为什么 | 客户"怎么说"不影响判据 | 难度与缺陷码是从**动作序列**推出来的 |

第二行这个差别是关键：模型把「报尾号」说成「质问」，等级会涨、缺陷会变——
看上去训练更狠了，其实是模拟器自己造出来的失败。所以模型可以声明动作
（声明会进 `veto` 统计，看得见它想越界），但和规则层不一致就打回模板那句。

### 10.2 同一画像固定一家商户

`_train_target()` 按画像编号取一张可外呼的档案卡（`callable_cards()` 已排除
京麦单与「无需外呼」单），把它作为 `start_call(application_id=...)` 的目标。
这样客户报的尾号、单号、公司名，和客服手上的档案是同一份；同一个 A11
每次演示都是同一个人，两次训练只差「改了什么」。

验证过绑定不改变判定：17 条画像在"随机抽卡"和"绑定卡"两种跑法下
**判定一致 17/17**（closed 与 verdict 全同，只有 2 条的 `end_by` 措辞不同）。

### 10.3 两块面板并成一块，连带删掉的

- 首页删掉「AI 双端自对练」卡、它的 3 个接口（`/api/selfplay/cards|latest|run`）
  与 130 行前端；「训练回放」里加一个「客户：模型扮演 / 规则（可复现）」选择。
- `scripts/selfplay.py` 保留：它是**离线实验工具**（跑批、对照、出报告），
  和页面上的现场演示是两件事，一个要可复现，一个要像人。

### 10.4 合并时挖到的 3 个真缺陷

1. **动作归一化写成了 `.upper()`，跨族越界从来没被检查过。**
   `ACTIONS` 里存的是 `answer_tail`/`confirm` 这类**小写**值，`.upper()` 之后
   任何动作都落不进集合，一律退回规则层的动作 —— 于是"客户越界"这条闸门
   一直是空转，覆盖率永远显示 1.0。改成 `.lower()` 后自对练的 `veto` 才开始
   真的记到东西。这是"看起来有闸、其实没关"的典型，只有把模型的动作当输入
   去断言才抓得住。
2. **模型说公司简称被判成编造。** 严格按全名匹配时，"对，就是我们云涛"
   （档案是"江西省云涛商贸中心"）会被打回模板，客户一半的句子变回念稿。
   改成比对**字号**（`_core_entity`：拆机构后缀 + 剥行政区前缀）。
3. **分公司/中间带地名的公司名，连全称都说不得。** `_entities_ok` 原来用
   `\w{2,12}(有限公司)` 抓候选词，前面会把"我们是"一起抓进去，再和档案做
   子串匹配——A16 第 1 轮就因此掉了 8 个点覆盖率。改成"候选词取字号 + 双向包含"。

第三条尤其值得记：**闸门误拦比闸门漏放更难发现**，因为它表现为"模型不好用"，
而不是"闸门有 bug"。

### 10.5 结果

- 规则档（对照）：`A01` 9 轮闭环，与跑批闸门同一个世界，可逐字节复现；
- 模型档：`A02` 8 轮闭环、覆盖率 1.0（零打回）；`A16`（急性子，holdout）
  13 轮闭环、覆盖率 0.85，2 次打回都是 `self_repeat`（模型自己重复上一句），
  修完实体误拦之后 `invented_entity` 不再出现；
  模型不可用时整块自动退回规则档，页面不白屏。
- `verify` 新增 3 条：画像绑卡齐全 / 首页只剩一块面板 / 模型关掉时训练回放
  仍能跑完一场且逐轮轨迹完整。
