# 55 · 核身报错了，客服却说「核对上了」

2026-11-12 22:36，用户看完线上说了一句：

> 申请单号后六位对不上与客服的验证，手机号报错也有可能被客户识别成正常的

照着这句话在线上跑了一通（电话打给 QZ202611060001 川上商贸，预留尾号 0086），
报了个 `1234`：

```
我：1234
客服：核对上了，感谢配合。辛夷品牌、美妆个护类目没有通过审核，原因是海外商标
      注册证明未完成公证认证，需要补充境外主体证明、中文译本、海外采购凭证…
```

**这句话里有两个事故**：`1234` 不是本单的号，却被判「核对上了」；念的
「辛夷品牌、美妆个护」也不是川上的（川上是「闻樾品牌、家用电器」）。
这是把 A 商家的驳回原因念给了 B——串单，同时让客户以为核身已经通过。

## 一、三层问题，是三个不同的根因

### 1.1 串单：`target_locked` 只认"外部显式指定的单号"

`app.start_call` 里原来是这一行：

```python
sess["target_locked"] = bool(application_id)
```

只有运营在请求里显式传 `application_id` 时才锁目标。而**页面点"开始"不传**——
走的是外呼名单取下一条（`next_outbound_target()`）。于是：

- `outbound_target` 有值（开场白报了"川上官方旗舰店"）→ 系统知道打给谁
- `target_locked` 是 `False` → 核身时**不跟本单比**，直接拿客户报的数字查库
- `query_application("1234")` 命中 QZ202611060003（天津静姝，尾号 1234）
- `slots.application` 被换成静姝，接着念辛夷的驳回原因

2026-11-11 那次修的是"打给降真、念梧丘"（客户报 9673），修法就是
`_verify_against_outbound`——但它挂在 `target_locked` 这个条件下面，
而线上这条路 `target_locked` 一直是 `False`。**上一轮的修复在线上没生效过。**

### 1.2 无反馈：`identity_mismatch` 写了，但没人读

`_verify_against_outbound` 对不上时会记一笔：

```python
session["identity_mismatch"] = slot
```

全仓库搜这个键，**只有这一处写入，零处读取**。所以客户报错之后，下一句走的是
`_ask_identity` 的通用追问（"那我换个方式核对：…" / "那方便说一下您的姓名吗"），
听起来就是"客服又问了个新问题"。客户不知道自己刚报错了，自然以为核对通过了。

### 1.3 单号后六位被直接丢掉

客服自己的话术（`reply_ask_tail_2`）说的是：

> 那我换个方式核对：**申请单编号后六位**，或者申请时预留手机号的后四位，任意一个都行。

但 `classify` 只认"孤立 4 位数字段"，`_extract_application_id` 只认
`QZ` + 12 位。客户按提示报 `060001`（本单正确后六位）：

```
我：060001
客服：好的，核对申请单需要您预留手机号的后四位，说四个数字就行。
```

数字被丢了，等于让客户把刚说的话再说一遍。**客服给了一条自己接不住的路。**

## 二、改法

### 2.1 HTTP 入口锁目标（`app.py`）

```python
def start_call(application_id=None, random_target=False, lock_target=False):
    ...
    sess["target_locked"] = bool(application_id) or bool(lock_target)
```

`/api/call/start` 传 `lock_target=True`；脚本直调 `start_call()` 不传。

为什么用开关而不是"有 outbound_target 就锁"：C4 那 340 条用例自带台词
「尾号4565」，靠"报哪个号就查哪个号"跑通；直接收紧会让它们全部卡在 IDENTITY。
分层之后——

- **HTTP = 真实外呼**：名单取到的那一单就是本单，报别家的号一律"对不上"
- **脚本直调 = 跑批**：行为与改动前逐字一致（C4 batch01 复跑 **40/40**，100%）

顺带把 `_verify_against_outbound` 在赛题场景的客户库回退关掉
（`allow_customer=not use_app`）：120 份申请单和 12 位售后客户共用 4 位尾号键空间，
回退等于给"报了个售后客户的尾号"开门。

### 2.2 对不上就说出来（`modules/dialogue.py`）

新增 `_IDENTITY_MISMATCH` 四句话，在 `_ask_identity` 出口按槽位拼在追问前面：

| 客户报的 | 客服说 |
|---|---|
| 尾号 | 您报的这个尾号，跟这张申请单上预留的号码对不上。 |
| 申请单号 | 这个申请单编号我这边对不上。 |
| 姓名 | 这个姓名跟申请单上的联系人对不上。 |
| 公司名 | 这个公司名跟申请单对不上。 |

**只说不符、不说正确值**——正确值一旦念出来，核身就等于没做。
每次报错都会说（客户第二次又报错，他得知道自己又错了），但话术会换，
不逐字复读。

### 2.3 按位数分流（`_take_identity_slots`）

```
4 位        → 预留手机号后四位
6 位        → 申请单编号后六位
7~11 位     → 客户在报整号，取末四位当尾号
```

线上实测（锁定本单 QZ202611060001）：

| 客户报 | 结果 |
|---|---|
| `QZ202611060001` | 核对上了（闻樾/家用电器） |
| `060001` | 核对上了 ← 旧版直接丢 |
| `我的单号后六位是060001` | 核对上了 ← 旧版直接丢 |
| `19900000086` | 核对上了 ← 旧版直接丢 |
| `999999` | 这个申请单编号我这边对不上 |
| `1234` | 您报的这个尾号，跟这张申请单上预留的号码对不上 |

## 四、还没做

- 报 8 位、10 位数字（客户报错位数）时取末四位核，命中不了就说"尾号对不上"，
  不会追问"您报的是几位"——比"当没听见"好，但还不算听懂。
- 真实外呼里客户报的可能是**另一个人**的尾号（同事接电话）。现在会说"对不上"，
  然后换问姓名/单号；没有"请转接本人"这条并行路径，靠 `reply_offtopic_2`
  里那句"请店里另一位同事接听"兜着。
