# 43 · 让大模型当客服，把它说过的话录成 mock

## 一、先把问题说准

用户的判断是：「现在用户是智能模拟了，但是客服太傻了，不是你微调就能解决的。」

对。而且不是「措辞不自然」那种傻。线上实录里，客服说的是：

```
客：这号我早报过三遍了！      服：好的，收到。咱们回到正题，您可以简单回我一句清楚了或者还有疑问。
客：对，是我公司。            服：对，是您本人。那这几样材料您清楚怎么准备吗？
客：后台卡得我刷不出来。      服：清楚了，您稍等我这边处理。
```

真正的问题在前面几轮已经定位过：**说什么由规则定，模型只能改语气**。

`nlg.assist` 的输入是已经定死的骨架：

    好的，收到。咱们回到正题，您可以简单回我一句清楚了或者还有疑问。

客户说「我早报过三遍了」，骨架里没有「承认重复」这个选项。模型再强，
也只能把这句话说得客气一点——**它能改语气，改不了内容**。

规则能枚举的形状有限，客户一换说法就露馅：「刷不出来」不在障碍词表、
「你到底是谁」不含「你谁」、「是我公司」被当成「是我本人」。这些不是靠
补词表能补完的——词表永远差一条。**这就是「微调解决不了」的意思**：
要换的不是措辞，是谁来决定说什么。

## 二、加一层「模型客服」（`modules/agent_free.py`）

输入三样，输出一句话：

    本环节目标 + 本单事实 + 最近对话 + 客户刚说

    → 一句自由组织的话（1-2 句，≤80 字）

和 `assist` 的区别就一句：`assist` 拿骨架当**输入**，`agent_free` 拿骨架当**兜底**。

### 三条边界，一条都不能越

1. **事实只能来自本单档案 / 官方口径。** 复用 `nlg._facts_ok`：模型编一个金额、
   一个日期、一条政策，这一句就丢掉，退回骨架。实测拦下过「11月19号前搞定」
   （档案里是 `2026-11-19`，改个说法就是另一个承诺）。
2. **流程不由模型改。** `next_stage` / 写工单 / 收线原因仍由规则状态机决定。
   模型只决定这一句怎么说。否则 88 条验收的闭环口径立刻失去意义。
3. **任何异常都退回骨架。** 超时、空、禁语、太短、和最近几轮太像、跑题，
   全部返回 None。外呼里没声比话说得难听严重得多。

### 五道闸门

| 闸门 | 拦什么 | 踩过的坑 |
|---|---|---|
| 事实 | 编造数字/金额/日期 | 「11月19号前搞定」被拦 |
| 禁语 | 承诺通过、索要证件、**自曝无能** | 模型说过「这个我确实没法确认，稍后让专员回电」 |
| 长度 | <8 字（信息丢了）、>80 字 | 把材料清单+截止日塞进一句 |
| 重复 | 与最近 5 轮相似度 ≥0.75 | 连着四轮都以「尾号9403，对上了」开头 |
| 跑题 | 与骨架的动词一个都不沾 | 骨架说接障碍，模型开始讲收费标准 |

## 三、第一个坑：判据卡词不卡意思

第一版把赛题的「必答要素」（`must_say = ["复述"]`）做成**输出必须包含**的闸门，
结果 CONFIRM 的每一轮都被拦：

```
模型：您这三样材料——授权书、链路证明、营业执照，清楚怎么准备了吗？
闸门：must_say=['复述'] → 不通过
```

意思一字不差，就是没有「复述」这两个字。**这是规则层最容易犯的错：
用词代替意思。**

改法不是放宽闸门，是**换切分**：骨架本来就承担硬要素的那一轮（骨架里含这几个词）
就用骨架，骨架不承担要素的轮次（追问、答来源、接障碍、认复读）才交给模型。

效果：13 轮一通，模型接管 10 轮，骨架 3 轮（开场自报、核身问句、收线——都是该由
规则逐字保证的）。

## 四、第二个坑：模型自己会「装傻」和「无中生有」

- **无中生有**：连着四轮以「尾号9403，对上了」开头，而客户那几轮根本没提尾号
  ——模型从档案里挑了个值，假装是客户刚说的。相似度闸门拦不住（整句不同，
  只有前缀相同）。补 `_drop_invented_ack`：第一个分句里的 4 位数字不在客户
  这条消息里，就砍掉这半句（砍完剩「对上了。」这种残骸也一并去掉）。
- **自曝无能**：客户问「你这电话哪打来的」，模型答「这个我确实没法确认，
  稍后让专员给您回电」。这一轮客户问的恰恰是档案里有答案的事——等于把
  「客服太傻」从规则层搬到了模型层。禁语加「确认不到/没法确认/查不到」，
  提示词里直接给出标准答法。

## 五、录制：把它说过的话变成 mock

模型说的话**不可复现**：同一通跑两遍不一样，闸门今天绿明天红。
所以它不能只活在线上，说过的话要落成数据。

`scripts/record_agent.py`：

```
python scripts/record_agent.py --n 3          # 客户侧也用模型
python scripts/record_agent.py --n 6 --user rule
```

产物两份：

    eval/fixtures/agent_free/<画像>.json   这一通的逐轮实录（客户话 + 客服话 + 来源）
    config/mock/agent_lines.json           按环节汇总的话术库

逐轮实录里每轮带 `source: model|skeleton`——为了这个字段，`_reply` 加了
`reply_source`，`handle_turn` 的返回里也补了一行透传。少了这一行，
训练轨迹每轮都显示"未知来源"，录制统计全是 0 轮（第一次就是这样，
代码其实一直在调模型）。

## 六、回放：`AGENT_FREE=replay`

```python
rows = _lines()["by_stage"][stage]          # 录制库按环节分组
best = 相似度最高的一条（门槛 0.55）
命中 → 过同一套闸门 → 用录制的话；未命中 → 退回骨架
```

不调模型、可逐字节复现，说的仍然是模型组织过的人话。
演示用 replay，线上用 llm，跑批用 rule（`AGENT_FREE=0`）。

## 七、两次「隔离把自己人也隔了」

1. **import 污染**：跑批脚本模块级写了 `setdefault("AGENT_FREE","0")`，
   而 `app.py` 的训练接口会 `from scripts import adversarial_evolve`——
   线上演示的模型客服被一起关掉。表现：录了三通，**模型说 0 轮**。
   → 挪到 `if __name__ == "__main__":` 里。
2. **放错目录**：话术库第一版写到 `config/scenes/pop_reject_lines.json`，
   而那个目录下每个 json 都会被当成**场景包**校验（缺 `scene_name`/`stages`
   直接判红）。verify 当场 248/251。→ 移到 `config/mock/`。

两条都是"我加了道闸门，然后被自己的闸门绊倒"。前者靠「统计结果是 0」发现，
后者靠跑闸门发现——**这两个数字都得真的看一眼**。

## 九、没解决的，写在这

1. **A03 那通被判失败（闭环了但期望不闭环）**：第 9 轮客户说「我这身份信息
   不随便报，你先说清楚你们是哪个部门的」，系统却走了 WRITEBACK 写了「同意」工单。
   这是**状态机**对「拒绝 + 质疑」的判定问题，不是模型话术问题——
   和前面修的「打错了还写工单」是同一类。`_REFUSE_MARKS` 缺「不随便报」。
   这一轮没改，因为动的是 consent 判定，风险高，要单独一轮。
2. **「您是现在同意，还是暂时不需要呢」串到资质场景**：这句来自
   `config/evolution/adversarial/*.scene.json`（对抗进化产出的变体场景）。
   资质驳回不是营销，问「同意吗」不成立。属于配置优先级/进化产物污染，
   要单独查 `APP_CONFIG` 的解析链。
3. **接管率还偏低**：骨架仍占一部分轮次（首句、核身、复述、收线）。
   这是刻意的——那些轮次必须逐字可追溯。但如果要更"像人"，
   下一步是让模型也参与这些轮次，同时把「必答要素」改成可验证的语义判据
   （比如 CONFIRM 检查"有没有问到确认"，而不是"有没有复述两个字"）。
