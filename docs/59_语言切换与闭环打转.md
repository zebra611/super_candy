# 11-13 两件事：说 ok 不切英文 / 清单发完不许打转

> 两条用户反馈，一条是语言，一条是闭环。放在一篇里，因为根子是同一个毛病：
> **系统在"猜用户想干什么"，而不是看用户到底说了什么。**

---

## 一、说 ok、yes 不该切英文

### 用户原话

> 回答 ok、yes 的时候不要立马切英文，直到用户使用完整的英语句子或者明确说
> 我中文不好，才转换成英语。

### 旧判据错在哪

```python
letters = "".join(_LATIN.findall(t))
if len(letters) >= 2 and low and not looks_like_code:
    return "en"          # ← 两个拉丁字母就切英文
```

`ok` 两个字母，`yes` 三个字母，都过线。于是客户只是应了一声，客服下一句
就整段改口说英语——客户并没有要换语言，只是点了下头。11-12 加英文支持时
为了"说 yes 不能毫无反应"，把判据做成了"有没有英文"，把"是不是在说英语"
这件事整个丢了。

### 新判据（`i18n.detect`，按顺序判）

| 顺序 | 条件 | 结果 | 例子 |
|---|---|---|---|
| ① | 明确要求中文 | zh | `i can't understand english` / `can you speak chinese` |
| ② | 明确说中文不好 / 要英文（**可以是中文说的**） | en | `我中文不好` / `不懂中文` / `说英语` |
| ③ | 句子里有中文 | zh | `请问是安食吗` |
| ④ | 明确问"你会说英语吗" | en | `do you speak english` |
| ⑤ | 能对上中文短句的英文**短回答** | **保持当前语言** | `ok` / `yes` / `thanks` / `what materials` |
| ⑥ | 完整的英文句子 | en | `what is this`（3 词带助动词）/ `I want to know why…`（≥4 词） |
| ⑦ | 其余（数字、标点、单个词） | 保持 | `0086` / `QZ202611060001` |

第 ② 条必须排在"句中有中文→zh"之前，否则「我中文不好」会被判成中文——
这正是用户说的那半句，也是最容易漏的一条。

"完整句子"的判据不是"词多"：≥4 个词，或 3 个词但带主语/助动词
（`i` / `you` / `is` / `do` / `can` …）。这样 `yes i am` 仍然算短回答（它是
确认，不是语种），`what is this` 才算在说话。

### 连带改的一处

`to_zh()` 原来只在 en 模式下跑。判据改完后，中文模式下的 `ok` 不再切英文，
`ok` 会原样进分类器、被当成没听懂，客服反问"您刚才说什么"——客户明明应了
一声。现在两种语言模式下都先归一成中文等价句（`ok` → `是的`），流程照常走。

### 还发现一个会挂断人的洞

`classify` 把"无中文且无数字"判成噪声，而噪声连续三轮就收线（"可能信号不太好"）。
以前英文用户每句都算噪声；判据改完后，只有说完整英文句才进 en，进了 en 之后
每句都是"无中文"——三句就被挂断。现在噪声通道只对中文会话生效
（`if flags.get("evidence") == "noise" and session.get("lang") != "en"`），
并有用例守：连说四句英文不许收线。

## 二、清单发完之后原地打转

### 用户原话

> 前面还很正常，后面就开始牛头不对马嘴了。"不用再等我复述"这句话也很奇怪。
> 而且闭环的时候甚至没有说问候语并说明客服电话，而且通话还能继续下去，很怪。

### 复现（本地，30 秒）

```
我：是的 → 核对申请单需要您预留手机号的后四位
我：0086 → 核对上了，暖时光品牌、家用电器…需要补品牌授权书…
我：材料 → 清单我已经发到后台了，忘了随时翻。       ← checklist_sent=True
我：对   → 清单已经发到您商家后台了…不用再等我复述。这一步您清楚怎么补吗？
我：对   → 嗯，清单就在您后台，忘了随时翻；哪一步卡住直接说，我单讲这一步。
我：对   → 我刚才可能没说清楚，嗯，清单就在您后台，忘了随时翻…     ← 复读
我：对   → 嗯，清单就在您后台…                                    ← 又复读
```

三件事同时成立：**阶段停在 NEED 不动**（`_short_affirm` 分支无条件 return，
永远进不了 OFFER/CONFIRM）、**同一句反复念**（`n >= 2` 走同一个 else 分支）、
**话术在自说自话**（客户没让客服复述过，客服却说"不用再等我复述"）。

### 改法

1. `_checklist_again_reply` 从"原地应答"改成"最多接两次就收口"：
   - 第 1 次：短确认 + 把四段式③问回去，**推进到 OFFER**；
   - 第 2 次：换一句（"清单就在后台，照着传就行…现在方便提交吗？"），推进到 CONFIRM；
   - 第 3 次：不再问，按"客户已经认可"回写收线。
2. `_short_affirm` 分支只在 NEED/OFFER 生效：CONFIRM 的"对"是四段式④的表态，
   得交给阶段逻辑去写字收线，不能在这里被当成"知道了"。
3. 话术去掉"不用再等我复述"，改成"需要的时候直接翻后台清单就行"——主语换回客户。
4. `_skeleton_variant` 加语气词剥离：原来会拼成"换个说法，嗯，清单就在…"。

### 收线与"通话还能继续"

- 收线句（WRITEBACK 的 `reply_checklist_done`）本身带"再见"，`_with_hotline`
  会在"再见"前插入热线——这条路径**本来就有热线**，但整条链路走不到（见上），
  客户看到的是"打转 → 自己挂断"。修好推进之后，收线句是：
  「…清单也在您商家后台了，随时可以翻看。感谢您的配合。如果还有问题，直接打电话
  联系 4006180092。再见。」
- 收线后（stage=DONE）再来一句，只回一句"已经结束 + 热线"，三句轮换不复读；
  **不再走业务**。唯一的例外是改口/表态（含"我说错了""我同意""那就办吧"），
  那些要出新版本工单——课程用例 EV01 正是"先说不要钱、听到免费后改口"。

### 同一批发现的误判：「麻烦」被判成骂人

情绪词表里有「烦」，而「麻烦您把清单发我」含「烦」——客服回
「非常抱歉让您有这样的感受」。同一类还有"滚筒洗衣机"（滚）、"垃圾袋"（垃圾），
在这个赛题的类目里都是正经商品名。现在判情绪前先扣掉礼貌前缀与商品词，
真骂人的「真麻烦」「别烦我」照样命中。

## 四、一条教训

这两件事表面无关，根子一样：**判据写的是"有没有某个特征"，而不是"用户在做
什么"。** 有拉丁字母 ≠ 在说英语；说"对" ≠ 想让客服再念一遍清单；句子里有
"烦" ≠ 在骂人。特征到处都是，行为只有一个——判据要贴着行为写。

## 五、顺带修掉的一个称呼：出话路径统一剥句首称呼

改完上两条、上线复测时看到收线句变成：

```
马涛，这通电话就先到这里          ← 第一版
马涛先生，这通电话就先到这里      ← 补完全名+尊称之后
马涛您好，这通电话就先到这里      ← 补完问候语之后
```

`agent_free` 内部的 `_drop_name_call` 只管它自己生成的那一句；措辞层（nlg）
把骨架整句重写时会再加一个称呼，加完就没人管了。现在在 `_reply` 的改写之后
补一道，**只剥句首**（`马涛，` / `马涛先生，` / `马涛您好，` / `马经理，`）。

为什么不整句过滤：客户自己报了姓名时，客服复述一次是承接他给的值。
verify 有一条专门守这个区别——只说"是我"不许带名字，说了"是我，马涛"才允许复述。
第一版做成了整句过滤，那条当场红。
