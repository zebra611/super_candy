# 部署与一键启动（M8）

> 归属：4 号 黄睿哲。涉及文件：`Dockerfile`、`docker-compose.yml`、`启动.bat`、
> `启动全部.bat`、`mock_business/`。
> 目标：**别人拿到仓库，三条命令之内能跑起来；跑不起来时，报错能指出是哪一层。**

---

## 1. 四种跑法，按场合选

| 场合 | 怎么做 | 需要什么 | 起不来的典型原因 |
|---|---|---|---|
| 本地自己开发 | 双击 `启动.bat` | Python 3.9+ | 没装 Python / PATH 里是应用商店的假 python |
| 想连 Mock 业务系统 | 双击 `启动全部.bat` | 同上 | 8100 端口被占 |
| 换机器/换系统复现 | `docker compose up --build` | Docker | 镜像没拉到，网络问题 |
| 给老师/评委发链接 | GitHub Codespaces 或托管沙箱 | 平台 | 没注入 `DASHSCOPE_API_KEY`，听起来是机械音 |

四种跑法用的是**同一份代码、同一份配置**，没有"演示专用版本"。
这点很重要：如果演示版本和仓库版本不一致，答辩时被要求现场跑一遍就会翻车。

## 2. 本地：双击

### `启动.bat`
原来的入口，行为不变：找 Python → `python app.py` → 浏览器自动打开
`http://127.0.0.1:8000`。

它的 Python 探测逻辑值得说明：本机 PATH 里的 `python` 是应用商店的占位程序，
执行只会打印 "Python was not found" 并以 0 退出。所以脚本不查 `where python`，
而是**真的执行一次 `import unicodedata`**，用退出码判断——这是唯一可靠的测试。

### `启动全部.bat`（新增）
起两个进程：

```
[1] Mock 业务系统   http://127.0.0.1:8100/mock/health   （独立窗口）
[2] 通话服务        http://127.0.0.1:8000
                    http://127.0.0.1:8000/dashboard     （指标看板）
```

Python 探测逻辑**不重复实现**，直接 `call 启动.bat --check` 复用结果。
"能跑"的判断标准只保留一份，否则两个脚本迟早给出不一样答案。

## 3. Docker：一条命令起全套

```bash
docker compose up --build
```

| 服务 | 端口 | 说明 |
|---|---|---|
| `app` | 8000 | 通话服务 + 看板 |
| `mock` | 8100 | Mock 业务系统（名单/订单/工单） |

### 镜像里的三个决定

**1. 用 `python:3.12-slim` 而不是 alpine**
项目零第三方依赖，镜像大小基本由解释器决定。alpine 用 musl，`sqlite3` 与 `ssl`
的边界行为和开发机不一致——"本地能跑、容器不行"十有八九出在这里。
多几十 MB 换一致的 glibc 行为，值得。

**2. `HEALTHCHECK` 打 `/api/health`**
这个接口不查库、不要 token，能稳定反映"进程还活着"。健康检查探一个要查库的接口，
数据库一慢就会误判成容器挂了，进而被重启，形成雪崩。

**3. `data/` 挂宿主机目录，不用命名卷**
好处：`data/events.db` 用任意 SQLite 工具直接能看，答辩现场可以当场查库。
代价：不能多机共享。骨架阶段选前者。

### 环境变量

| 变量 | 作用 | 不设会怎样 |
|---|---|---|
| `DASHSCOPE_API_KEY` | 云端识别与合成 | 回落占位实现：识别返回固定句、播报是浏览器机械音 |
| `APP_SCENE` | 选场景（`retail_recall`） | 用 `config/scene.json` |
| `PORT` | 监听端口，同时决定绑 `0.0.0.0` | 本地默认 8000，只绑 127.0.0.1 |

> `PORT` 有两个作用容易被忽略：除了端口，**它存在与否还决定绑定地址**。
> 沙箱里必须监听 `0.0.0.0`，否则外部访问不到；本地则只开本机，更安全。
> 这条规则写在 `app.main()` 的注释里，改之前先读那段。

## 4. 场景配置中心（M8 的另一半）

业务内容全部外置，换场景 = 换文件，代码不动。

```
config/
  scene.json                 默认场景（老路径，所有人的书签和文档都还认它）
  secrets.json               密钥（gitignore，不进仓库）
  scenes/
    service_outbound.json    场景 A：服务类外呼（回访 + 延保权益）
    retail_recall.json       场景 B：会员复购召回（到店礼包）
```

三种选择方式，优先级从高到低：

```bash
APP_CONFIG=/abs/path/xxx.json python app.py     # 1. 任意文件
APP_SCENE=retail_recall python app.py           # 2. 按场景名
python app.py                                   # 3. 默认 config/scene.json
```

运行时也能切（演示用，只允许本机）：

```bash
curl -X POST http://127.0.0.1:8000/api/scene \
     -H "Content-Type: application/json" -d "{\"name\":\"retail_recall\"}"
```

切完**下一轮回复就生效**（话术是每轮现读配置的），已开始的会话不回滚。

### schema 校验：把 KeyError 提前到启动那一眼

```bash
python config_loader.py                 # 校验当前场景
python config_loader.py --list          # 列出所有场景
python config_loader.py --use retail_recall   # 校验指定场景
```

查的是"错了会在运行时炸"或"错了会静默失效"的项：

- 七个阶段（`contracts.STAGES`）是否齐全，每段有没有 `reply` 与 `must_say`；
- **话术里的占位符**是不是 `dialogue.py` 认识的（只支持 `{amount}` / `{status}`）。
  多写一个 `{客户名}` 不会在加载时报错，而是在那句话说出口的一刻抛 `KeyError`——
  这种错在演示时最致命，所以在这里就拦；
- 槽位名重复、缺 `type`；
- `writeback_template` 里有没有业务字段（全是 `_` 开头等于空单据）；
- 预算数字的形制。

默认**只告警不抛错**（骨架阶段宁可少说话也别起不来）；
设 `SC_STRICT_CONFIG=1` 则直接 `ConfigError`，部署与答辩前自检用这个。

## 5. Mock 业务系统

独立服务，不跟通话进程绑在一起——真实企业对接里，这三个接口在业务方机房，
分开做才能换地址、演超时、测鉴权。

```bash
python mock_business/service.py       # 默认 127.0.0.1:8100
```

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/mock/health` | 数据量、工单数、运行时长 |
| GET | `/mock/customer?keyword=8866` | 姓名/手机号后四位/客户号都能查 |
| GET | `/mock/order?customer_id=C1001` | 也可用 `keyword` |
| POST | `/mock/ticket` | 建工单，**必须带 `idempotency_key`** |
| GET | `/mock/tickets` | 列已建工单 |
| GET | `/mock/stats` | 调用计数与错误数 |

三条硬约定：

1. **查不到是 `200 + {"found": false}`，不是 404。** 业务上的"没这个人"是正常
   结果，用 404 表达会让调用方把"没查到"和"接口挂了"混在一起。
2. **建工单必须带 `idempotency_key`。** 同一 key 重复提交返回同一张单
   （`created=false`），不会产生第二张。没带就直接 400——
   回写重试会重复下单，这在业务上是事故，入口就该拦。
3. **参数错是 400 + `{"error","detail"}`**，不静默返回空对象。

细节与联调说明见 `mock_business/README.md`。它对接的是
`contracts.TOOL_SCHEMAS` 里的三个工具签名，2B（潘柏亦）接真实接口时按这个改
`modules/tools.py` 即可，**接口形状不用重新设计**。

## 6. 成本与速率闸门

`cost_guard.py`，三层分开（混在一起就分不清是"贵"还是"忙"）：

| 层 | 位置 | 触发后 |
|---|---|---|
| 单通预算 | `app._budget_reason()`（原有） | 结束本通电话 |
| 日成本上限 | `cost_guard.allow()` | 拒新轮次，HTTP 429 `DAILY_COST_LIMIT` |
| 每会话每分钟轮次 | `cost_guard.allow()` | 拒新轮次，HTTP 429 `RATE_LIMITED` |

配置在 `config/*.json` 的 `budget` 段：

```json
"guard_enabled": false,
"daily_hard_limit_cny": 50.0,
"rate_limit_per_min": 60
```

**默认关闭**。理由写在配置里：骨架阶段硬熔断会让演示莫名其妙失败，
而比赛最怕"演示时突然不能用"。但开关、数字、日志都给了，
需要时改一行配置就能上，不用改代码。

成本口径只有一条：**累加 `turn_end.payload.est_cost_cny`，不另算一份**。
按单价乘用量重算看着更"准"，但只要单价一改，历史账目就跟着变——账不能这么算。
