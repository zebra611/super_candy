# 37 · 两类「闭环了但做错了」的缺陷

## 1. 为什么要单独成码

11-10 复盘 17 通对抗客户，通过率 17/17、系统缺陷会话 0，但逐轮读会话能看见错：

| 现象 | 会话 / 轮次 | 为什么之前抓不到 |
|---|---|---|
| 客户说「我刚不是说了吗，就那几个数」，客服仍回写工单（期望是**不闭环**） | A09/A14（复现 PR #44 原始改动时） | `fault` 只能记成 `unexplained`，没有缺陷码能证实 |
| 客户说「信号不好，你再说一遍」，客服回「这个我这边确认不到，稍后让专员回电」 | A17 第 6、8 轮 | 电话最后还是闭环了，通过率不掉 |
| 客户报完姓名，客服回「核对上了，感谢配合。说联系人姓名也行」，被判"又在要姓名" | A04/A06/A09 第 3 轮 | 性格层句尾后缀里含「姓名」，裸词匹配误伤 |

共同点：**都不会让闭环率掉下来**。闭环率是结果指标，这三是过程错误；
不单独立码，它们就会一直藏在"通过"底下，下次再犯还是靠人眼翻 rows。

## 2. 判据

### 2.1 `agent_premature_close`（误闭环）

```
expect.closed is False 且 closed is True 且 客户最后一轮不是明确同意（confirm）
```

- 收线轮定位：第一个 `next_stage in (WRITEBACK, DONE)` 或 `stage in (WRITEBACK, DONE)` 的轮次。
- `evidence` 写清 `goal`、客户原话、客服"仍回写了工单"。
- **刻意漏判**：客户最后说"清楚了，我按你说的弄"时不记——那可能是画像真被说服了，
  属于用例期望该改，不是客服的错。判据宁可漏，不可冤枉。
- 与 `agent_premature_writeback` 互斥：同一通电话只记一条，不把一件事数两遍。

### 2.2 `agent_repair_ignored`（重说被当提问）

```
user.action == "mishear" 且 客服回复含「确认不到 / 让专员回电 / 稍后让专员」
```

客户要的是"把上一句再讲一遍"，客服去查库或转专员，就是没把这句话当动作。
不看阶段：IDENTITY 阶段答"号码是您预留的"不算（那是在回答），OFFER 阶段答兜底就是错。

### 2.3 槽位假阳

`_RE_ASK["contact_name"]` 原来含裸「姓名」，性格层会在句尾挂「说联系人姓名也行」，
客服原话其实是"核对上了"。收窄为追问句式：`您的姓名 / 怎么称呼 / 怎么叫您 /
您贵姓 / 姓名是 / 报一下姓名 / 确认一下姓名 / 说一下姓名`。

修完性格链 `doctor --deep` 复算：系统缺陷会话 **3 → 1**，缺陷总数 **3 → 1**。

## 3. 听不清的客户：A17

`eval/personas_adversarial.json` 加 `traits.mishear_every`：

- 每 N 轮说一次「啊？信号不好，你再说一遍」，**不看客服表现**——这是客户自己的耳朵问题。
- 与弱点驱动的 `MISHEAR` 分开：那条是"客服把提问当噪声"才触发的惩罚，会计入难度；
  这条不进 `hits`，不影响等级，只考"重说请求能不能被当成重说"。
- 收到「您清楚了吗」那一轮不插，否则客户永远表不了态，用例变死循环。
- `A17`：holdout、`mishear_every=2`、`patience=12`、`expect.closed=true`。

## 4. 修法：先加守卫，再让闭环开开关

`repair.OFFER` 之前是 `false`。11-09 审 PR #44 时实测打开它负面 6→8：客户问
「你哪来的号码」，客服把整段驳回原因再念一遍——复述不是回答。

这次先加两个守卫，再交给 `self_evolve.py` 走四道验收打开：

```python
if (policy.repair_enabled("OFFER") and policy.is_repair_request(text)
        and not (flags.get("no") or flags.get("deny") or flags.get("hangup"))
        and not policy.question_class(text)):
```

1. 明确拒绝/挂断优先：「没听清，不过不要了」要记拒绝，不能拿复述糊过去；
2. 同句带实义提问不抢：「啊？我没听清，那到底要补什么」问的是材料。

验收结果（`run_newcodes`）：

| 轮 | 调整 | 负面 | 正面 | 通过 |
|---|---|---|---|---|
| 0 | 基线 | 8 | 85 | 17/17 |
| 1 | `route.OFFER.provenance` | 6 | 87 | 17/17 |
| 2 | 收敛，无更多可自动调整的簇 | 6 | 87 | 17/17 |

`agent_repair_ignored` 从 2 通降到 0；`agent_premature_close` 保持 0。
剩 6 条只能改代码：`no_answer|NEED`、`slot_loss|IDENTITY`、`repeat|IDENTITY`。

## 5. 收尾冻结

`_reply(next_stage="DONE")` 不再做性格适配。此前最后一句话会是
「…感谢您的配合，再见。我放慢一点说。」——告别语后面挂补救语，
而且这是整通电话客户听到的最后一句。与 PR #44 的 P1 是同一处修复。

对照组仍在：`next_stage="WRITEBACK"` 时 hard_of_hearing 画像会加「我放慢一点说」，
断言两边都钉住。

## 7. 边界

- `agent_premature_close` 依赖用例的 `expect.closed`：画像被说服时它会漏判，
  这是有意的——漏判一条好过冤枉客服一次。
- 真实通话审计（`modules/real_audit.py`）不产生这两个码：那里的用户动作是文本启发出来的，
  没有 `mishear` 这种明确标签；它只看"复读/答非所问/指代含糊"。
- A17 只验收，不据它调话术（holdout 纪律）。
