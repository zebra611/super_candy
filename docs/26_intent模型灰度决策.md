# 26 intent 模型灰度开启决策（S1）

> 结论先写：**不开启，默认保持 `provider=template`（规则版）**。
> 本文只给决策依据与开启闸门，不改配置、不改规则版取值。决策日期 2026-11-06。
> 所有数字来自 `scripts/intent_gray_probe.py` 的可复跑输出，不是估算，也不引用别的模块的旧数字。

---

## 一、为什么现在不开：一句话

成本可以忽略（1000 通电话约 0.22~0.26 元），**延迟不行**：intent 分类 P95 实测 478ms，
而 C7 量出的完整链路 P95 已经是 1114ms、预算 1300ms，只剩 **186ms** 余量。
把模型串在 ASR 之后，P95 会到约 1592ms，直接破预算。降噪、VAD、TTS 都在同一条串行链路里，
没有地方能白拿这 478ms。

清单里「模型改写 401~560ms 已实测」是 11-05 对 **nlg 改写**测的，不是 intent 分类；
两者 prompt 长度、max_tokens、调用位置都不同，拿它当 intent 的延迟预算属于偷换口径，本文不采用。

## 二、三要素之一：延迟预算（实测）

```bash
python scripts/intent_gray_probe.py --rounds 20 --self-test --json data/intent_gray_probe_latest.json
```

| 项 | 实测值 |
|---|---|
| 模型 / 超时 | `qwen-flash` / 生产默认 `timeout_ms=800` |
| 调用次数 | 20 次真实云端调用，**成功 20 / 失败 0** |
| 单次延迟 | min 270.9ms ｜ **P50 336.8ms** ｜ **P95 477.5ms** ｜ max 595.4ms |
| 实测 token | prompt 均值 **196.9** ｜ completion 均值 **15.2** |
| C7 链路基线 | P50 813ms ｜ P95 1114ms ｜ 单轮预算 1300ms（24/24 在预算内） |
| 剩余余量 | 1300 − 1114 = **186ms** |
| 判定 | intent P95 477.5ms **超出余量 2.6 倍** → 串行接入即破预算 |

**这不是"加一点延迟"**：链路预算是按「用户说完到听见第一个字」定的，
intent 分类必须在回复生成之前完成，属于纯串行开销，无法与 TTS 重叠。

## 三、三要素之二：成本估算

单价来源：阿里云百炼公开报价，2026-11-06 查证。
`help.aliyun.com` 模型详情页给「输入 0.15 元 / 百万 token、输出 1.5 元 / 百万 token」；
同站计费规则页给「输入 0.0002 元 / 千 token、输出 0.0015 元 / 千 token」（= 0.20 / 1.50 元每百万）。
**两处输入单价口径不同，故按区间给，最终以控制台账单为准**；不假装精确到小数点后多位。

按实测 token（196.9 in / 15.2 out）与 `eval/seed_cases.json` 实测平均 4.2 轮/通：

| 口径 | 金额（元） |
|---|---|
| 单次 intent 调用 | 0.000052 ~ 0.000062 |
| 单通电话（4.2 轮） | 0.00022 ~ 0.00026 |
| 1000 通电话 | **0.22 ~ 0.26** |

范围声明：只算 intent 分类，**不含** nlg 改写、ASR、TTS、embedding；不含免费额度与阶梯计价变化。
**结论：成本不是阻碍，不需要为省钱关模型；卡住的是延迟。**

## 四、三要素之三：降级路径

`modules/intent.py` 是外挂层，规则版先出完整 flags，模型只在高置信且标签合法时改写主意图。
探针离线验证 **13/13 通过**（`--offline`，不依赖网络/密钥）：

| 编号 | 场景 | 期望 |
|---|---|---|
| D0 | 默认 `provider=template` | 零网络调用，输出与规则版逐字节相同 |
| D1 | 无 API Key | 退回规则版 |
| D2 | 调用超时 | 退回规则版 |
| D3 | 模型输出乱码 / 非 JSON | 退回规则版 |
| D4 | 禁止标签 `handoff` / `deny` / `hangup` / `info` / `other` | 一律退回规则版（5 条） |
| D5 | 置信度 0.31 < 0.70 闸门 | 退回规则版 |
| D6 | 尾号 `digits` | 身份证据不被模型改写 |
| D7 | 密钥读取本身抛异常 | 不外抛，退回规则版 |
| D8 | **反向**：合法高置信标签 | 确实能改写（`evidence=model`），防「模型压根没生效」的假绿 |

**本轮修掉的真缺陷（D7）**：`_ask_model` 以前只把 `urlopen` 包在 try 里，
`config_loader.secret` 读文件失败（secrets 损坏/权限）会把 `OSError` 直接漏到 `dialogue.respond`，
整轮通话崩掉，与模块契约「调用方不需要写 try」不符。现在密钥读取、请求体构造、Request 构造
全部纳入保护，任何异常都退回规则版。

**变异验证 2/2**（`--self-test`）：放开禁止标签 / 放开置信闸门后，对应断言必须变红。
证明 13/13 全绿不是「探针写得太松」。

## 五、开启闸门（必须全部满足，缺一不开）

| 闸门 | 判据 |
|---|---|
| **G1 延迟** | 同口径实测 intent **P95 ≤ 200ms** 且 `timeout_ms ≤ 200`；或改造成异步/预取，与 TTS 并行、不占串行链路。当前 477.5ms 不满足 |
| **G2 降级** | 降级探针 13/13 + 变异 2/2 挂进 `verify` 总闸门；线上 `evidence!=model` 的降级率 > 1% 自动回滚 |
| **G3 收益** | 在**独立留出集**（不是 25 条自拟自证样本）上，闭环率与误闭环率不劣化，且规则版确实漏判的那类说法被救回。没有可证收益就没有开的价值 |
| **G4 灰度** | 按 `session_id` 哈希 ≤ 5% 灰度；每轮 `model_intent` / `evidence` 留痕可审计；`deny`/`hangup`/`handoff`/`digits` 永不交模型（代码已保证） |
| **G5 回滚** | 单行配置 `intent.provider=template` 即回滚，无需改代码、无需重启模型侧 |

**开启后的观察项**：降级率、`evidence=model` 占比、单轮 P95、`run_eval` 88 条闭环率。
任一劣化立即走 G5。

## 六、不做的事（防止把决策写成"已经上线"）

- 不改 `dialogue.classify` 的任何取值——40 多个测试钉在它的具体行为上。
- 不把 `intent_bench.py` 的 25 条自拟口语样本说成泛化准确率（口径见 `docs/21`，T15）。
- 不擅自把 `scene.json` 的 `intent.provider` 切成 `dashscope`。本文是提案，**拍板权在队长**。
- 不因为「成本才两毛六」就忽略延迟：预算是端到端的，不是账单上的。

---

## 七、已知边界

- 20 次调用是单日、单地区、单账号样本，不代表全天网络抖动；P95 会随云端负载变化。
- 成本按公开报价与实测 token 推算，未取账单实付值；报价可能调整。
- 延迟是「intent 分类这一段」的墙钟，不是端到端；串进链路后的真实增量需开灰度后复测。
- 探针 `--offline` 时云端两节明确输出「未测，不写成跑过了」，CI 无密钥也不会假报数据。
