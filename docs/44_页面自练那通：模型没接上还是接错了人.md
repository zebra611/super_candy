# 44 · 页面上那通自练：不是"没接大模型"，是接了、但接错了人

> 触发：用户在自己的页面上（自练对话）打了 13 句，发来截图问
> 「何意味。为什么听不懂我的问题，你真的接入大模型了吗」。

先把结论摆在最前面，因为这一条最难堪：

**模型接上了，而且一直在说话。真正的问题是那通电话从第 5 轮起就在念
另一家商户的档案。**

---

## 一、现场：截图里到底发生了什么

把截图里的 13 句原话抄下来，本地逐句重放，结果一模一样：

```
 3 客：什么
   服：您的号码是商家入驻时预留的联系方式……您报一下手机号后四位。
 4 客：9670
   服：没关系，那方便说一下您的姓名吗？
 5 客：9673
   服：核对上了，感谢配合。梧冈品牌、运动户外类目没有通过审核，
       原因是缺少资质（公章/流水/品牌），需补充境外商标注册证、中文译本……
```

问题在第 5 轮：**电话打给的是"广东省降真百货经营部"（品牌杜若、家居日用、
要补品牌授权书），客服从这一轮开始念的是"梧冈、运动户外、境外商标注册证"。**

不是幻觉，也不是模型编的。查库查出来的：

```python
tools.query_application("9673")   # → 青海省梧丘商贸合伙企业（品牌 梧冈，尾号 9673）
tools.query_application("9403")   # → 广东省降真百货经营部（品牌 杜若，尾号 9403）
```

客户随口报了个 9673（那家商户的真实尾号），`_verify_identity` 拿它去**全库**查，
命中青海梧丘，然后：

```python
session["slots"]["application"] = rec      # ← 把本单档案换成了别人家的
```

之后所有话术里的 `{application_desc}` `{reason}` `{materials}` 全部来自那家。
客户听到的是"它听不懂我"，实质是**把 A 商家的事念给 B 听**。

这一条比"听不懂"严重得多：串单是数据隔离问题，不是话术问题。

---

## 二、修法：外呼单只认本单

外呼单本来就知道自己打给谁，核身只该回答"是不是这一单"，**不该有"查出另一单"这个结果**。

`app.start_call` 增加 `target_locked`（外部显式指定申请单时为 True），
`_verify_identity` 在锁定时走 `_verify_against_outbound`：

1. 只拿本单的尾号 / 单号 / 公司 / 姓名比对；
2. 对不上就清掉这个值、下一轮重问，**不查申请单库**；
3. 确实对不上时**只退回客户库**查一次（售后主场景的"张伟/8866"走这条），
   但绝不把 `slots.application` 换成查出来的记录。

为什么还要留"客户库"这一条：主场景是客户打进来，外呼目标那条申请单和
"接电话的是谁"不是一回事。不留，主场景整通核不上（verify 证据 14 当场红）。
留了也不能查申请单库——那正是串单的入口。

跑批/自练按名单取下一条（`start_call()` 不带单号）时不锁定，维持"报号即身份"
的老语义：C4 那 340 条用例全是这么编的（用例自带台词"尾号4565"）。

## 三、第二层：模型为什么只说了 2 轮

修完串单，把模型开关打开再跑同样的 13 句，模型只说了 2 轮——用户那句
"你真的接入大模型了吗"问得有理。原因有两条，都在规则层：

### 1. `_freeze_identity`：核身轮整轮冻结

```python
_freeze_identity = intent.startswith("identity_") and intent != "identity_ok"
```

当初的理由是指代必须固定（"预留手机号后四位"不能被模型压成"说下后四位数字"）。
代价是一通电话大半轮次都在核身，冻结等于模型从头到尾不说话。

改法：**让模型说，再由内容闸检查它有没有真的问到东西**
（`_content_ok`：必须出现后四位/尾号/姓名/单号之一），说不出来退回骨架。
`_freeze_identity` 只保留给 nlg 那条改写路径——骨架自己那句不许改。

### 2. 必答词门槛：`if must and any(w in base_text for w in must): return None`

`must_say` 是"核对""重新提交""复述"这种业务常用词，几乎每条骨架都有，
于是模型被大面积挡回。这条判据的错在于**用骨架含不含词来决定模型能不能说话**。

正确做法是反过来：让模型说，再检查它说的这句有没有这件事。这就是 `_content_ok`
（自报身份 / 核身问句 / 驳回原因 / 材料 / 确认 五个语义要素）。

改完同一通：模型 10 轮 / 骨架 3 轮（其中 2 轮是模型自己的输出被闸门拦下）。

## 四、模型自己暴露的三个毛病

放开之后立刻现形，都是"更像人但更危险"的那种：

| 现象 | 例子 | 处理 |
|---|---|---|
| 无中生有的确认 | 客户还没报号，客服说「您预留的手机号后四位是9403，对上了」 | `_leaks_secret`：核身未通过时，档案里的尾号/单号**一个字都不许出现**（念出来等于自己把门打开） |
| 嘴漏 | 「申请单号后六位是060019」 | 同上 |
| 跨轮复读 | 第 11 轮和第 13 轮逐字相同 | 去重闸原来读 `session["memory"]["recent"]`，而 `/api/turn` 这条链路根本没维护 memory，常年空转 → 改成模型自己维护 `agent_free_recent` |

另外两个"看着像判据、其实是挑词"的地方：

- `_same_intent`：从骨架挑业务动词，要求输出命中同一个。骨架说「我按公司名核一遍，
  一样能确认是您这单」，模型说「我核一下是不是您这单」——意思一样，动词不同，被丢。
  换成 2 字词重合度（`_same_topic`，门槛 0.15）。
- 事实闸不认客户刚说的数字：客户说 9670，客服纠正"您说的9670和预留的对不上"，
  被判"编造数字"。把 `user_text` 也算进事实来源。

## 五、还有三处骨架自己在犯的错

1. **骨架复读**：同一个状态连着两轮查同一句话，逐字播两遍
   （截图里「您可以简单回我一句清楚了或者还有疑问就行」说了两次）。
   模型层有去重，骨架没有 → `_skeleton_variant`，只换开头（"我刚才可能没说清楚，"
   / "换个说法，" / "我再说一遍，"），内容一个字不动。
2. **「怎么补」答不上来**：这是 OFFER 环节唯一该答的事，答案就写在档案的
   `reject_reason` / `required_materials` 里，却落到 `reply_unknown`
   （"这个我这边确认不到，稍后让专员给您回电"）→ 新分支直接给
   驳回原因 + 要补哪几样 + 后台重新提交。
3. **尾巴自相矛盾**：核身问句「…预留手机号的后四位，说四个数字就行。」
   后面挂一句「您回一个字也行。」——刚让对方报四位数字。判据原来只认问号，
   祈使式问句没有问号。补 `_SKIP_SUFFIX_MARKS`（后四位/尾号/姓名/单号/公司名/全名…），
   两种尾巴（suffix 与 avoid_repeat）都拦。
   **不含"再见"**：真正的收尾轮由 `_persona_freeze` 整轮冻结，而 WRITEBACK
   这类"说到再见但不是最后一句"的轮次仍需要追加引导语（test_scene_isolation 的对照组）。

## 六、核身不许无限绕

截图那通还有一条：客户报错两次号之后，连着八轮"哎妈呀/弄不明白/那歇歇"，
系统一直停在 IDENTITY 反复要尾号，直到轮次预算用完。

`_IDENTITY_MAX_TURNS = 8`：超过就如实收尾（`end_reason=identity_failed`），
给官方客服号，**不写工单**——身份都没核上，写出去的业务结论没有意义。

## 七、回归与变异

`scripts/test_train_replay.py` 从 24 条加到 **29 条**，新增 5 条都测**接线**不只测判据：

| 断言 | 变异靶子 |
|---|---|
| 客户报别家尾号：不核过、不念别人家原因 | 去掉 `target_locked` 分支 → 红 |
| 核身未通过时不许念档案尾号/单号 | 删 `_gates` 里那句 `_leaks_secret` → 红 |

**这一轮又踩了三次"绿了但没测到"**，全部记在用例注释里：

## 七之二、线上复跑又揪出两处（都是话术本身坏了）

修完发布，用同一单跑两通对照：**报错号**（9673）与**报对号**（9403）。

**① 报错号那通**：11 轮，`梧冈/运动户外/境外商标/确认不到/回一个字也行` 全 0，
第 11 轮如实收线（`identity_failed`，给了官方客服号），不再空转到轮次预算用完。

**② 报对号那通**：`尾号9403，对上了` → 讲清驳回原因与三样材料 → 客户问"怎么补"
直接给材料和后台入口 → 客户说"后台页面打不开"给换浏览器的办法 → 复述 → 待确认。
逻辑通了，但暴露出两处纯话术问题：

1. **复述句语序错**：
   `…您这笔申请是因为授权书公章与品牌持有人名称不一致，需重新出具没有通过审核…`
   ——模板把 `{reason}` 嵌在"因为…没有通过审核"中间，而这条档案的驳回原因
   本身以"需重新出具"结尾，接上"没有通过审核"就成了病句。
   改成"您这笔申请没有通过审核，原因是{reason}，需要补充{materials}…"——
   无论原因怎么写都通顺。
2. **「你不是知道吗」在 NEED/OFFER 无人接**：元话语判据原本只接在 CONFIRM，
   NEED/OFFER 落到 `reply_unknown`，回的是「您说的这个我确认不到，稍后让专员
   给您回电」——客户在说"你在问废话"，客服答"我不知道"，是最刺人的一种答错。
   词表补 `你不是知道/你不知道吗/还用问`，`_meta_repeat_reply` 加 `stay`
   参数（NEED/OFFER 认账时不能顺手把阶段推到 CONFIRM——事还没讲完）。
   现在回「是我刚才没接住，抱歉。您说的我记下了，不重复问了。」+ 复述材料与入口。
3. **整段解释后面还在讨回应**：60 多字的解释末尾挂「您回一个字也行。」，
   像求人回话。判据一开始想用长度，**两版都不对**：40 字漏掉 37 字那句；
   改成 30 字又会把 verify 里那条 31 字的"该加后缀"对照组一起拦掉。
   最后改成看**内容**：句子里已经有本单事实（驳回/材料/授权书/后台/清单/
   浏览器）就不再挂引导。判据挑长度是又一次"挑表面特征"，挑内容才对。

## 九、这一轮真正学到的东西

1. **"听不懂"往往不是理解问题，是数据问题。** 客服把另一家商户的档案当成这一单，
   说什么都像听不懂。先查"它在说谁的事"，再查"它说得自不自然"。
2. **"接了大模型"和"大模型在说话"是两件事。** 一条 `_freeze_identity` 加上一条
   错误的必答词门槛，就能让模型在 13 轮里只说 2 轮，而所有汇总指标照旧全绿。
   所以 `_reply` 现在记 `reply_source`，`agent_free` 记 `agent_free_reject` +
   `agent_free_raw`——"这句谁说的、模型说了什么、被哪道闸拦的"必须能事后回答。
3. **判据挑词，不是判语义。** `_same_intent` 要求命中同一个动词、
   `must_say` 要求逐字出现"复述"、尾巴守卫只认问号——三处都是同一类错。
   换成词重合度、语义要素、祈使句判据之后，同一批用例才既绿又真。
