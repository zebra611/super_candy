
它覆盖的是**已经踩过坑的那些行为**，每条都给出实际数据：

| 证据 | 断言什么 |

| 5 | 第一次含糊只追问不回写；第二次仍含糊才记 `unknown` |
| 6 | 同意后工单结论为 true；改口后重写一次、**同一张工单**、`updated=true` |
| 7 | 禁语命中整句替换，播报文本里既没有禁语也没有 `***` |
| 8 | 必说话术检查不再是 `skipped`；五项合规检查都有结论；未闭环会扣分 |

## E. 查质检报告

本机可以直接看（`/api/sessions` 只允许本机访问）：

```bash
# 先拿到 session_id 和 read_token，再查
curl "http://127.0.0.1:8000/api/report?session_id=<sid>&token=<token>"
```

返回三块：`transcript`（转写）、`compliance`（逐项合规结论）、`score`（0–1）。
`compliance.checks` 里每一项都带 `status`（pass / fail / skipped）与命中明细——
**skipped 是"没检测"，不是"通过了"**，看报告时别混。

## F. 另外三个工具脚本（针对具体问题）

| 脚本 | 什么时候用 | 会不会花钱/动数据 |
|---|---|---|
| `python scripts/bench_voice.py` | 要报 P50/P95 时。跑 30 轮真实云端调用，出分位数 | **花钱**（约 3 分钟真实调用）；写临时库，不动 `data/events.db` |
| `python scripts/clean_events.py` | 觉得库里数据不对、或面板指标看着好得离谱时 | 默认只预览；`--yes` 才删，且先自动备份到 `data/backup/` |
| `python scripts/check_key.py` | 怀疑密钥有问题（401/403/欠费） | 不花钱，只做一次最小请求 |

**`clean_events.py` 为什么存在**

跑批脚本曾经直接写生产库，305 个会话里 300 个是测试产物。后果不是"数据脏"这么轻，
而是**指标变成假的**：测试用例的识别耗时是 0ms，混进分位数会把首字 P50 拉到几十毫秒。
现在跑批已经改用临时库，这个脚本是善后工具，也是事后复核的手电筒——
它会按"识别耗时是否大于 0"把真人通话和跑批产物分开，并列出每通真人通话说了什么。

**bench 的结论怎么用**

只能报服务端口径（`server_first_audio_ms`）。浏览器口径的 `first_audio_ms`
必须真人戴耳机实测后由前端上报，两者差了 100–250ms。
拿服务端的数当"首字响应"汇报，就是虚报。
