# 怎么确认「到底改了什么」

> **不要看总结，看原始输出。**
> 文档和口头汇报都可能滞后或说错。**代码、事件链、git 记录这三样是硬的，其余都是软的。**

---

## A. 双击 `验证.bat`（最省事）

它会自动找 Python，跑 `scripts/verify.py`，逐条打印**实际事件链与 payload**，最后给 `N/N 通过`。
看到 FAIL 就是有问题，以这个输出为准。

---

## B. 命令行

```bash
python scripts/verify.py       # 22 条断言，用临时库，不污染 data/
```

它覆盖的是**已经踩过坑的那些行为**，每条都给出实际数据：

| 证据 | 断言什么 |
|---|---|
| 2 | 契约里有 `no_answer` / `latency_report` / `error` |
| 3 | 文字轮不写 `vad_result`、`source=text`、`fake=false`、尾号在入库文本里被打码 |
| 4 | 沉默写 `no_answer`、不写 `asr_result`、不推进状态机、连续两次才挂断 |
| 5 | 第一次含糊只追问不回写；第二次仍含糊才记 `unknown` |
| 6 | 同意后工单结论为 true；改口后重写一次、**同一张工单**、`updated=true` |
| 7 | 禁语命中整句替换，播报文本里既没有禁语也没有 `***` |
| 8 | 必说话术检查不再是 `skipped`；五项合规检查都有结论；未闭环会扣分 |
| 9 | 语音轮 `fake=true`；首字口径由浏览器上报，与服务端处理耗时分列 |
| 10 | 错 token 被拒；同一会话并发第二轮被挡 |
| 11 | 超过轮次上限会写 `error` 并礼貌收尾 |

**它证明不了什么**（脚本末尾也会自己说）：真 ASR/TTS、流式与打断、语义级合规、模拟用户跑批。
这四块仍是占位。

## D. 在页面上亲手点

打开 `启动.bat` → 点「开始通话」→ 依次试这几条：

| 操作 | 应该看到 |
|---|---|
| 一开始 | 客服先说话（开场自报身份），事件链里有 `agent_reply`（turn 0） |
| 报尾号"8866" | 直接核验通过进 NEED，不再重复问姓名 |
| 输入框留空点发送 | 事件链出现 `no_answer`，**没有** `asr_result`，客服说"您还在吗" |
| 走到 CONFIRM 说"嗯……" | 客服追问"您可以简单回我一句同意或者不需要"，不挂断 |
| 闭环后说"等等，我不要了" | 事件链出现第二条 `writeback`（version=2），同一 ticket_id |

任何一条与上表不符，**那就是代码和文档不一致**，把截图或事件链贴出来，以实际输出为准。

## E. 查质检报告

本机可以直接看（`/api/sessions` 只允许本机访问）：

```bash
# 先拿到 session_id 和 read_token，再查
curl "http://127.0.0.1:8000/api/report?session_id=<sid>&token=<token>"
```

返回三块：`transcript`（转写）、`compliance`（逐项合规结论）、`score`（0–1）。
`compliance.checks` 里每一项都带 `status`（pass / fail / skipped）与命中明细——
**skipped 是"没检测"，不是"通过了"**，看报告时别混。
