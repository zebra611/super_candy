# 24 评测指标口径定义（角色 3 定标准）

> 背景：任务清单 T17 要四项指标，其中「任务闭环完成率」和「回写合规率」的分母口径由 3 号定。
> 本文只定义口径，不实现采集；采集在 `scripts/run_eval.py` 与 `scripts/task2_metrics.py`。
> 一句话原则：**分母要回答"该发生的有没发生"，不能把"本来就不该发生"算成失败。**

---

## 一、任务闭环完成率（双指标）

### 定义

| 指标 | 分子 | 分母 | 当前值（30 条种子） |
|---|---|---|---|
| **应闭环达成率** | `expect.closed=true` 且事件流里出现 `writeback` 的用例数 | `expect.closed=true` 的用例数 | **11/11 = 100%** |
| **误闭环率** | `expect.closed=false` 但出现了 `writeback` 的用例数 | `expect.closed=false` 的用例数 | **0/14** |

`expect` 里没写 `closed` 的 5 条不参与统计，报告里单列"未声明 5 条不计入"，不允许悄悄算成 0 或算成通过。

### 为什么不用"闭环数 / 全部用例数"

30 条种子里有 14 条**按设计就不该闭环**：用户明确拒绝（R01–R04）、身份核验失败（M01）、沉默挂机（M05）、诱导询问（I01–I04）等。把它们放进分母，会得到 `11/30 = 37%`，读起来像"系统有六成业务没做完"，而实际是"该闭环的全闭合了，不该闭环的一条没乱闭"。

这个数字一旦写进答辩材料，评委会当场问"37% 是怎么算的"，很难解释。所以口径必须换成双指标。

### 复现

```bash
python3 scripts/run_eval.py      # 输出最后三行里的「闭环率：应闭环 11/11 = 100%｜误闭环 0/14｜未声明 5 条不计入」
```

## 二、回写合规率

### 定义（主口径：按回写次数）

| 项 | 内容 |
|---|---|
| 指标名 | 回写格式合规率（writeback compliance rate） |
| **分子** | 通过校验的 `create_ticket` 调用次数 |
| **分母（主）** | `create_ticket` 调用总次数 |
| **分母（辅）** | 发生过 `create_ticket` 的会话数（一个会话的**所有**回写都合规，才计为 1） |
| 当前值 | **主口径 13/13 = 100%**；**辅口径 11/11 = 100%** |

### 校验什么（分子判据）

以 `config_loader.writeback_schema()` 的 `required` 为准，不在脚本里写死字段名：

1. 必填字段齐全：当前是 `call_result / identity_confirmed / need / consent / agent_version`；等 4 号把 `customer_id` 加进 `required` 后，这里**自动**纳入，不用改代码；
2. 类型正确：`identity_confirmed` 必须是 `bool`，`writeback_version` 必须是正整数；
3. 值域合法：`consent ∈ {true, false, "unknown"}`，`"unknown"` 是合法值不是缺失；
4. 校验器统一用 `tools.validate_writeback()`（PR #14 已实现），脚本不另写一份判定。

### 排除项

- **没有触发回写的会话不进分母**：拒绝、挂断、身份核验失败、沉默挂机的会话根本没有 `create_ticket`，把它们算进去等于把"没发生"记成"不合格"。
- **被合规护栏拦掉、整通电话没有回写的会话**同理排除。

### 为什么主口径按"回写次数"而不是"会话数"

实测数据：30 条用例共 **13 次** `create_ticket`，分布在 **11 个**会话里——`C01`（回写后反悔）和 `C02`（拒绝后改主意）各写了两次，第二次是 `writeback_version=2` 的更正。

用会话数当分母，这两次更正会被压成一条，掩盖"第二次写错"的问题；而企业侧的真实风险恰恰来自第二次：**工单已经建了，更正写错就是把错数据留在业务系统里**。所以主口径按次数，会话数作为辅助口径一起报，两个数都给，避免被问"是不是挑了好看的那个"。

### 复现

```bash
python3 scripts/task2_metrics.py    # ④ 回写格式合规率：13/13 = 100.0%
```

## 三、四条口径之间的边界（避免重复计分）

| 指标 | 回答的问题 | 不回答什么 |
|---|---|---|
| 意图/字段覆盖率 | 事件字段有没有写全 | 不代表判得对 |
| 槽位完整率 | 该收集的信息有没有收到 | 不代表用户同意 |
| 闭环完成率（双指标） | 该闭合的业务有没有闭合 | 不代表回写内容合法 |
| 回写合规率 | 写进业务系统的内容合不合法 | 不代表用户满意 |

**四个数不能相互替代**：闭环率 100% 但回写合规率 0 是完全可能的（工单建出来了、字段全是空的）。答辩时四个一起给，才构成"业务结果可信"的证据链。
