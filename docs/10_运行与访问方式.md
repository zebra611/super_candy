# 运行与访问方式

> 三种跑法，按场景选。**不要双击 `web/index.html`**——原因见本文第 4 节。
> 本文只讲"怎么把它跑起来"，设计取舍见 `docs/01_架构与分工设计.md`。

---

## 1. 本地双击（自己调试，最快）

双击项目根目录的 **`启动.bat`**，它会自动找 Python、起服务、打开浏览器。
关掉那个黑窗口就是停止服务。

等价的手动写法：

```bash
cd super_candy
python app.py            # 默认 http://127.0.0.1:8000
python app.py 9000       # 换端口
```

不需要装任何第三方包，Python 3.9 以上即可。

> **为什么要有 `启动.bat`**：有些机器 PATH 里的 `python` 是微软商店的假快捷方式，
> 敲 `python app.py` 只会弹"去商店安装"。启动器会逐个试候选解释器，
> 用一次真实的 `import` 判断哪个能用，再拿它起服务。

## 2. 在浏览器里跑（给队友 / 换设备 / 对方零安装）

用 GitHub Codespaces，在一台云端的 VS Code 里跑：

1. 仓库页 → 绿色 **Code** 按钮 → **Codespaces** 标签 → **Create codespace on main**
2. 等 1 分钟左右，浏览器里打开一个 VS Code，底部终端敲 `python app.py`
3. **关键一步**：右侧 **PORTS** 面板 → 找到 8000 端口 → 右键 → **Port Visibility** → **Public**
   不做这步，链接只有你自己能打开，别人访问会被跳到 GitHub 登录页
4. 点 8000 端口那行的地球图标，得到形如 `https://xxxx-8000.app.github.dev/` 的地址

> 两个限制：① codespace 停止或空闲超时（默认 30 分钟）后链接失效；
> ② 地址里的随机串换一次 codespace 就换一个。
> 不用时记得去 Codespaces 页面停掉实例，否则一直耗免费额度。

## 3. 固定公网链接（发给老师 / 评委 / 写进方案书）

**https://voice-agent-skeleton.app.workbuddy.host/?sharecode=ACYOJRLVUP**

任何人、任何设备、任何网络点开就能用，不用登录、不用装 Python、不用启动任何东西。

**为什么这个地址是永久固定的**

链接绑定的是「发布出去的这个应用」，不是某一次上传的文件。所以：

- 改代码、加模块、换话术 → **重新发布一次，链接不变**，只是背后的内容被换成新版
- 换电脑、换网络、关掉 codespace → 链接照样能打开
- 地址里的 `voice-agent-skeleton` 是应用标识，`sharecode` 是访问凭证，两者都不随代码改动变化

**怎么更新线上内容**：改完代码后，对 `super_candy` 这个目录再执行一次发布。
它认出是同一个目录 → 同一个应用 → 覆盖更新，链接保持不变。

**三个必须知道的限制**

1. **它是公开的。** 任何拿到链接的人都能访问。现在全是假数据没问题；
   一旦接入真实 Mock 接口、真实话术、真实名单，就应该先下线。
2. **数据不持久。** 沙箱只有一个 HTTP 端口和临时文件系统，`data/events.db` 会在每次
   重新发布后清空。所以「闭环通话数」「P50」每次都从 0 开始——演示够用，长期跑分要用本地。
3. **端口由平台注入。** 线上运行时 `app.py` 检测到 `PORT` 就绑 `0.0.0.0` 并跳过自动开浏览器；
   本地则绑 `127.0.0.1` 且自动开浏览器。同一份代码，两种模式。

**要下线**：在 WorkBuddy 的「设置—数据管理—应用」里取消发布，链接立刻失效。

## 4. 关于 `web/index.html`

**不要双击它。** 它是一个需要后端才能工作的页面：

- 双击会变成 `file://` 打开，页面上所有 `/api/*` 调用全部失败；
- 在 GitHub 上点开它，看到的是源码（GitHub 只展示文件内容，不渲染）。

这两种情况都不是出错。**正确入口永远是 `http://127.0.0.1:8000`。**

## 5. 页面上怎么操作

点「开始通话」——客服会先说开场白（外呼是客服先开口）。

然后两种输入方式：

- **有麦克风**：点「按下说话」→ 说一句 → 再点一次「停止并发送」
- **没麦克风**：在下面输入框打字，点「发送」
- **想测"用户不说话"**：输入框留空直接点「发送」

每说一轮，状态机按意图往前走：`GREETING → IDENTITY → NEED → OFFER → CONFIRM → WRITEBACK → DONE`。
走到回写那一轮会真的调用一次 `create_ticket`，右下角事件链里出现 `writeback` ——**这就是"闭环"的硬证据**。

面板上四个数字的含义：

| 显示 | 含义 |
|---|---|
| 本轮首字响应（T4−T0） | 浏览器实测：你点发送/说完 → 听到第一声。**这才是门槛口径** |
| 本轮处理耗时（服务端） | 服务器从收到请求到回复就绪。通常十几毫秒，**不是**用户等待时间 |
| 首字 P50 / P95（语音轮） | 只统计语音轮的聚合值；没有语音样本时显示"暂无" |
| 闭环通话数 | 有多少通电话真的完成了结构化回写 |

## 6. 三种方式怎么选

| 场景 | 用哪个 |
|---|---|
| 自己调试、改代码看效果 | 本地双击（改完刷新即生效，不用重新发布） |
| 队友临时看一眼、或换台电脑 | Codespaces 或直接给固定链接 |
| 发给老师、评委、写进方案书 | 固定公网链接 |

---

## 7. 安全边界（接真数据前必读）

- 每通电话有独立的 `read_token`，没有它即使拿到 `session_id` 也读不到事件链与质检报告；
- 入库的识别文本里，连续 4 位以上数字被打码（手机尾号不落库，对话逻辑仍用原文）；
- `/api/sessions` 只允许本机访问；
- `/api/metrics` 是匿名可读的，但它只含分位数与计数，不含任何个人信息。

**但公开链接本身仍是公开的**：接真实名单前必须下线，或改成需要登录的部署方式。
