# 团队使用规范（两条硬规矩）

> 这两条不是建议，是每次开工都要走的流程。
> 团队协作的提交/PR 细则在 `CONTRIBUTING.md`；本文只管"开写之前"和"收工之前"。

---

## 规矩一：写代码前，先确认"提示内容"有没有更新

这里的"提示内容"指**契约与约定**，不是聊天记录：
`docs/02_状态机定义.md`、`docs/03_事件契约.md`、`docs/04_时延打点规范.md`、
`contracts.py`、`config/scene.json`。

每次让 AI 开始写之前，先花 30 秒确认三件事：

```bash
git pull origin main                                        # ① 有没有人推了新东西
git log --oneline -5 -- docs/ contracts.py app.py            # ② 契约和骨架最近改过没有
```

③ 打开上面三份文档，看开头那行"状态：v1 草案 / 已冻结"，确认它还是你以为的那一版。

**为什么必须有这一条**：契约一改，照着旧版写出来的代码就是白写，而且往往到合并时才发现，
返工成本最高。所以"确认没变化"也是一项工作——叫确认基线一致，不能说"我觉得应该没变"。

**开工前要先报三句话**，确认无误再动手：

1. 这次要改哪些文件；
2. 依据哪几份契约、哪一版；
3. 会不会碰禁改区（`contracts.py`、别人的文件）。

---

## 规矩二：写完就清理，不留"以防万一"的代码

判据只有一句：**"绝对不再需要" = 没人会再读它，也没人会再跑它。**

**必须删**：

- 一次性验证脚本与临时文件（`_t.bat`、`_t.log`、`probe_*.py`、`tmp_*.py`）
- `data/`、`__pycache__/`、`*.pyc`（`.gitignore` 已挡，但确认没被提交）
- 注释掉的大段旧代码，包括写着"先留着"的那些
- 调试用的 `print`、`TODO 临时`、被注释掉的入口
- 已经被替换掉的旧实现（旧函数、旧配置分支）——旧版本在 git 历史里永远找得到，
  仓库里留一份只会让人分不清哪个是现行代码
- 0 字节占位文件、空目录

**不要删**：

- `docs/` 下的设计文档——那是资产，不是垃圾
- 明确还会用到的东西（如 `eval/seed_cases.json`）——没用上 ≠ 不再需要

**清理不是删完就完了，删完必须跑一遍**：

```bash
python app.py                    # 能起来
python scripts/verify.py         # 行为断言全过
python scripts/run_eval.py       # 评测能跑完、分数没掉
```

跑不过说明删错了，`git checkout -- <文件>` 能找回来，不用怕。

**提交前 6 项清理自检**：

- [ ] 临时脚本、日志、探针已删
- [ ] `git status` 里没有 `data/`、`__pycache__`、`*.pyc`、音频、`.env`
- [ ] 没有注释掉的死代码
- [ ] 没有遗留调试 `print`
- [ ] 被替换的旧实现已删干净，不留"旧版备用"
- [ ] 删完之后服务能起来、自检与评测都没掉

---

## 附：一句话记住这两条

**开工前对齐基线，收工后清干净。** 其余都可以商量，这两条不行——它们分别对应
"白写两周"和"没人敢改"这两种最贵的后果。
