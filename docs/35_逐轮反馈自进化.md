# 35 · 逐轮反馈自进化（多轮闭环）

## 1. 它解决什么问题

11-08 的对抗链已经能「跑一批 → 聚失败簇 → 改话术 → 闸门」，但只跑一轮，
而且只能改**话术**。11-09 逐轮拆开 16 通对抗客户后发现，重复最多的负面反馈
不是措辞不好，而是**分支选错**：

| 现象 | 会话 / 轮次 | 错误分支 |
|---|---|---|
| 客户说「信号不好，你再说一遍」，客服回「这个我这边确认不到」 | A01 第 4~7 轮 | 把修复请求当成「答不上来的问题」 |
| 确认环节被问「具体要补什么材料」，客服回「确认不到」，第二次收线 | A03/A06/A10/A14/A15 | 手里有本单材料清单，却走了「查不到」分支 |
| 复述时把「授权链路不完整」降成「材料问题」 | A01/A02/A03/A04/A06/A10/A13/A14 | 复述用了通用句，丢了具体原因 |
| 开场客户答非所问，客服连续 3~4 轮逐字重复「您是XX公司的负责人吗」 | A07/A09 | 公司确认只有一句问法 |

这些都改话术改不动：话术没毛病，走错了门。

## 2. 三层结构

### 2.1 逐轮反馈 `modules/feedback.py`

给**每一句客服回复**一个判定：`+` / `−` / `0`，附 `codes`、`why`、`evidence`、`target`。

- 负面码：`repeat`（与上一句实质相同，整句相似度 ≥0.90）、`no_answer`
  （客户在问，回复里没有该类的正面信息）、`generic_summary`（前面讲过具体原因，
  这一句只剩「材料问题」）、`slot_loss`（刚给的事实又被要一遍）、
  `noise_on_question`、`placeholder`、`stalled`。
- 正面码只认三件事：`answered`（正面回答）、`fact_acked`（接住事实）、
  `advanced`（推进阶段且 `must_say` 齐全）。**没扣分不算好**，所以有大量 `0`。
- 合规性延迟回答（「这个我得先核对身份才能讲」）记为 `deferred` 而不是
  `no_answer`——把「不能答」和「没答」混为一谈，会逼优化器去泄露未核验信息。

不用 `turns[i].user.found`：对抗器把弱点命中挂在**下一轮用户动作**上（它是在
看到客服上一句之后才观察的），直接拿来当第 i 轮的问题会整体错一拍。
本模块全部从 `turns[i].agent.reply_text` 与上一句自己比。

### 2.2 可学习面 `modules/policy.py`

白名单，只有四个键：

```json
"evolution_policy": {
  "repair": {"OFFER": false, "CONFIRM": false},
  "answer_routes": {"CONFIRM": {"fee": "reply_ask_fee",
                                "material": "reply_application_answer"}},
  "confirm_specific": true,
  "greeting_company_alt": true
}
```

- 默认全关 = 加这层之前的行为逐字节不变（226 条 verify 不会因「多了一层」漂移）。
- 路由值必须是 `reply_` 开头的话术键：优化器能改「说什么」，不能改 `must_say`。
- 代码只提供一次查表与填槽，不预置任何一条路线；路线由反馈学出来。

### 2.3 闭环 `scripts/self_evolve.py`

```
python scripts/self_evolve.py run [--rounds 6] [--ids A01,A04]
python scripts/self_evolve.py report [run_id]
python scripts/self_evolve.py check
python scripts/self_evolve.py promote <run_id> --yes
```

每轮：评当前配置 → 逐轮反馈 → 按可学习目标聚簇 → 挑条数最多且没试过的一簇 →
改一处 → **子进程复跑同一批客户** → 四道验收 → 采纳或退回。

四道验收（任一不过即退回，配置不动）：

1. 目标缺陷码条数下降（不是总分好看，是指名道姓那条少了）；
2. 负面反馈总量下降；
3. 通过数与 holdout 不降；
4. 没有任何一通电话从「零负面」变成「有负面」（不许拆东墙补西墙）。

**一轮只改一处**：改两处再复跑，收益只能算在「这两处」头上，分不清就无法
在下一轮继续，无效的那处会一直占着开关。

## 3. 日志与追溯

目录 `eval/reports/self_evolve/<run_id>/`：

| 文件 | 内容 |
|---|---|
| `training_log.md` | 总账表 + 每轮：开始/结束指标、反馈构成、改了哪一处、五条判据逐条结果、退回原因、只能改代码的缺陷 |
| `feedback.jsonl` | 每一轮、每一句话：极性、缺陷码、理由、证据原话、可学习目标、对应决定 |
| `round_XX.json` | 该轮完整快照（簇、示例、尝试、判据、前后配置 sha） |
| `run.json` | 运行元数据、采纳/退回清单、学到的策略、起止指标 |
| `final.scene.json` | 末轮完整配置（可直接复跑） |

`index.jsonl` 是一行一次运行的索引（同 `run_id` 重跑会覆盖旧行，不留两条
时间不同、指标相同的记录）。网页「自进化训练日志」卡片读
`/api/evolve/runs`、`/api/evolve/run?id=`、`POST /api/evolve/train`。

## 5. 边界（必须写清）

- **不能改代码**：剩下 6 条负面反馈只能改 `dialogue.py`（NEED 第二遍追问、
  IDENTITY 槽位轮换后缀、IDENTITY 重复追问）。判据没把它们映射到配置，
  闭环就不碰，只列进日志的「只能改代码」一节。改代码必须重定基线，
  否则前后分数不可比。
- **判据与画像不在可学习面内**：闭环不给自己改考卷。
- **promote 永远人工**：`--yes` 才会写两份线上配置，写前留 `.bak_<run>`，
  写后重跑基线。不提供自动上线。
- **模拟评测 ≠ 真人语音水平**：这里测的是文字链路的分支与话术；语音识别、
  打断、时延是另外几条线，见 docs/32、docs/33。
