## 1. 接口

所有接口都是 JSON。**除 `/`、`/api/health`、`/api/metrics` 外，都需要这通电话的 `read_token`。**

例外只有一个：`/api/audio/chunk` 的请求体是**二进制 PCM**，不是 JSON。

| 方法 | 路径 | 说明 | 需要 token |
|---|---|---|---|
| POST | `/api/call/start` | 开一通电话。返回 `session_id`、`read_token`、`opening`（开场白文本）与 `opening_tts`（它的合成结果，含 `audio_url`） | 否 |
| POST | `/api/audio/chunk?session_id=&token=&seq=&rate=16000` | **S1 新增**：上传一片音频，体为 PCM16LE 原始字节。`seq` 是这片第一帧的序号 | 是 |
| POST | `/api/turn` | 一轮对话。体 `{session_id, token, audio_streamed:true, audio_dropped?}`（音频已分片传完）或 `{session_id, token, text}`（打字） | 是 |
| POST | `/api/turn/metric` | 前端上报首字响应。体 `{session_id, token, turn_id, first_audio_ms, estimate}` | 是 |
| GET | `/api/tts/rest?session_id=&token=&turn_id=` | **分段合成的剩余音频**。首段在 `/api/turn` 的响应里，播完后调这个取剩下的（最多等 3 秒） | 是 |
| POST | `/api/call/barge_in` | **用户打断**。体 `{session_id, token, turn_id, reason, text}`。写 `barge_in` 事件（payload 带 `heard`）+ 丢弃该轮未播音频 + 清空音频缓冲 | 是 |
| POST | `/api/asr/probe` | **插话探针**。原始 PCM 走体，query 带 `session_id`/`token`。只识别，返回 `{text, has_content, asr_ms}`；不写事件、不推进状态机 | 是 |
| POST | `/api/audio/reset` | 丢弃缓冲里堆着的音频（播报结束后调，防止回声被下一轮识别） | 是 |
| POST | `/api/call/end` | 挂断。体 `{session_id, token}` | 是 |
| GET | `/api/events?session_id=&token=` | 这通电话的事件链 | 是 |
| GET | `/api/report?session_id=&token=` | 转写 + 质检 + 打分（角色 3 的入口） | 是 |
| GET | `/api/metrics` | 全局指标：双口径时延、闭环数、估算成本 | 否（只含聚合值） |
| GET | `/api/sessions` | 最近会话列表 | 仅限本机 |
| GET | `/api/health` | 存活检查（含首字门槛值） | 否 |

**音频流的约定**（S1 定稿，细节见 `contracts.py` 的 PCM 常量）：

- 格式固定 **PCM16LE / 16kHz / 单声道**，每帧 20ms = 320 采样 = 640 字节；
- 前端每 8 帧（160ms）发一片，`seq` 用这片第一帧的序号，从 0 递增；
- 服务端按 `seq` 校验连续性：跳号记 `gaps`，倒退的片丢弃并记 `duplicates`；
- 一轮结束时 `/api/turn` 带 `audio_streamed:true`，服务端把缓冲整段交给 ASR 并清空。

**错误码**（都是结构化 JSON，`{"error": "...", "detail": "..."}`）：

| HTTP | error | 含义 |
|---|---|---|
| 400 | `UNKNOWN_SESSION` | 会话不存在（已挂断、或 ID 写错） |
| 400 | `BAD_JSON` / `BAD_AUDIO` / `BAD_METRIC` / `BAD_CHUNK` | 请求体或参数不合法（`BAD_CHUNK` 含采样率不符、奇数字节、空分片） |
| 403 | `FORBIDDEN` | 缺少或错误的 token |
| 409 | `SESSION_BUSY` | 同一会话上一轮还没处理完 |
| 413 | `PAYLOAD_TOO_LARGE` / `AUDIO_TOO_LARGE` | 请求体或音频超过上限（单轮累计 8 MB） |
| 500 | `TURN_FAILED` | 处理这一轮时出了未预期异常 |

## 3. 现在还是假的（刻意留的，不是 bug）

| # | 假在哪 | 影响 | 谁负责替换 |
|---|---|---|---|
| 1 | 识别仍是"说完才整段上传"，合成仍是整段 HTTP，没有 WebSocket 双向通道 | 做不了实时字幕；首字压不到 0.5 秒以内 | 1 号（见 docs/16 第 5 节） |
| 2 | VAD 是前端的能量阈值（不判噪声类型），端点是"静音 700ms" | 强噪声环境可能误触发；说话带长停顿时会被提前断句 | 1 号 |
| 3 | `modules/tools.py` 三个工具返回写死的数据 | 接不到真实名单/订单/工单 | 2B |
| 4 | 幂等存储是内存 dict | 进程重启后幂等失效（逻辑对，存储要换库） | 2B |
| 5 | 合规只做字面词表 + 分类词表 | 换个说法的虚假承诺抓不到 | 3 号 |
| 6 | 自进化（RSI）完全没做 | 同分裁决第①顺位拿不到 | 3 号 |

**已经是真的**（可以放心用）：事件流、状态机流程、身份核验硬约束、拒绝也回写、
含糊三分法、改口更正、幂等、回写失败兜底、会话 token、TTL/并发闸门、五项质检结论、双口径时延、
浏览器 16kHz 分帧采集与序号连续性校验（S1）、
**云端识别 qwen3-asr-flash 与云端合成 qwen3-tts-flash（含静音闸门、超时分档、断连重试、合成失败回落）**、
**分段合成（只等首段就返回）**、**前端能量 VAD 端点检测与自动提交**、**打断（停播＋记账＋丢待播音频）**。
