## 1. 赛题与三道硬门槛

赛题「智语外呼」：做一个能在浏览器里打完一整通外呼电话的数字员工。
难点不在"能对话"，而在这三件事必须同时成立：

| 门槛 | 具体要求 | 我们的做法 |
|---|---|---|
| **流程必须走完** | 自报身份→核验→需求→权益→确认→回写，少一环不合格 | 状态机硬控环节推进，模型只管每句话说啥 |
| **说得快** | 首字响应 P50 ≤ 2000ms | 静音闸门 + 分段合成 + 首段即返回 |
| **说得对** | 不承诺未授权权益、不泄露完整手机号、拒绝也要留痕 | 禁语整句替换 + 入库打码 + 拒绝也回写 |

一句话概括架构：**状态机管流程，大模型管说话。**

## 2. 总体架构

```
浏览器（采集/播报/打断）
   │  HTTP 分片（16kHz/单声道/20ms 一帧，8 帧一片）
   ▼
app.py  路由 · 会话边界 · 串联链路
   ├── modules/voice.py      VAD · 云端识别 · 云端合成
   ├── modules/dialogue.py   状态机 · 槽位 · 话术
   ├── modules/tools.py      客户/订单/工单（幂等）
   ├── modules/eval.py       五项质检 · 闭环打分
   └── events.py  ──────────► SQLite 事件流（单一事实源）
                                  │
                                  ├── dashboard.py → web/dashboard.html（看板）
                                  └── modules/eval.py（质检只读）
```

八个模块分给 5 个人 4 个任务，边界以**文件**为单位切死（详见 `docs/11`）。

### 为什么用事件流当"单一事实源"

转写、质检、时延、成本四件事本质是同一份数据的四个视角。各记一份必然对不上，
而对不上时没人能说清是谁错。所以每发生一件事就写一条带时间戳的事件，
其余全部派生。代价是写入路径必须可靠——这部分在 `events.py` 里做了
WAL、连接复用、类型校验三件事（见 `docs/17`）。

## 3. 关键设计决策

### 3.1 环节推进由代码控制，不由模型控制

模型擅长"这句话怎么说"，不擅长"下一步该走哪一步"。把环节交给模型，
一旦它跳到回写，前面没核实就建单——业务上直接算不合格。
所以 `dialogue.py` 是规则状态机，模型的输出被约束在"当前阶段可以说的话"里。

### 3.2 时延用双口径，且绝不混报

| 口径 | 定义 | 回答什么问题 | 实测 |
|---|---|---|---|
| 处理耗时 | 服务端收到请求 → 返回回复 | 服务器快不快 | P50 974ms / P95 1210ms |
| 首字响应 | T4−T0，用户说完 → 听到第一帧声音 | 用户等多久（**赛题门槛**） | 约 1.1–1.4s（含网络与播放启动） |

30 轮基准里 30/30 在 2000ms 内，P95 余量约 800ms。长尾偶发：第一次基准撞过
一次首段合成 4556ms（4 秒闸门超时后重试成功），第二次没撞上——机制兜得住，
但演示赶上的概率不为零，所以演示脚本里备了降级路径。

### 3.3 合规用整句替换，不打码

打码后的句子会被 TTS 念成"星星星星"，而且语义仍带诱导性，
等于既不通顺也没合规。命中禁语就整句换成合规话术。

### 3.4 回写幂等按通话，不按调用

一通电话一张工单；用户改口是**更新同一张**，不是再开一张。
幂等键用 `session_id:turn_id` 派生。业务系统里始终只有一张单、一个最终结论。

### 3.5 拒绝与沉默都要留痕

- 用户明确拒绝 → 也写 `writeback`，`consent=false`；
- 沉默 → 记 `no_answer`，追问一次，连续两次才挂断；
- 含糊 → 第一次追问，仍含糊记 `unknown`。

理由很实际：业务侧关心的是"这通电话的结果"，不是"只有成功的才记录"。

## 4. 技术选型

| 维度 | 选择 | 被否的方案与原因 |
|---|---|---|
| 语音识别 | 阿里云百炼 `qwen3-asr-flash`（HTTP） | 本地 Whisper：中文准确率可以，但首次加载与内存不适合演示机；流式 Paraformer 等 S2 |
| 语音合成 | `qwen3-tts-flash`，音色 Serena | 浏览器 `speechSynthesis`：机械音，评委第一耳朵就能听出来 |
| 传输 | HTTP 分片（S1） | WebSocket：真流式要重写通信模型，收益在 S2；S1 先用分片把链路跑通 |
| 存储 | SQLite 单文件 | 各种 DB 服务：零依赖优先，评委 clone 下来不用装任何东西 |
| Web 框架 | 标准库 `http.server` | FastAPI/uvicorn：多一个依赖就多一个装不上的理由 |
| 配置 | JSON + 自校验 | YAML：多一个依赖；且我们要能校验结构，不是只要能读 |

**贯穿全部选型的一条原则：零第三方依赖。**
`python app.py` 能跑，就少一个"环境不对"的失败模式。

## 5. 评测

| 项目 | 结果 | 说明 |
|---|---|---|
| `verify.py` 行为断言 | 52/52 | 每条都打出实际事件链与字段值，不只打 PASS |
| `run_eval.py` 用例 | 30/30 | **文字驱动，不测时延、不过 ASR** |
| 其中闭环 | 11/30 | 闭环指真的写入了工单 |

⚠️ **30/30 不能直接拿去汇报。** 用例和规则是互相照着写的，过拟合风险写在
`docs/06` 第 7 节。对外只能说"业务流水线通了"，不能说"系统准确率 100%"。

质检五项（闭环、辱骂、虚假承诺、诱导、隐私、必说话术）目前是**词表 + 规则**，
判不了的标 `skipped` 而不是蒙一个。语义级检测未实现，看板上明确标黄。

## 6. 工程质量与可复现（M8 交付）

| 能力 | 入口 | 验证方式 |
|---|---|---|
| 一键启动 | `启动.bat` / `启动全部.bat` | 双击，浏览器自动打开 |
| 容器化 | `docker compose up --build` | 两个服务 + healthcheck |
| 事件流 | `data/events.db` | `scripts/archive_events.py --stats` |
| 指标看板 | `/dashboard` | 七个区块，每 10 秒刷新 |
| 场景切换 | `config/scenes/*.json` | `python config_loader.py --list` |
| Mock 业务 | `mock_business/service.py` | 六接口，含幂等与错误码 |
| 成本闸门 | `cost_guard.py` | `/api/cost`，默认关闭 |

**配置写错要在启动时报错，而不是跑到第三个环节才 KeyError。**
这条已经落地为 `config_loader.validate()`，并连"话术里写了不认识的占位符"
这种会在演示中途爆炸的错误都提前拦下。
