# 61 · 换成「龙安欢（V3）」音色：确实要换模型，但不用换账号

**2026-11-13 下午**。用户贴了百炼文档截图，红圈圈住 `cosyvoice-v3-flash` 音色列表里
的一行，附一句「我想换成这个音色，好像要换个模型」。

## 一、先把截图读准

| 项 | 值 |
|---|---|
| 模型 | `cosyvoice-v3-flash` |
| 音色 | **龙安欢（V3）** |
| voice 参数 | `longanhuan_v3` |
| 特质 | 欢脱元气女，20~30 岁 |
| 支持语言 | 中文（普通话、广东话、东北话、闽南话、陕西话、山东话、四川话、安徽话）、英文 |
| 特性 | SSML / Instruct / 时间戳 |
| 地域 | 华北 2（北京） |

页面顶部提示条原文：

> 说明 所选音色（voice）须在当前模型（model）的音色列表中。待合成文本（text）
> 须使用该音色支持的语言，否则可能出现发音错误或语音不自然。

**这句提示就是"要换模型"的原因**：`longanhuan_v3` 不在 `qwen3-tts-flash` 的音色列表里，
只属于 CosyVoice 系列。原配置是 `qwen3-tts-flash` + `Serena`，光把 `voice_name`
改成 `longanhuan_v3` 会被接口拒掉。

## 二、"要不要 WorkspaceId"——查完是不用

官方文档主推业务空间专属域名：

```
POST https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer
```

看着像还得去控制台找 WorkspaceId、换同地域 API Key。但 SDK 文档明确写着
「The existing domain remains fully functional」——通用域名仍完全可用：

```
POST https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer
```

用项目里现有的 `dashscope_api_key` 真跑了一次，**200**，所以不需要改账号、
不需要额外配置。这是动手前最值得确认的一点，否则会凭空给用户加一个待办。

## 三、三个必须跟着改的差别

| | qwen3-tts-flash（旧） | cosyvoice-v3-flash（新） |
|---|---|---|
| 端点 | `aigc/multimodal-generation/generation` | `audio/tts/SpeechSynthesizer` |
| 语言参数 | `input.language_type`（Chinese / English） | **没有这个参数**；用 `input.language_hints`（数组，当前只取第一个元素） |
| 音频参数 | 无 | `format`（默认 mp3）、`sample_rate`（默认 22050）；显式给 mp3 / 24000 |
| 返回体 | `output.audio.url` | **同样是** `output.audio.url` |
| 单价 | 0.08 元/千字符（项目里用的估值） | **0.1 元/千字符**（官方 1 元/万字符，华北 2 北京） |

返回体结构相同，所以解析、重试、`http→https` 混合内容那道闸一行都没改。
价格不改会让看板成本低估 20%，属于"数字看着对其实是错的"，必须一起改。

## 四、真跑证据

不是照文档写的，全部用项目自己的代码 + 真实 key 打过：

1. 手写请求打通用域名：`longanhuan_v3` 中文 2375ms / 英文 + `language_hints:["en"]`
   1784ms，均 200；下载音频 113851 bytes、`audio/mpeg`、`ID3` 头。
2. 用 `modules/voice.tts()` 端到端跑（分段合成路径）：

   | 文本 | mode | voice | 首段延迟 | 音频 |
   |---|---|---|---|---|
   | 开场中文话术 | segments | longanhuan_v3 | **580.5ms** | 15451 bytes，mp3 |
   | 英文热线句 | segments | longanhuan_v3 | **452.6ms** | 13051 bytes，mp3 |

首字延迟和旧模型（382–627ms）同一量级，没有因为换模型变慢。

## 五、改了什么

- `modules/voice.py`：新增 `tts_request_body(cfg, text)` 纯函数，按模型族分支构造
  `(endpoint, body)`；`_tts_dashscope` 改调用它；`http→https` 抽成
  `_https_audio_url(url)`。**旧 qwen3-tts 分支原样留着**——换音色是配置决策，
  效果不对改回配置就能回滚，不用再动代码。
- 四个场景的 `tts` 段（`config/scene.json` + `scenes/pop_reject.json` /
  `retail_recall.json` / `service_outbound.json`）：model / endpoint / voice_name /
  format / sample_rate 全部同步，删掉 `language_type`。四个都改是因为线上走
  pop_reject，但跑批和售后共用同一把 key，漏一个就会"主场景换了、切场景变回去"。
- `config/scene.json` 的 `budget.price_per_1k_chars_tts`：`0.08 → 0.1`。
- 三处"当前状态"说明（`voice.py` 模块头、`verify.py` 输出、README 能力表）
  同步成新模型名，避免宣称与实际不一致。
- 新增 `scripts/test_tts_cosy.py`（9 条，不联网）：四场景一致性、价格、
  中/英请求体、旧分支可回滚、端点默认值、混合内容闸。

## 七、两件挂账

1. **`test_hangup_http` 是预存失败**，与本次无关：12/13，红在
   "终态出口：判据成立｜end_reason=''"。用 `git archive HEAD` 导出干净快照单独跑，
   **同样 12/13、同一条红**，确认不是这次引入。它测的是前端挂断判据，
   和 TTS 配置不重叠，本次没动。
2. 音色特质是「欢脱元气女」，而这是**驳回通知**外呼。语气是否偏活泼属于业务判断，
   用户指定了这个音色就按它来；CosyVoice 支持 `instruction` 微调情感/方言，
   若试听后觉得太跳，可以加一句 instruct（如"请用平稳、正式的语气表达"），
   不需要再换模型。

## 八、没动的东西

- `config/evolution/` 下的历史快照（改一个字 sha 全变，且那是当时的实录）；
- `config/evolution/adversarial/adv*.scene.json` 候选场景（历史候选，不回填）；
- `scripts/gen_speaker_corpus.py` 里的旧音色候选（历史语料工具，不在主链路）；
- 官方资料包；
- **没有自动上线**——发布覆盖同一个分享链接，按惯例等用户明确说"上线"。

## 九、一句提醒

页面提示条后半句「待合成文本须使用该音色支持的语言」对本项目是成立的：
`longanhuan_v3` 只支持中文（含方言）与英文。项目里日/法/西等语种本来就未识别，
不会误送；中英互切那条路径已真跑过英文。
