# 56 · 报错了不该说「没关系」，名字也不该被同音字判死

两条要求连着来，指向同一个环节：核身。

2026-11-12 22:59 的截图（线上，中国香港沉香商贸那通）：

```
客服：好的，核对申请单需要您预留手机号的后四位，说四个数字就行。
客户：4940
客服：没关系，那方便说一下您的姓名吗？我核对一下申请单。      ← 用户指的就是这句
```

> 不应该说没关系，而是我并没有核对上，请您再确认一次并给我报电话号码后四位，
> 其他两种也是同理。

紧接着：

> 你没有考虑名字在语音输入的时候会有同音无法识别的情况

两条都对，而且第二条是第一条的下半场：**如果同音字会被判成"报错了"，
那么"明确告知没核对上"这句话本身就会变成误伤。**

## 一、「没关系」错在哪

三处错：

1. **把失败说轻了**。客户报的号和这单对不上，这是核身失败，不是"没事"。说"没关系"，
   客户根本不知道自己刚报错了——这也正是 11-12 早些时候那条反馈的根子
   （"手机号报错也有可能被客户识别成正常的"）。
2. **立刻换凭据**。报错尾号之后马上问"那说一下您的姓名"，等于告诉客户
   "你说的我不信"；而且新凭据他也未必记得，多问一个问题就多一次失败机会。
3. **话术自相矛盾**。上一版是把"对不上"那句拼在追问前面，拼出来是
   「您报的这个尾号…对不上。没关系，那方便说一下您的姓名吗？」——前半句说不符、
   后半句说没关系，一句话里两个态度。

改成整句替换（不再拼默认追问）：

> **我这边没有核对上，麻烦您再确认一次，报一下申请时预留手机号的后四位，说四个数字就行。**

并且**先请他就同一个值再报一次**，同一个槽位问满 2 次（`SLOT_ASK_MAX`）才换凭据。
第二次仍不对时那句会换说法（"我刚才可能没说清楚，我这边没有核对上…"），不逐字复读。

姓名、申请单号、公司名三条同理——`_IDENTITY_MISMATCH` 里四句话，每句都是
"没核对上 + 请再确认 + 重报这个值"。都只说不符，**不透露正确值**。

## 二、同音字：判错和判对都是错的

档案联系人是「晏青梧」，ASR 给出这些是非常正常的：

| ASR 结果 | 改动前 | 改动后 |
|---|---|---|
| 晏青梧 | 核对上了 | 核对上了 |
| 宴青梧 | 数字被丢掉，回"报一下尾号" | 我这边听着是「宴青梧」，您说的是这几个字吗？ |
| 晏青无 | **这个姓名跟申请单上的联系人对不上** | 同上（复述确认） |
| 严青梧 | 同上 | 同上 |
| 北京市川尚商贸有限公司 | 这个公司名跟申请单对不上 | 同上（复述确认） |
| 川上商贸（简称） | 直接丢弃 | 核对上了 |

三个问题叠在一起：

1. **匹配是严格子串**。差一个字就判错——而同一个人被 ASR 写错一个字是常态。
2. **我上一轮加的话术在这里是误伤**。原句是"这个姓名跟申请单上的联系人对不上"，
   客户明明就是本人，却被告知对不上，比"再问一遍"更伤。
3. **裸答姓名要求首字是姓氏**。`宴` 不在 `_SURNAMES` 里，整句名字被丢掉，
   客户答了姓名却收到"报一下手机号后四位"。

改法（不引入拼音表）：

- **相似判定**：等长 + 只差一个字 → `fuzzy`。项目零第三方依赖，标准库没有读音表，
  自己塞一张 3500 字拼音表既大又漏（生僻姓氏正是重灾区）。而语音核身要解决的不是
  "算出读音"，是"别把同一个人判成错的"——等长 + 一字之差就够覆盖 ASR 同音错。
- **fuzzy 不直接核上，也不判错**：复述确认一句「我这边听着是「X」，您说的是这几个字吗？」
  客户点头才记账，`identity_via` 记成 `name:fuzzy`，事后能分清"报准了"和"听成同音"。
  为什么不能直接核上：冒名的人报个近似名就过了。为什么不能判错：是同一个人。
- **客户否认** → 不再强调"没核对上"（他刚纠正过），直接给数字这条路：
  「明白，那我换个方式：麻烦您报一下申请时预留手机号的后四位。」数字不受同音影响。
- **裸答姓名去掉姓氏硬门槛**（只在"上一句确实问过姓名"时启用，靠 `_NAME_BLOCK`
  挡住"不知道/记不清"）；**公司名门槛 6→4**，"川上商贸"这种字号+行业的简称能进。

公司名另有一条：把"有限公司/商贸/北京市"这类不携带辨识信息的尾巴剥掉再比字号，
「北京市川上商贸有限公司」和「川尚商贸」才能对上。

## 三、验证

| 项 | 结果 |
|---|---|
| `scripts/verify.py` | **269/269** |

| L2 基线 | v47 → **v48**（话术改动） |

变异验证（改回去必须红）：

| 变异 | 报红 | 是否连坐 |
|---|---|---|
| 配置里 `reply_mismatch_tail` 换回"没关系，那方便说一下您的姓名吗" | 3 条（`wrong_tail`/`mismatch_each_time`/`same_value_twice`） | 都是话术相关，无连坐 |
| `_name_level` 的 fuzzy 分支去掉 | 3 条同音用例 | 无连坐 |
| 裸答姓名恢复"首字必须是姓氏" | 1 条（`test_homophone_name_asks_confirm`） | 无连坐 |

变异过程中踩到两个测试自身的坑，一并记下来：

1. **改代码默认值不会让测试红**——`_identity_text` 是"配置优先"，所以第一次变异
   （改 `dialogue.py` 里的默认文案）全绿。真正生效的是 `config/scenes/pop_reject.json`。
2. **跨用例状态污染**：`app.start_call/end_call` 会留适配器内存态，导致"单条跑绿、
   整包跑红"。`TestWrongValueSpeaksUp.setUp` 里加 `tools._reset_for_test()` 解决。
   另外把"第三次必须问姓名"改成"第三次不再问尾号"——问姓名还是问单号由
   `_next_identity_slot` 排序决定，写死会把断言绑在实现细节上。

## 四、还没做

- 同音只容**一个字**。连着错两个（"晏青无"再错成"燕清无"）仍判不符，
  但会走复述确认失败后的数字路径，不会卡死。
- 复述时念的是 **ASR 听到的字**（「宴青梧」），不是档案里的字——不泄露档案，
  但客户会看到自己的名字被念错一个字。念对了就泄露"系统里存的是哪几个字"。
- 拼音级近似（"张"vs"章"这种完全同音但不同字）现在靠"等长+1 字差"覆盖，
  不等长的（"李"vs"李某某"）走子串，也没有做声母韵母级比较。
