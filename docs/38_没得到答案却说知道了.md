# 38 · 「没得到答案却说知道了」与随机场景自进化

## 1. 现象

11-10 逐轮读 A11/A16：

```
t3 客户：那我具体要补什么材料
   客服：您申请的闻樾品牌，因授权链不完整…请补齐后重新提交      ← 只说"补齐"，没列清单
t4 客户：急，那我具体要补什么材料
   客服：您看这样解释清楚了吗？您可以简单回我一句清楚了或者还有疑问   ← 没答，改催表态
t5 客户：清楚了，我按你说的弄
   客服：…已记录…感谢配合，再见。                            ← 回写
```

客户从头到尾没拿到"要补哪三样"，却说了"清楚了"。**电话闭环了，问题一个字没答**。
这类"配合式确认"最容易被当成好数据：闭环率 100%、通过 17/17，全绿。

## 2. 根因

`dialogue._stage_need` 里有一段"官方原话说一次就够"的逻辑：

```python
if session.get("official_line_spoken"):
    _after = CONFIRM.reply_after_ask          # "您看这样解释清楚了吗？"
    return _reply(..., next_stage="CONFIRM")  # 直接推进确认
```

原意是防"同一句念三遍"（11-08 实测客户第 9 轮挂断）。但它把"客户再问一遍"
当成了"客户在催"，于是跳过了回答。而客户第二次问，恰恰说明第一次没讲清：
官方话术只说"补齐后重新提交"，不含材料清单。

## 3. 修法

第二次追问按**问题类别**给本单事实，两种说法轮换，不推进阶段：

```python
_cls = policy.question_class(text)
_key = {"material": "reply_application_detail", "reason": "reply_application_detail",
        "provenance": "reply_provenance", "fee": "reply_ask_fee",
        "validity": "reply_ask_validity"}.get(_cls, "")
_tpl = 轮换取 _key 或 _key_2
return _reply(_fill_application(_soothe(_tpl), app), intent="ask")   # 仍停在 NEED
```

NEED 阶段补了 4 个话术键（`reply_application_detail_2` / `reply_provenance` /
`reply_provenance_2` / `reply_ask_fee`），两份场景文件同步。

修后同一通：

```
t4 客户：急，那我具体要补什么材料
   客服：您这笔申请是闻樾品牌、家用电器类目，驳回原因是授权链路不完整，
        缺少品牌方到一级经销商的逐级授权文件，需要补充品牌授权书、
        逐级授权链路证明、授权方营业执照。                        ← 给了清单
```

对抗批次：负面 **4 → 1**，`no_answer|NEED` 消失，A11/A16 弱点命中归零，
通过仍 17/17。

## 4. 随机场景

`scripts/self_evolve.py` 加 `--scene random`：从 `config/scenes/*.json` 随机挑
（排除 `.bak`），并打印每个候选是否可评测：

```
随机场景：pop_reject（候选 pop_reject✓、retail_recall✗、service_outbound✗）
```

`✓` 的判据是场景开了 `application_mode`（`start_call` 会给出客户档案）。
另外两个场景按 **C5 场景隔离**故意不接外呼名单，`start_call` 返回空档案——
拿资审画像去跑，客户手里没有任何可核身事实，闭环永远达不成。

实测：`--scene retail_recall` → 12/17、负面 50、`stalled 48`。**这不是对话质量差，
是数据没接**。给零售场景补了 6 个核身话术键后，负面 50→20，但闭环仍是 12/17，
因为客户档案为空、核身永远过不去。

结论：随机能力已就位，但**目前只有 pop_reject 具备"档案 + 画像 + 可学面"三件套**。
要让随机真正有意义，得先给另两个场景接数据（各自的外呼名单）与各自的画像集；
在那之前，随机抽到它们时报告会明说"数字只能看诊断，不能用来调参"。

## 5. 回归与变异

- `verify` **238/238**：新增两条 NEED 断言（真跑：注入档案 → 核身 → 问两次材料）。
  断言里显式 `set_scene("pop_reject")` 再切回——前面的证据会把场景切走，
  不切回来读到的是售后场景的 NEED（它没有 `reply_application_detail`）。
- 变异：把 `_cls` 强制置空（退回"催确认"）→ 两条断言精确变红（238→236）。
- `run_eval` 88/88、对抗 17/17、`self_evolve check` 14/14；基线 L2 **v24**。

## 6. 边界

- 这条修复只覆盖"客户重复追问同类问题"；若客户第一次问的是画外问题
  （后台哪个入口），仍然答不上来并转专员——那是对的，不该硬编。
- 「客户没得到答案却确认」还有另一半：模拟器本身会社会性顺从。真实通话里
  同样存在，系统侧能做的是"回写前把问题答完"，不是替客户改口。
