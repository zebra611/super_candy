## 四、决策记录（ADR-lite）

只记"当时为什么这么定"，避免两个月后有人问"这破设计谁写的"。

| 日期 | 决策 | 理由 | 影响 |
|---|---|---|---|
| 2026-11 | 不引入任何第三方依赖 | clone 下来就能跑，少一个"环境不对"的失败模式 | 放弃 FastAPI 的自动文档与校验，改用手写 schema 校验 |
| 2026-11 | 事件流当唯一事实源 | 转写/质检/时延/成本是同一份数据的四个视角，各记一份必然对不上 | 事件表会变大 → 必须配套归档（已做） |
| 2026-11 | 时延双口径并列，不合并 | 服务端快 ≠ 用户等得短 | 看板与文档都要同时给两个数 |
| 2026-11 | 看板独立页面，不改 `index.html` | 两个区域迭代节奏不同，同文件每次改都要解冲突 | 多一个页面，但 1 号的终端不受影响 |
| 2026-11 | 成本闸门默认关闭 | 骨架阶段硬熔断会让演示莫名失败 | 需要时改一行配置 |
| 2026-11 | 配置默认仍是 `config/scene.json` | 文档、书签、脚本全指向它，改默认等于改所有人的入口 | 多场景是"加一条路" |
