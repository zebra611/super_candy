# 42 · 把上一轮自己列出来的难看，一处一处改掉

上一轮交付时写了这么一段：

> **但这一通仍不好看的地方，我没修，也不装作没有**：第 8 轮客户问「你到底是谁」
> 仍回「确认不到」；第 10 轮客户说「是我」被回「清楚了，还有其他疑问吗」；
> 第 11 轮「补传页面刷不出来」没命中后台障碍词表。

这一轮就是把这三处改掉。改的过程里又发现一处更深的：**那通电话从第 5 轮起
就没再往前走，整整 10 轮困在同一个问题上**。三处只是症状，这个是病。

## 一、先说最深的那处：客户报了四次信息，客服一次都没接住

线上 A15 第 5–13 轮原文：

```
 5 客：是我。
   服：我跟您复述一下：……您清楚了吗？              → CONFIRM
 9 客：尾号9403，没错。
   服：澹台溪亭，清楚了吗？还是有疑问？
10 客：是我。
   服：清楚了，还有其他疑问吗？
11 客：后台卡得我连补传页面都刷不出来……
   服：清楚了，您稍等我这边处理。您也可以对照申请单编号核实。
12 客：QZ202611060019，这单号我早背熟了！
   服：澹台溪亭，清楚了还是还有疑问？
13 客：清楚啥？我连补传入口都打不开，这算哪门子清楚！
```

客户递了四次实质信息（本人、尾号、单号、障碍），客服四次回的是同一句话。
这不算「客户不表态」，是**客服没接住**：客户报什么都等于没听见。

根因不在判据——`_still_engaged` 已经正确返回 `"fact"`，分支也走对了。
问题在**话术**：

```python
_acks = ["好的，收到。咱们回到正题，您可以简单回我一句清楚了或者还有疑问。",
         "记下了。那回到正题，您可以简单回我一句清楚了或者还有疑问。"]
```

「收到」两个字是空壳，后面那半句才是重点，而改写层正好把空壳压掉了——
线上实际播出的就是「清楚了，还有其他疑问吗？」。骨架里从头到尾**没有客户
刚给的那个值**：客户说尾号 9403，骨架里没有 9403，改写层自然也没东西可保。

### 改法：承接必须带值

```python
if order:  head = "单号 %s 我记下了。" % order.group(0)
elif tail4: head = "尾号 %s，对上了。" % tail4.group(1)
elif who:   head = "对，是您本人。"
```

配合 nlg 的第 8 道守卫：**骨架里的 4 位以上数字，改写后必须还在**，否则退回骨架。
数字是业务事实，改掉一位就是另一件事——这条闸门不许改写层碰。

第 3 次起不再追问。判据是「**不许再出现问句**」，不是「不许说这几个词」：

```python
check("客户第三次报信息后，不许再用问句逼表态",
      not re.search(r"[？?]", last14) and "吗" not in last14)
```

第一版判据是黑名单（「清楚了吗 / 还有疑问 / 简单回我一句 / 哪点不清楚」），
变异测试里把第 3 次改回追问、只换成「那这几样材料您清楚怎么准备吗？」，
**照样全绿**——换个说法继续逼表态，和原句没有区别。判据得是问句本身。

改后同一段：

```
 9 客：尾号9403，没错。
   服：尾号 9403，对上了。那这几样材料您清楚怎么准备吗？
10 客：是我。
   服：对，是您本人。材料这块，您还有哪点不清楚？
12 客：QZ202611060019，这单号我早背熟了！
   服：单号 QZ202611060019 我记下了。清单在后台都能看到，您照着准备就行；
       哪一步卡住了直接说，我陪您过一遍。
```

## 二、「你到底是谁」为什么答不上来

`policy.question_class` 的 provenance 词表里有「你谁」「谁啊」「哪来的」，
而客户说的是「你**到底**是谁」——「你」和「谁」之间隔了「到底是」，
连续串一个都没命中，整句落到「答不上来」的兜底，回「我这边确认不到」。

同一通电话第 4、6 轮明明答过两次「您的号码是商家入驻时预留的联系方式，
我们是官方审核」。**最难看的不是不会答，是第三次问同一件事时忘了自己会。**

补进词表：`到底是谁 / 你是谁 / 什么单位 / 哪个单位 / 平台给的 / 这号真是 /
怎么证明 / 真的假的`。改后第 8 轮正常答来源。

---

## 三、词表只认墙上那一块砖

`_BLOCKED_UI_MARKS` 收的是「打不开 / 进不去 / 登录不了 / 上传不了……」。
客户说的是「后台卡得我连补传页面都**刷不出来**」——同一个意思，一个字都没命中，
于是没走障碍承接，继续问「清楚了吗」。

客户在说一堵墙，词表却只认墙上那一块砖。补：`刷不出来 / 刷不开 / 刷新不了 /
加载不出 / 打不开页面 / 显示不出来 / 白屏 / 转圈`。

## 四、顺手抓到自己写的一处：说了要记，其实没记

`_blocked_ui_reply` 第二次的旧话术：

> 那这样，**我这条记下「后台打不开」**，专员联系您时一并处理。

而代码在这一轮**一张记录都没写**——只有第三次收线时才有 `end_reason` 可查。
说了要做却没做，和用户最早抱怨的「没得到答案却说知道了」是同一类毛病：
**嘴上比手上走得快**。

改成第二次就如实收线（end_reason 就是那条「记下」）：

```python
return _finish(session,
    "后台的问题我这边确实处理不了，也不占用您时间了：材料您先备着，"
    "我把这情况交给专员，稍后用官方号码联系您一起看，再见。",
    "blocked_ui")
```

客户第二次说同一堵墙，系统确实解决不了，再问第三次「清楚了吗」就是空转。
`end_reason="blocked_ui"` 落进事件表，业务侧可据此派单——比一句空承诺可查。

顺带删掉了因此用不上的配置键 `reply_blocked_ui_2`，不留死配置。

## 五、两个「假绿」，都是变异测试逼出来的

**假绿一：断言判据太宽。** 「不许追问」第一版是黑名单，M9 变异（第 3 次改回
继续追问）没红。改成「不许有问句」后才抓住。

**假绿二：变异本身改错了地方。** M8 想测「承接不带值」，第一版只把
`order = re.search(...)` 改成 `None`——尾号分支照样命中 9403，断言 13 全绿。
变异要改的是**整个 head 赋值段**，不是其中一条分支。

两条都记在用例注释里了。变异测试本身也会说谎，它绿了不代表闸门有效。

## 五之二、旧判据本身也会过期

改完跑 `verify`，251 条里有一条红：

```
[FAIL] 连续报信息：接住话术交替不复读，且不追加「要信息型」后缀
       两轮主干是否相同=True
```

它是这么判的：`_o2["reply_text"][:12] != _o1["reply_text"][:12]`——**前 12 字不同**。
旧骨架每句都以「好的，收到。咱们回到正题…」开头，前 12 字相同就等于主干相同，
这条判据当时是对的。

但这一轮要修的正是这句话：它现在以客户报的值开头。客户两轮报的是**同一个**
单号，承接句必然都是「单号 QZ202611060001 我记下了」——**前 12 字相同是对的**，
相同才说明接住了。

所以红的不是代码，是判据过期了。改判据不是改松：

```python
_t2 != _t1 and _q2 != _q1        # 整句不复读，且追问那半句必须换说法
```

比原来更严（整句比对 + 追问段比对），而且测的是这轮真正在意的行为。
M12 变异（把追问固定成一句、不再换）精确红，证明新判据有牙。

**教训**：断言写的是「当时那句话的形状」。改了话术的形状，断言就要跟着改，
但必须改成**更对口**的判据，不是删掉或者放宽。判断标准是——变异能不能红。

## 五之三、发布之后线上又抓到两处（这一节最重要）

本地全绿、重新发布，再跑同一通 A15 模型档。客户这次说的话不一样
（模型客户每轮都不一样），于是又露出两个新形状：

```
 6 客：对，是我公司。
   服：澹台溪亭女士，您这边清楚这几样材料怎么准备吗？      ← 承接句被改写层吃了
 9 客：我刚才不是说过了吗？
   服：您刚说过了，我这边确认不到，稍后让专员给您回电……   ← 把"你没听"听成"我答不上"
14 客：QZ202611060019，这号我早报过三遍了！
   服：单号 QZ202611060019 我记下了。材料这块，您还有哪点不清楚？  ← 又追问
```

**第 6 轮**：骨架是「对，是您本人」+ 追问，改写层把前半句压掉了，
只剩追问。客户确认了身份，客服一句都没认，然后又问一遍。
—— 数字有守卫、单号有守卫，姓名和「是您公司」没有。补第 9 道守卫：
dialogue 在承接轮把承接半句放进 `must_keep_open`，nlg 改写后若这半句
不见了，退回骨架（骨架本来就是给人听的话，退回不吃亏）。

顺便修正一处：客户说「是我**公司**」，旧代码一律回「是您本人」——两回事。
现在按是否含「公司/企业」分流，并从 `outbound_target` 取公司名
（pop 场景的 `slots.application` 是空的，写在这里才取得到）。

**第 9 轮**：「我刚才不是说过了吗」是**元话语**，客户在说"你刚才没听"。
旧逻辑判不出提问，落到 `engaged="talk"` 的兜底，回「我这边确认不到」——
客户在抱怨重复，客服答"我确认不到"，把「你没听」听成了「我答不上」。
补 `_META_REPEAT_MARKS`（我刚才不是说了 / 我说过了 / 你刚问过了 / 怎么又问 /
报过三遍 …），命中就先认账、停止追问，且不给任何「确认不到」的出口。

改完再跑线上，第 8 轮仍是「抱歉没接住，您说的我记下了，接下来照着准备就行。
**您也可以对照申请单编号核实**」——客户刚说"我说过了"，客服转头又要一遍单号。
元话语轮也要置 `fact_ack_turn`，把要信息型后缀拦住。第 14 轮「这号我早报过
三遍了」同理没认出来（词表只收"我说过了"，没收带遍数的），一并补上。

### 又一次「测了判据、没测接线」

第 9 道守卫我一开始只在 `test_train_replay` 里测了纯函数 `_open_kept`——
把 `say` 里那句 `if not _open_kept(...)` 改成 `if False`，**变异照样全绿**。
函数是对的，接线断了。补了 `test_nlg.py::test_open_kept_or_fallback`，
mock 改写返回丢掉承接的文本，断言 `say` 退回骨架、且正常改写不被误挡。
改完 M14 精确红。

**这轮一共三次「绿了但没测到」**：黑名单判据、变异改错分支、只测函数不测接线。
三次都不是代码 bug，是验证本身在骗人。变异测试是唯一能戳穿它的东西。

## 七、这轮没改的，以及为什么

1. **官方 QA 原文「可在单据中授权书位置上传」读着别扭，不改。**
   它出自 `config/kb_pop.json` 的 `KB-POP-Q01`，`source_id` 指向
   `官方资料包/驳回外呼QA.xlsx#高频QA 行2`。qa 是官方原话、不可改写，
   改了就是改溯源——宁可读着别扭，不能替官方润色。真要顺，只能改
   「读不通时不许原样播报」的规则，那是另一件事。
2. **L2 基线仍有 1 个 `agent_no_progress`**（S05 客户 6 轮拒绝核身、系统按
   安全规则不推进，归因器记成「客服无进展」）。归因口径问题，不为刷绿改它。
3. **模型档仍未接进跑批闸门。** 上一轮线上真跑抓到「记住了没」被当成确认，
   规则档 17/17 全过却没抓到——这一轮的三处也是靠线上逐轮实录发现的，
   规则档跑批依旧全绿。这是下一步的第一优先级，不是这轮能顺手补的。
