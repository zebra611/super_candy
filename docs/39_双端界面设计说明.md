# 双端界面设计说明（客户侧 / 客服侧）

> 交付物：`eval/ui/`（模板 + 头像清单 + 单文件预览）。**不直接改 `web/index.html`**——那是 R1（张博涵）的文件，由他 review 后合并。

---

## 一、为什么要分两端

同一个页面换个皮不叫双端。两端回答的是**不同人的不同问题**：

| | 客户侧 | 客服侧 |
|---|---|---|
| 他关心什么 | 对面是谁、说到哪句、怎么退出 | 该说什么、说到哪、有没有越界 |
| 看到的信息 | 头像、名字、工号、一句实时字幕 | 客户画像、六环节进度、指标、完整对话流、风险提示 |
| 看不到的 | 情绪标签、P50、轮次——**这些只会让客户更焦虑** | — |
| 操作 | 静音 / 挂断 / 免提 / 转人工 | 无需操作，只看 |

## 二、视觉规范

| 项 | 取值 | 说明 |
|---|---|---|
| 主色 | `#E1251B` / 深 `#C81623` | 京东红，只用在品牌标、当前环节、主按钮 |
| 底色 | `#F5F6F8` + 两处极淡红径向渐变 | 白卡片浮起来靠的是底，不是描边 |
| 投影 | `0 12px 30px rgba(200,22,35,.07)` | 红调投影，不是灰调——这点差别决定"贵不贵" |
| 圆角 | 卡片 18px，气泡 15px，按钮 12px | 三档足够，再多就乱 |
| 字阶 | 11 / 12.5 / 13.5 / 16 / 20 | 五档；数字一律 `tabular-nums` |
| 分隔 | 1px `#ECEFF3` 细线，不用阴影分隔 | 阴影多了显脏 |

## 三、头像（4 位，2 男 2 女）

| ID | 名字 | 年龄 | 耳麦 | 定位 | 适合 |
|---|---|---|---|---|---|
| F1 小彩 | 26 | 否 | 品牌形象 | 常规回访、品牌露出 |
| F2 小雅 | 23 | 是 | 在岗新人 | 年轻客户、轻松场景 |
| M1 小川 | 29 | 否 | 品牌形象 | 常规回访、投诉安抚 |
| M2 小航 | 23 | 是 | 在岗新人 | 学生与年轻商家 |

**为什么分"有耳麦/无耳麦"两档**：耳麦是"客服"的识别符号，没有它再好看也像办公室职员；但全是耳麦又像呼叫中心宣传照。两档并存，答辩时按场景挑。

**"不假笑"的三条硬标准**（写进了生成 prompt，也是挑图的判据）：
1. 笑意到眼睛——眼轮匝肌收紧、眼角有细纹，这是真假笑的唯一分界线；
2. 眉毛放松——眉头上抬 0.5mm 就显惊讶或焦虑；
3. 嘴角对称——单边先笑会像冷笑，这是"奸诈感"的主要来源。

## 四、怎么改（不用碰 HTML）

```bash
# 换头像：把图放进 eval/ui/assets/，改 eval/ui/avatars.json，然后
python3 scripts/build_ui_preview.py      # 产出 eval/ui/preview.html（单文件，可直接双击）
python3 scripts/test_ui_template.py      # 6 条：清单完整、无外链、构建可复算
```

`preview.html` 把 4 张头像内联成 base64，**只有一个文件**，发给别人不会漏图（约 360KB）。

## 五、落地边界

1. `web/index.html` 属 R1，本目录只是**模板与数据**；要上线需张博涵 review 后合并；
2. 头像为 AI 生成，右下角带工具水印，圆形裁切后不可见；若赛题要求真人照片，同名覆盖 `assets/` 即可，清单不用改；
3. 对客侧的"本通话由人工智能语音系统拨打"是《人工智能生成合成内容标识办法》要求的标识义务，**删不得**。

## 六、可复算（评审后补）

`eval/ui/preview.html` 是**生成物**，必须能从 `template.html + avatars.json + assets/` 逐字节重建。

- 构建脚本写文件时用 `open(..., "w", encoding="utf-8", newline="\n")`。
  Windows 文本模式会把 `\n` 翻成 `\r\n`，重建一次 1447 行全变（372660 → 373107 字节，
  +447 正好等于行数），库里那份立刻显示为已修改，364KB 的生成物会把真改动埋掉。
- `test_ui_template.py` 里 `test_committed_preview_matches_build` 断言
  「库内 preview.html 的 sha256 == 重建结果」，并顺带断言产物里没有 `\r\n`。
  旧版只比「两次内存构建」，永远相等，看不到落盘这一步。
- 改模板或换头像后必须重新跑 `python3 scripts/build_ui_preview.py` 并提交产物，
  否则这条断言会红——这是有意的，避免产物与模板长期分叉。
