> 关联：`scripts/test_noise_robustness.py`（实测 + 变异自测）、

>

> `Cough.`，落进核身失败计数，人还在线就被挂断。用户点名要求把"噪声

## 一、先纠一个概念错误：噪声不是一个问题，是四层问题

把"噪声"当成一件事，就会得出"接个降噪库"这种没法落地的结论。本系统链路是：

```
麦克风 → ① 声学层 → ② ASR 层 → ③ 文本/语义层 → ④ 对话状态机 → 回复/TTS
```

同一句"没听清"可能来自四个完全不同的原因：

| 层 | 失效形态 | 典型输出 | 谁能解决 |
|---|---|---|---|
| ① 声学 | 旁人说话、空调、键盘、TTS 回放 | 波形里叠了另一路信号 | 麦克风阵列 / AEC / NS / 说话人分离 |
| ② ASR | 把咳嗽转写成 `Cough.`、把旁人话转写成用户发言 | 一段看似正常的文本 | ASR 事件标签、词级置信度、热词 |
| ③ 语义 | 乱码被当成姓名、"不清楚"被当成同意 | `evidence=none` / 错别字 | 规则与置信度分级 |
| ④ 状态机 | 噪声烧掉核身次数、槽位横跳、直接挂断 | `identity_failed` | **本次 C6 修复的主战场** |

关键判断：**第 ① ② 层的问题，在第 ④ 层只能"不误伤"，不能"听清"。**
把文本层修得再好，也恢复不了被旁人声盖掉的音素。这句话要在答辩时主动讲，
否则会被追问到穿帮。

## 二、噪声类型学：为什么"嘈杂人声"是最难的一类

| 类型 | 物理特征 | 传统降噪 | 我们的处境 |
|---|---|---|---|
| 稳态噪声（空调/风扇/白噪） | 频谱统计近似平稳 | **有效**：谱减法、维纳滤波、自适应陷波 | 浏览器 WebRTC NS 已覆盖一部分 |
| 非稳态噪声（键盘/关门/敲击） | 短时脉冲 | 部分有效：瞬态检测 + 置零 | ASR 多半能容忍 |
| 非语音人声（咳嗽/喷嚏/笑/叹气） | 由人声带产生，频谱接近语音 | **差**：容易被当成语音保留 | ASR 会转写成 `Cough.`/`Sneeze.` |
| **竞争人声 / babble（旁人说话）** | **与目标语音同频带、同调制、同为语音、非平稳** | **基本无效** | **最难的一类，见下** |
| 回声自激（TTS 被麦克风录回） | 已知参考信号，线性卷积 + 少量非线性 | **有效**：AEC 自适应滤波 | 需要 AEC 真的生效 |
| 静音 / 丢帧 | 无能量 | VAD 可判 | 但"完全没声音"和"ASR 没识别出字"是两回事 |
| ASR 幻觉 | 波形干净，模型自己造词 | 与声学无关 | 只能靠文本层兜底 |

### 为什么竞争人声躲不过常规降噪

谱减法、维纳滤波、MMSE-STSA 这一类单通道增强的隐含前提是：**噪声的统计特性
可以从非语音段估计出来，且与语音不相关**。竞争人声把这个前提整个拆了：

1. 它和目标语音都在 100 Hz–4 kHz，基频、共振峰结构一样，滤波切不掉；
2. 它和语音一样非平稳，没法从"静音段"估计噪声谱；
3. 它和语音强相关（都是语言），维纳增益会把两边一起压掉，结果是目标也糊了；
4. 能量上未必更弱——旁边的人可能比接电话的人嗓门更大。

所以单通道降噪对 babble 的收益通常很小，甚至负收益。真正能分开它的是**两类额外信息**：

- **空间信息**：麦克风阵列 + 波束成形（MVDR / GSC），按到达方向形成指向性；
  手机双麦可以做，但浏览器拿不到原始多通道，WebRTC 内部做了也不暴露。
- **身份信息**：说话人日志（diarization，"谁在什么时候说"）或目标说话人提取
  （Target Speaker Extraction，用注册声纹把目标人声从混合信号里抽出来）。
  这需要声纹注册或至少能拿到多说话人分离结果，云端单说话人 ASR 不提供。

**一个常见的错误做法必须点名**：靠"提高 VAD 能量阈值"来挡旁人声。
它挡不住（旁人声能量可能更高），却会先切掉用户自己小声说的尾号、
犹豫时的半句、句尾轻声字——把噪声问题变成漏字问题，而且更难归因。
我们不做这件事。

### 回声自激的成因要说准

WebRTC 的 `getUserMedia` 默认带 AEC，但 AEC 只在**采集与播放走同一条
WebRTC 音频轨道**时才拿得到参考信号。如果 TTS 是用 `<audio>` 或
`AudioContext` 单独播放、采集却走另一条 MediaStream，回声路径就绕过了
AEC，自己的话会被录回去，"您提交的资质申请没有通过审核"变成下一轮
用户输入。这类噪声文本层能识别（探针 N06），但根子在播放链路。

## 三、现有链路逐段审计

| 环节 | 现在做什么 | 不做什么 | 后果 |
|---|---|---|---|
| 浏览器采集 | 分帧上传、能量 VAD 自动提交 | 不判"是谁在说" | 旁人说话被整段送进 ASR |
| `qwen3-asr-flash` | 单说话人识别，返回文本 | 不做 diarization、不给词级置信度、非语音事件直接转写成词 | `Cough.` 看起来像正常输入 |
| `modules/intent.classify` | 规则分类 + 置信度分级 | 默认 provider=template，不调模型判噪声 | 纯英文/无中文无数字 → `evidence=noise` |
| `dialogue._stage_identity` | 核身、槽位、退出机制 | 曾把噪声记进 `identity_vague`/`slot_asks` | **连续两声咳嗽就 `unclear` 挂断** |
| `app.py` 输出侧 | 合规护栏、TTS | 不回写 ASR 置信度到事件 | 事后分不清"没听清"和"答得含糊" |

11-06 事故的形状：第 1 声咳嗽还没挂断，但已经把 `identity_vague` 加到 1；
第 2 声就到 `IDENTITY_VAGUE_MAX=2` 直接收尾。当时只暴露了第 1 声，
所以单轮探针全绿是**假绿**——这是本次把探针改成连续 3 轮的直接原因。

## 四、三层防线：做了什么，没做什么

### L1 音频前端 —— **未实现，且不是文本层能替代的**

需要：AEC 回路对齐、麦克风阵列波束成形、说话人分离/目标说话人提取、
把 ASR 返回的词级置信度与 `speech_event` 标签透传到业务层。
本轮无硬件预算、无多通道原始音频、云端 ASR 不提供 diarization，
因此**这一层明确列为占位**，不假装做了。

### L2 ASR 输出层 —— 部分实现

- 纯英文 / 无中文无数字的转写 → `evidence=noise`（T17 修复）
- 2–3 位数字 → 引导补全四位，不算失败（T17-①）
- 挂断前完整重问一次（T17-③）

### L3 对话状态机 —— **本轮 C6 主修复**

五条具体规则，全部落在 `modules/dialogue.py` 的 `_stage_identity`：

1. **噪声与含糊分桶**：`evidence=noise` 走独立通道，不累加
   `identity_vague`、不加 `identity_attempts`、不轮换槽位、不推进阶段、不回写。
2. **无效轮不消耗追问机会**：这一轮 `_take_identity_slots` 没提交任何
   可核身信息（旁人说话、答非所问、TTS 回声），不算一次核身失败，
   不进 `_ask_identity`、不烧 `slot_asks`。这是中文环境人声的关键保护——
   文本层分不清"谁在说"，但至少可以不把有声音当成有回答。
3. **独立死等兜底**：`NOISE_MAX=5`，连续 5 轮纯噪声且用户无任何有效输入
   才按 `no_voice` 礼貌收尾；中间任一轮给出有效信息立即清零。
   与含糊的 `IDENTITY_VAGUE_MAX=2` 完全分开。
4. **弱形式姓名抽取要求首字是姓氏**：ASR 把环境音识别成"咕噜"这类
   2 字乱码时，旧逻辑会当成姓名提交并烧掉一次核身（C6 N04 实测抓到）。
   判据是中文姓名的语言事实，不是对样例过拟合；带引导词的强形式
   （我姓/我叫/X先生）不受影响。
5. **静音是另一类**：连续 2 次完全无识别结果按 `silence` 收尾（疑似挂机），
   这是有意设计，单列在探针里，不混进"嘈杂人声不挂断"的口径充数。

## 五、实测（可复跑）

```
python scripts/test_noise_robustness.py
python scripts/test_noise_robustness.py --self-test
```

**7 组 × 连续 3 轮噪声**：咳嗽/喷嚏英文词、中文旁人说话、纯英文环境音、
ASR 乱码与口头禅、3 位尾号半句、TTS 回声自激、混合噪声（真实嘈杂环境）。
每组断言：有回复、不挂断、`identity_attempts` / `identity_vague` /
`slot_asks` 三个计数器前后不变、不产生 `writeback`；随后用户正常报尾号
→ 陈述业务域 → 确认 → 关单，必须能恢复完整闭环。

**结果**：7/7 通过；静音设计边界符合（2 次收尾、不回写、不记核身失败）。

**变异自测（防假绿）**：
- M1 把 `NOISE_MAX` 退化成 1（第一声咳嗽就挂）→ 探针报红 6 条；
- M2 双层防护同时失效（noise 标记被抹 + 任何输入都当成有效槽位，
  即修复前形态）→ 探针报红 6 条。

两项 2/2 通过。全绿之后必须能变红，才说明断言真的在盯计数器，
而不是碰巧走了别的分支。该探针与标注校验已挂进 `scripts/verify.py`
证据 22 总闸门。

## 六、诚实边界：文本层做不到的三件事

1. **听不清**：被旁人声盖掉的音素恢复不了，只能请对方重说。
2. **分不清谁在说**：中文"那个订单放桌上吧"和商家说的一句业务陈述，
   在纯文本上没有任何可判别的特征；我们只能做到"不误伤"，做不到"剔除"。
3. **分不清"沉默"的两种成因**：完全没声音（网络/挂机）vs 有声音但
   ASR 一个字都没出，目前都落到空输入。要分开必须拿到 ASR 的能量/VAD
   元信息，云端接口现在不给。

另外两个已知限制：`intent.classify` 若切到 dashscope 模型判意图，
`evidence=noise` 这条规则可能被模型裁决覆盖（跑批与 verify 强制
`provider=template`）；噪声轮的 `intent=noise` 与真实"信号不好"目前
共用一套事件口径，看板上不做区分。

## 七、有硬件/接口预算时的落地顺序

按"投入产出 / 可验证性"排，不写做不到的空话：

| 阶段 | 动作 | 验收口径 |
|---|---|---|
| P0（零成本，先做） | TTS 播放与采集对齐到同一 WebRTC 轨道，让 AEC 真正生效；把 ASR 返回的词级置信度与事件标签透传进事件库 | 回声自激从事件流里消失；能区分"没声音"和"有声音没识别出字" |
| P1 | 前端加**双讲检测**（barge-in 已有三段式），噪声轮不提交整段音频，只在能量持续超过阈值时提交 | 旁人短句不再进入 ASR，用户打断仍能被认出 |
| P2 | 换支持 diarization / 多说话人的 ASR，或引入目标说话人提取；按声纹登记"接电话的人" | 竞争人声场景下字错率下降，可用带旁人声的回放集做 A/B |
| P3 | 麦克风阵列 + 波束成形（需硬件） | 定向拾音，babble 场景字错率下降 |

每一阶段都要用同一套回放集测，不能只报"感觉好多了"。回放集可以从
`test_noise_robustness.py` 的 7 组文本反造 TTS 音频，叠加真实环境人声，
形成可复现的噪声评测集——这是 C7 语音基准的自然延伸。

## 八、答辩问答口径（三句话）

> **问：嘈杂环境里别人说话，你们怎么处理？**
> 音频层我们承认没做说话人分离，云端 ASR 会把旁人声转写成文字；
> 但我们在对话状态机上把"有声音"和"有回答"分开——噪声不烧核身次数、
> 不轮换槽位、不挂断人，连续 3 轮噪声后用户正常说话仍能完整闭环，
> 这组行为有 7 组实测和 2 组变异验证。
>
> **问：那不还是没听清吗？**
> 是。文本层恢复不了被盖掉的音素，我们不宣称降噪。真正解决要 AEC 回路
> 对齐 + 说话人分离/波束成形，路线和验收口径写在 docs/25 第七节。
>
> **问：为什么不全交给大模型判断？**
> 核身和挂断是确定性业务动作，把"要不要挂电话"交给一个会把咳嗽判成
> 拒绝的模型，等于把可用性押在采样温度上。模型只在措辞层和意图裁决的
> 可改标签上介入，噪声分桶、次数、退出阈值全部是规则，可复现、可审计。
