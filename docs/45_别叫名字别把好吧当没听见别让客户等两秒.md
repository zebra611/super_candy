# 45 · 别叫名字、别把「好吧」当没听见、别让客户等两秒

> 触发：用户在线上页面截了一张图，三句话：
> 「不要直接叫名字啊喂，你怎么确定他说公司的那个部门的人，就敢说人名？」
> 「而且我回好吧，应该是这个回复吗？」
> 「还有反应时间严重超过 2s，这还不算语音输入，是什么情况？」

三条都不是"话说得不好听"，是三种不同的错：

1. **称呼错人**——把档案里的联系人姓名当成"接电话的人的名字"；
2. **没听见**——客户答了「好吧」，系统当成没表态，还要他再说一遍；
3. **等太久**——服务端处理 1369ms，语音轮 P95 2289ms，门槛是 2000ms。

---

## 一、直呼姓名：核身对上的是"这通电话"，不是"这个人"

### 现场

```
客：好吧
服：晏青梧，您简单回我一句清楚了或者还有疑问就行。您回一个字也行。   ← CONFIRM
```

这句话有两个来源叠在一起：

- 「晏青梧，」是**模型**加的。`agent_free` 的 prompt 里有【本单事实】，
  其中一行就是「联系人：晏青梧」，模型很自然地把它当称呼放在句首；
- 「您回一个字也行。」是**性格层**挂的尾巴。这一句本身已经在讨回应
  （"您简单回我一句…"），后面又追一句"回一个字也行"，一句话要了两遍表态。

### 为什么这是错的（不是"太随意"，是"假设错了"）

核身通过只能证明：**这个号码对应这笔申请**。它证明不了：

- 接电话的是联系人本人——可能是同事、前台、财务，也可能是打错了顺手接的人；
- 对方愿意被叫名字——商家资质这种电话，叫名字听起来像熟人，反而更像骗子。

更要紧的是**念出名字等于泄露**：客户只说了一句「是我」，客服就把
「晏青梧」三个字念给了一个还没确认身份的人听。这和上一轮修的"嘴漏"
（核身前念尾号）是同一类问题，只是漏的是姓名。

### 修法

1. `agent_free` 的 system prompt 加第 4c 条：**任何时候都不叫客户姓名**，
   「张经理」也不行；只有客户本条消息里自己报了名字，才可以复述一次。
2. 出话后再过一道 `_drop_name_call`：只删**称呼位置**（句首、标点后、句尾）
   的姓名与「姓+职务」，句子中间的档案值不动。

```
晏青梧，您简单回我一句…            → 您简单回我一句…
晏经理，麻烦您报一下后四位。        → 麻烦您报一下后四位。
对，是您本人，晏青梧。             → 对，是您本人。
您的联系人写的是晏青梧，对不上…      → 原样保留（这是讲事实，不是称呼）
```

3. 规则层的承接句同样改：`_fact_ack_reply` 里，客户说「是我」时不再拼
   `对，是您本人，{姓名}`，只说「对，是您本人。」；客户自己说了
   「是我，晏青梧」，才复述姓名（`reply_fact_self_named`）。

> 上一轮为了"承接必须带值"才把姓名拼进去的。那条原则没错，错在**值不是客户给的**——
> 尾号、单号是客户刚报的，姓名是客服手上档案里的。承接只能复述对方给过的东西。

## 二、「好吧」：客户答了，系统说没听见

### 现场

```
服：这个我这边确认不到，稍后让专员用官方号码给您回电说明，可以吗？   ← CONFIRM
客：好吧
服：您简单回我一句清楚了或者还有疑问就行。                          ← 又问一遍
客：知道了
服：好的，驳回原因和要补的材料我都记录下来了…再见！                  ← 这才闭环
```

客户白说一轮。而且下一轮他说的「知道了」和「好吧」是同一个意思——
**系统认一个、不认另一个**，这才是真问题。

### 根因

`WEAK_YES` 里明明有「好吧」，置信度 0.45 被压在 `YES_MIN_CONF` 下面，
于是落到「含糊」分支，`confirm_asks += 1`，回 `reply_again`：
「您可以简单回我一句清楚了或者还有疑问就行。」

这条设计本身是对的——**在营销场景**。那里的 CONFIRM 问的是"您同意领取吗"，
「好吧」多半是"我不想跟你争了"，据此回写 consent=true，后面退订、投诉就从这里来。
文档和 `tests/test_intent.py::test_weak_yes_not_written_back` 都在守这条。

但这一通（POP 资审驳回）问的是**「清楚了吗」**，记的是 `merchant_understood`。
「好吧」在这里就是「行，我知道了」，和「知道了」等价。

### 修法

`confirm_yes_words` 是**场景自己的**确认词表（注释里写着"问的是清楚不是同意"），
在 pop_reject / scene.json 两份里补上「好吧」「行吧」。营销场景
（`service_outbound` / `retail_recall`）**不配**这两个词，行为一点没变。

测试也分两头守：

- `verify` 新断言：pop 场景说「好吧」→ 直接 `DONE` + 有回写 + 回复里没有「回我一句」；
- 反向断言：`service_outbound` 的 `confirm_yes_words` 里**不许有**「好吧」；
- `test_intent` 那三条（弱肯定 below threshold、不落库）继续跑在原场景上，全绿。

### 顺带修的尾巴

`_SKIP_SUFFIX_MARKS` 补了「回我一句」「回一句」「简单回」——
句子自己已经在讨回应，性格层不许再挂「您回一个字也行」。
`verify` 里原来那条对照用例（拿"您可以简单回我一句…"当**该加**后缀的反例）
跟着换成一句不含讨回应的话，并新增一条"已经在讨回应的句子不许再挂后缀"。

## 三、两秒：钱花在哪，时间就花在哪

### 先把口径拆开

页面上的「本轮处理耗时 1369.2ms」不是模型一家的时间，它是
**ASR + 状态机/模型出话 + TTS 首段**（`app.handle_turn` 的 `total_ms`）。
同一块面板上另有两个数：打字轮 P50 942ms、处理耗时 P50 1053.9ms——
打字轮不过 ASR，所以差的那 ~500ms 基本就是识别。

### 实测：模型这一层到底多慢

同一个 prompt、同样的闸门，各跑 4 次：

| 模型 | 4 次耗时 | P50 |
|---|---|---|
| qwen-plus | 1010 / 937 / 728 / 715 ms | **832 ms** |
| qwen-flash | 335 / 380 / 470 / 612 ms | **425 ms** |

qwen-plus 的 832ms 加上 TTS 首段，就是 1369ms 的来源。

### 还有一处隐藏的坑：超时会重试

`agent_free` 原来用的是 `timeout=2.5, retries=1`（`llm.chat` 的默认值）。
第一次超时后 `time.sleep(0.6)` 再试一次，**最坏 5.6 秒**。
语音轮 P95 2289ms、面板上"超时 1"，长尾就是从这里来的——
而且客户那头是静音，比话说得难听严重得多。

### 修法

1. 这一层换 `qwen-flash`：任务是一句话、有七道闸门兜事实，
   要的是"说对"不是"想得深"；
2. `timeout` 2.5s → 1.5s，`retries` 1 → 0，`max_tokens` 200 → 120；
3. 三个值都进 `config/*.json` 的 `agent` 块（`model` / `timeout_ms` / `retries`），
   换机器/换模型不用改代码；
4. 模型没接上时把原因写进 `agent_free_reject`（`llm:timeout` 之类），
   不再看起来像"骨架就是答案"。

### 改完真跑一段（模型开着，pop 场景，QZ202611060001）

```
客：对，是我。                    服：好的，核对申请单需要您预留手机号的后四位…   439ms  skeleton
客：0086                          服：尾号0086，对上了。您申请的闻樾品牌…         599ms  model
客：哦，那要补什么材料？           服：您申请的闻樾品牌，因授权链不完整…          5ms    skeleton
客：上传路径我这边确认不到，怎么办？ 服：您看这样解释清楚了吗？…                  387ms  skeleton
客：好吧                          服：好的，刚才说的驳回原因和补材料要求我已记录…  529ms  model
                                  → WRITEBACK→DONE，回写版本 1
```

- 出话这一段 P50 从 832ms 掉到 ~450ms，**省下的 400ms 是实的**；
- 「好吧」这一轮直接闭环，不再要客户补一句「知道了」；
- 全程没有直呼姓名。

> 这段本地跑把 TTS 掐成了 browser（零网络），所以 529ms 不含合成。
> 线上还要加首段合成，预计落在 900ms 上下——比 1369ms 好，但**还没到"像真人"**。

## 五、这一轮还没解决的

1. **两秒是整条链路的账，不只模型**。TTS 还是整句合成（`voice.tts` 非流式），
   首段要等整句出来；真要压到 1 秒内，得改流式合成 + 首句优先，这是语音侧的活。
2. **「好吧」只按场景放行**，靠的是一张词表。客户说「那行吧」「行，就这样」
   仍是含糊——下一轮可以按"这一通问的是清楚还是同意"来选阈值，
   而不是按场景硬编码词表。
3. **本地这段跑暴露了一个别的问题**：客户问「要补什么材料」时，
   骨架只回了「…请补齐后重新提交」，三样材料的名字一个没念（那一轮 5ms，是骨架，
   不是模型）。这不在这次三条里，但确实是"听不懂"的下一个来源，记在这里。
