# 33 用音色挡住"非本人发言"：三条路都测了，结论和边界

> 问题：能不能靠判断音色，把"旁人说的话"从用户发言里剔掉？
> 短答：**能，但前提是你把问题问对。** 这里做的不是"声纹比对"，是
> **同一通电话内的说话人一致性**；而且现在只敢开**影子模式**（记录不拦截）。

---

## 一、先把问题问对：外呼场景没有"声纹"

"声纹比对"要求**事先注册**：先录一段这个人的声音，之后拿新的来比。
但外呼是**我们先打过去**——拨号之前根本不知道接电话的是谁，没有模板可比。

所以真正能做、也真正有用的是另一件事：

| 想解决的 | 实际要做的 | 叫法 |
|---|---|---|
| "这句话是不是目标本人说的" | 先定"主说话人"（开场应答的那位），后面的话跟他比 | **说话人一致性**（在线聚类的一种） |
| "这句话是谁说的、换人了吗" | 同一通话里分出 1/2/3 号说话人 | 说话人分离（diarization） |

两者的区别很实在：**一致性只回答"像不像刚才那位"**，不回答"他是不是店主"。
旁人抢在第一句接了电话，系统会把他当主说话人——这一点挡不住，也没有方案能挡。

---

## 二、三条路，全部实测，两条被否

### 路线 A：纯手工特征（MFCC + F0 + 谱质心），零依赖

做了完整实现并在 25 条多音色语料上标定：

| 指标 | 结果 |
|---|---|
| EER（同人 vs 异人） | **24.0%** |
| 短句（<2s）EER | **30.2%** |
| 零误杀工作点 | 阈值取到最低分，**漏放 99%** |

**结论：不可用。** 根因不是调参：MFCC 均值里"内容"的方差远大于"说话人"的方差，
5 句不同的话，同一个人的差异比不同人之间的差异还大。这条路放弃，代码没进仓库，
只把"为什么不行"留在这里，免得下次再有人试一遍。

### 路线 B：让 ASR 直接给 speaker_id（零新增依赖）

`paraformer-realtime-v2` 的 run-task 参数里加上 `speaker_diarization_enabled`，
喂一段"女声→男声→女声"的拼接音频（`scripts/probe_diarization.py`）：

```
返回的整句（3 条）：
  sid=1 spk=None     0~3020  我这个是品牌授权的材料，没过是吧？
  sid=2 spk=None  3380~6720  嚯这个是品牌授权的材料，没过是吧？
  sid=3 spk=None  7040~9240  喂，你好，哪位？
结论：服务端没有返回 speaker_id，说话人分离不可用
```

**结论：不可用。** 句子切得很准（三个 sid 都对），但没有 speaker 字段——
说明这个实时接口不支持。除非改走批式（URL 转写）那条线，而我们的场景是实时通话。

### 路线 C：神经声纹嵌入（WeSpeaker 中文模型，ONNX）

- 模型：`wespeaker_zh_cnceleb_resnet34.onnx`（CN-Celeb 训练，26MB，输入 80 维 fbank，输出 256 维）
- 运行时：`onnxruntime`（本机已有；缺了自动 abstain，主链路不变）
- 下载：`python scripts/fetch_speaker_model.py`（带 sha256 校验 + 断点续传）

在本机 25 条语料（5 个音色 × 5 句）上标定：

| 指标 | 结果 |
|---|---|
| EER 总体 | **16.0%** |
| 长句（≥2s）EER | **8.0%** |
| 短句（<2s）EER | **11.2%** |
| 工作点（零误杀） | 阈值 0.746：本人 **0/10 误杀**，旁人 **15/100 漏放** |

**音色两两相似度**（越高越容易混，这张表比 EER 更能指导上线）：

```
Chelsie~Cherry   0.702   ← 三个女声彼此 0.64~0.70，是主要混淆源
Chelsie~Serena   0.685
Cherry~Serena    0.643
Dylan~Ethan      0.398   ← 两个男声之间
其它跨性别       0.20~0.26  ← 最容易分
```

**结论：可用，但只当"第二道闸"。** 跨性别几乎不会错；同性别近音色才是风险区，
而这一类恰好也是最容易在真实场景里出现的（夫妻、同事）。

## 三、现在的接入形态：影子模式

配置在场景包里：

```json
"speaker_gate": { "enabled": true, "mode": "shadow" }
```

每一轮识别出文本后，`app._speaker_probe()` 会：

1. 判这句像不像"主说话人"（`same / other / uncertain / abstain`）；
2. 写一条 `speaker_gate` 事件（含 `decision` / `score` / `ms` / `enrolled`）；
3. **到此为止**——不改变这一轮怎么处理。

三态而不是二态的用意：
- `abstain`（太短、没注册、没模型）**完全忽略**，否则 1.2 秒的"尾号0086"会被系统性判成旁人；
- `uncertain`（灰区）只记录，不影响用户；
- 只有 `other` 才算"非本人"，而它现在也只进事件。

注册纪律（比阈值重要）：
- 注册未满 3 条：来什么收什么（还没有中心）；
- 满 3 条后：`same` 用 0.25 学习率正常更新，`uncertain` 用 0.05 慢速跟随，`other` 不收。
  为什么留 0.05 这一档：同一人不同句子的相似度本来就不稳（p05=0.65、均值 0.76），
  只认"same"会让中心永远停在最像的那三句上；而全量更新又会被旁人一句拽走。

## 四、为什么现在**不**开 enforce

因为**没有真人双人语料**。上面所有数字都来自 TTS 五个音色的合成语料，
它只能证明"音色差异可被这套嵌入分开"，不能证明"真人对话里接进去不会误伤"。
没有真机数据就拦截，等于拿演示赌一个没测过的阈值。

要开 enforce，缺的是一次 10 分钟的真实录音（很具体）：

1. 同一个人念 5 句（长短各半）→ 当"本人"；
2. 换一个人（最好同性别）念 5 句 → 当"旁人"；
3. `python scripts/bench_speaker_gate.py` 看新的分数分布，重定阈值；
4. 再决定 `mode` 是否改成 `enforce`。

在拿到这组数据之前，影子模式的价值是：**真实通话里已经开始产 `speaker_gate` 事件**，
攒够样本就能回答"我们这套设备/房间/人群下，分布长什么样"。

## 五、顺带说"语音系统还不够好"

按性价比排，比先啃声纹更值的几件事：

| 优先级 | 事情 | 现状 |
|---|---|---|
| P0 | 端点判定（说完多久算说完） | 已按真机重标（静音 RMS p99=0.0294，连续 4 帧），但**停顿长的老人**仍可能被切句 |
| P0 | 打断判定（客服说话时能不能插话） | 外放回声 max=0.2119、连续 9 帧超阈，已加自回声否决；换设备/换房间要重标 |
| P1 | 说话人一致性 | **本次完成（影子）**：跨性别可挡，同性近音色漏 15% |
| P1 | ASR 热词 | `qwen3-asr-flash` 的 HTTP 接口没有热词字段，config 里的 hints 目前不生效 |
| P2 | 首字时延 | 现网 p50≈580ms 识别 + 首字 ~820ms，离 2000ms 门槛还有余量，不是瓶颈 |

一句实话：**"分不清旁人"不是时延或识别率问题，是物理层问题**（单麦克风、无波束成形、
云端 ASR 不做 diarization）。这次的嵌入方案把"能分多少"量化出来了，剩下的靠语料和真机数据推。

## 六、怎么跑

```bash
# 1) 造多音色语料（5 个音色 × 5 句，约 25 次 TTS）
python scripts/gen_speaker_corpus.py

# 2) 下模型（26MB，带 sha256 与断点续传）
python scripts/fetch_speaker_model.py

# 3) 标定：EER、分时长、音色两两相似度、工作点
python scripts/bench_speaker_gate.py

# 4) 探测云端 diarization 到底支不支持（结论已写进本文第二节）
python scripts/probe_diarization.py

# 5) 总闸门（含说话人门的 5 条断言）
python scripts/verify.py
```

相关文件：

```
modules/speaker_gate.py           嵌入 + 在线档案 + 三态判定
app.py  _speaker_probe()          影子模式接入（写 speaker_gate 事件）
scripts/gen_speaker_corpus.py     多音色语料
scripts/fetch_speaker_model.py    模型下载（sha256 + 续传）
scripts/bench_speaker_gate.py     标定与评估
scripts/probe_diarization.py      云端 diarization 可用性探测
data/speaker_calib.json           标定结果（阈值/均值），运行时只做查表
```
