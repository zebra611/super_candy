# 41 · 逐句复盘：为什么「全是绿的」却「全是问题」

2026-11-11 下午。用户把线上训练回放的一通对话截图发来，问：

> 所以你跑的时候没感觉出来全是问题吗

**答：没有。而且这不是疏忽一句能带过去的。** 当时我报的是
「对抗 17/17、verify 250/250、客户侧覆盖率 0.9、负面 0 条」，
这些数字当时全是真的，但它们**对截图里那类错误是盲的**。
我读的是汇总表，不是逐轮对话。

这一篇把当时看漏的、修的过程中自己又造出来的、以及最后仍然存在的，
一次写清楚。

---

## 一、先看那通对话里到底发生了什么

截图是 A15（留出集·半信半疑的财务），13 轮。逐句摘出来：

| 客户说的 | 客服回的 | 问题 |
|---|---|---|
| 「单号？我只记得尾号，别的记不清了。」 | 「您报的**单号**我这边对得上」 | 客户刚说记不住单号，客服把否认当成确认，后面整通建在错前提上 |
| 「单号？我真记不住，号码 4656 的手机上也没存！」 | 同一句「您报的单号我这边对得上」 | 逐字复读；且只报了尾号，说的却是单号 |
| 「您可以简单回我一句清楚了或者还有疑问就行」×2 轮 | 两轮逐字相同 | 卡带 |
| 「后台审核我看材料页面都打不开」×2 轮 | 把材料清单、驳回原因各念一遍 | 对着一堵墙念清单 |
| 「打错了，没这个人！」 | 「好的，我先按现在的沟通情况记录…」**并写了工单** | 把一通打错人的电话记成「已沟通」 |
| 全程只说「嗯」 | 回写一张 `consent=unknown` 的工单 | 「没得到答案却说知道了」换了个形式，这次写在工单里 |

**为什么 250 条断言一条都没红**：闸门判的是「阶段推进对不对、有没有
writeback 事件、意图标签是不是这几个」，不判「这句话和上一句是不是在说
同一件事」。归因器按 `action` 分桶，客户说「记不住」和「报单号」在它眼里
是两个动作，语义上却正好相反——它测不到。覆盖率 1.0 只说明模型那句没被
闸门打回，不说明那句贴题。

这是结构性缺口，不是「再跑一遍就能发现」。所以补的不是更多汇总指标，
是**直接读对话本身**的回归用例。

## 二、截图里的毛病，逐条修掉

| # | 修法 | 落点 |
|---|---|---|
| 1 | 把「报的是单号还是尾号」分开判；句子里带「记不住/想不起/没存」就不算报信息 | `dialogue._echoed_slot`、`_NO_RECALL_MARKS` |
| 2 | 同一动作最多连来两次，第三次换同族说法；客服确认追问两条话术轮换 | `adversary._vary`、`CONFIRM.reply_again_2` |
| 3 | 「后台打不开/不会弄」独立分支：先接住墙，两次后转专员，**不编入口路径** | `_blocked_ui_reply`（NEED/OFFER/CONFIRM 三处） |
| 4 | 「打错了、没这个人」→ 立即停且 `WRITEBACK` 入口再加一道拦截，一张工单都不写 | `_denies_identity` + `_stage_writeback` |
| 5 | 连续两次含糊**不写工单**，明说「我什么都没记」，留在确认阶段等表态 | `_stage_confirm` |

外加两个从同一份实录里顺手挖出来的：
- **半句**：`_fit` 原来允许在「，、；」处截断，线上出现过
  「…需重新提交品牌授权书、」这种句尾挂顿号的话 → 只认「。！？」，
  断不出完整句就退回骨架（`nlg.py`、`agent_llm.py` 同步）。
- **单号记不住**被判成提问、落到「确认不到」→ 加 `_cant_recall_order`，
  正面告诉他「不用单号，按公司名和尾号认的单」。

这些全部固化进 `scripts/test_train_replay.py`（14 条断言，全离线，
逐句读对话），并接进总闸门证据 36。

## 三、修的过程中，我自己又造了三个回归（这才是重点）

第一版修法把「连续两次含糊」直接改成**转专员收线 + 不写工单**。
方向没错（不替客户编结论），但把「不替客户下结论」做成了
「替客户结束通话」。跑批当场报出来：

| 现象 | 数字 | 真正根因 |
|---|---|---|
| 88 条评测 L02 / L07 不闭环 | 86/88 | `confirm_asks` 是**累计**计数；客户中间问「权益收费吗」「有效期多久」也照攒，两次就收线，后面的「同意」「算了还是不要了」根本没机会说 |
| Q2 课程 Gen3 消耗战 | 8/12 | 客户把同一句抱怨连说四遍，被逐轮计成「含糊」；第三轮收线，后面「那就按你说的办，同意」被挂断 |
| verify | 245/250 | 两条旧断言还钉着「第二次含糊要回写 unknown」；`test_nlg` 断言允许逗号/顿号结尾 |

三处都不是「调一下阈值」能了事的：

1. **累计 → 连续**。`confirm_asks` 改成连续含糊计数，任何实质轮
   （提问答上、路由答上、报信息、说听不清、说后台打不开、明确表态）
   都把观察窗口重开。另外「等等，我先问下收费」不带问号，意图层判不出
   `ask`，补了 `_QUESTION_MARKS` 只收「问下/想问/先问/问一句」这类
   **明确说要问**的动词短语——不放「吗/吧/啊」，否则「可以吧」全变提问，
   闸门就拆了。
2. **连续两次不收线**。明说「我这边先不记任何结论」，留在 CONFIRM；
   连续第三次才交给人。这样「嗯嗯」不产生假工单，客户后面一句
   「那我要吧」仍能正常回写。
3. **客户复读 ≠ 含糊**。新增 `_self_repeated`（difflib ≥0.85，
   **长度下限 4 字**，所以「嗯」「再说吧」这类真含糊不进这条），
   命中就换一种说法承接、不累计含糊、三轮话术轮换不复读。

`verify` 那三条不是「改松断言蒙过去」：
- 证据 5 的两条改成新契约（不写工单 / 不收线 / 明说没下结论 / 之后能正常回写），
  并在注释里写明它们是变异靶子；
- `test_nlg.py` 把「截断」和「不许半句」拆成两条，后者专门守
  「句尾挂顿号」，共 26 条；
- Q2 断言原来只看 `exit code`，**Gen3 8/12 时照样绿**（这个也要记），
  改成逐代读 JSON 通过率，三代都必须 100%。

**变异验证（5/5 精确变红）**：把五处修复逐个改回旧行为——
允许在「、」处截断 / 连续两次含糊直接收线 / 客户复读当含糊 /
核身质疑当噪声 / 后置反问仍当成确认——对应闸门 `test_nlg.py`、
`test_train_replay.py`、课程 Gen3 当场报红，恢复后 sha256 逐字节一致。

其中第 4 项第一版**是假绿**：我造的用例连着两句明确拒绝，
`identity_refusals` 两次就先收尾了，根本没走到 `no_voice` 兜底；
把判据删掉照样全绿。改用 L2 基线里 S05 的六句原话才真正覆盖，
这一点单独写进了用例注释。

## 四、顺带挖出的第六处：核身阶段「装听不见」

L2 基线 S05（拒绝提供信息的商家）第 6 轮：

```
客户：我说，我凭什么告诉你，你先说你是哪个部门的
客服：可能信号不太好，我先不打扰您了，稍后会有专员与您联系，感谢您的接听，再见。
```

根因是 `IDENTITY` 的 `not took` 分支把「没给出可核身信息」一律累计进
`noise_turns`，到 5 轮就甩给链路噪声。注释里明明写着「不等于没听清」，
兜底却仍这么说。改成：**客户在质疑/提问/拒绝 = 人在谈，噪声计数归零**；
纯噪声或答非所问连 5 轮仍走 `no_voice` 收线，明确拒绝核身仍由
`identity_refusals` 两次收尾——闸门没拆。

修完 S05 末句变成「理解您的顾虑，那我不勉强。稍后会有专员用官方号码
联系您，您可以先核实身份」，`agent_noise_on_question` 缺陷码消失。

## 四之二、闸门全绿之后，线上真跑又抓到一处

本地全绿（verify 251/251、88/88、17/17、课程 12/12）之后重新发布，
线上真跑一通 A15 **模型档**。逐轮实录确实干净了：0 次相邻复读、
「您报的单号」「信号不太好」「确认不到」各 0 次。但 `verdict` 仍是**失败**：
A15 是留出集、期望不闭环，实际却闭环了。而规则档跑批 17/17 全过——
**模型档根本没进跑批闸门**，两边判定不一致。

逐句回放定位到第 7 轮：

```
客户：澹台溪亭，记住了没？              （报姓名 + 挑衅）
客服：WRITEBACK→DONE intent=consent     （写了一张同意工单并收线）
```

根因：pop 场景 `confirm_yes_words` 里有「记住了」，而否定检查只查确认词
**前面** 4 个字（用来防「没听明白」），抓不到「记住了**没**」这种后置反问。
这正是用户最早那句抱怨的镜像：不是「用户没得到答案却说知道了」，
是「客服没得到确认，却把挑衅当成确认」。

修两处：
1. `_negated` 同时查确认词后 3 字里的「没 / 吗 / 呢 / 不 / ？」，后置反问不算确认；
2. 修完这一轮仍回「这个我这边确认不到」——客户在报姓名，却因为带问号被
   `_still_engaged` 判成「问了个答不上的知识题」。把「报本单事实」的判据
   提到「提问」之前（真质疑不含档案值，仍走 talk）。现在回
   「好的，收到。咱们回到正题…」并留在 CONFIRM 等表态，一张工单都不写。

回归第 14 条钉住它；变异第 5 项（把后置否定检查改回 `return False`）
精确红 13/14，恢复后 14/14。

**这一节才是整篇的重点**：`verify` 全绿之后，线上真跑仍然抓到了新东西。
汇总闸门覆盖的是「已经想到的形状」，模型客户会说出没想到的形状。
所以交付前除了跑闸门，还得真跑一通、把逐轮实录自己读一遍。

## 五、结果（以及不宣称的部分）

| 闸门 | 结果 |
|---|---|
| `scripts/verify.py` | 251/251（新增证据 36） |
| `scripts/run_eval.py` 88 条 | 88/88｜应闭环 56/56｜误闭环 0/27｜留出 18/18 |
| 对抗 17 条 | 17/17（train 11/11、holdout 6/6、系统缺陷会话 0） |
| Q2 三代课程 | Gen1 40/40、Gen2 24/24、**Gen3 12/12** |
| 逐句复盘回归 | 14/14 |
| 离线自测 | `test_nlg` 26、`test_llm_layer` 43 |
| 变异 | 5/5 精确红 |
| L2 基线 | v26 → v30（`rebase`，`doctor --deep` 三处一致，复算 10/10） |

**不宣称的**：L2 基线里还剩 1 个 `agent_no_progress` 缺陷会话（S05）。
客户 6 轮拒绝核身，系统按安全规则**不该**推进阶段，归因器却把
「客户不配合」记成「客服无进展」。这是归因口径问题，不是客服瞎答；
改它会动历史基线的可比性，所以本轮不动，如实留着。

上一轮记的那个数据根因也**仍未根治**：97 条有官方话术的单里只有 19 条
（20%）话术与自己的驳回原因讲同一件事，中位重合度 0.11。当前只加了
覆盖度闸门（对不上就不念官方原话，改说档案自己的原因）。要根治得改
`scripts/gen_mock_applications.py` 的原因池再重生成 120 条——这是下一轮
第一优先级，比继续调客服话术值钱。

## 六、怎么自己复现

```bash
python scripts/test_train_replay.py        # 14 条：直接读截图那通对话
python scripts/verify.py                   # 251 条总闸门（含证据 36）
python scripts/run_eval.py L02 L07         # 长对话里隔着提问的明确表态
python scripts/course_evolution.py --self-test   # Gen3 消耗战
python scripts/evolve.py doctor --deep     # L2 基线三处一致
```

**一句话教训**：汇总指标验收的是「流程有没有走完」，不是「话有没有说对」。
以后每次交付前，除了看分数，至少打开一通完整逐轮实录自己读一遍。
