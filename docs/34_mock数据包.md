# 34 · mock 数据包：从「8 条自造原因」到「官方 68 场景全覆盖」

> 一句话：把赛题给的两份 xlsx **机械转成**结构化数据，再按目录补齐档案，
> 让 mock 能照着官方资料包说话；同时**不动**任何既有文件与既有引用。

---

## 1. 为什么要重做

原来的 mock 只有三类东西：

| 原来有什么 | 缺口 |
|---|---|
| `applications.json` 120 条档案 | 驳回原因只有 **8 条自造说法**（每个业务域 4 条），口径与官方对不上 |
| 内置 2 个客户（C1001/C1002） | 售后/召回场景只够跑通，谈不上"覆盖" |
| 内存工单 | 没有历史工单可查 |

官方资料包里其实写得很细：

- **68 个关单场景**（一级菜单 / 一级分类 / 二级分类 / 关单方式 / 参考话术）；
- **52 条驳回话术**（开头语 + 驳回语 + 结束语，含 4006180092 兜底热线）；
- **高频 QA 11 条 + 特殊场景追问 16 条**（官方原话，可直接复述）。

演示时商家说"商标状态不符合要求"，系统却回另一套自造原因——评委一眼能看出来。
所以这次不是"多加几条假数据"，而是**把官方口径变成机器可读的数据**。

## 2. 做了什么（文件即契约）

```
config/mock/
  catalog.json                   68 个官方关单场景（id / 菜单 / 分类 / 关单方式 / 话术 / 需补材料 / 热线）
  rebuttals.json                 52 条驳回话术（逐字保留官方原文）
  qa.json                        27 条问答（高频 11 + 特殊场景 16，已去重）
  applications.json / .csv       原集 120 条（结构不变，修掉 14 条自相矛盾）
  applications_catalog.json/.csv 官方场景 68 条（一场景一条）
  customers.json                 12 个客户（含原 C1001/C1002 同值）
  orders.json                    16 笔订单（query_order 取最近一笔）
```

运行时申请单池 **= 120 + 68 = 188 条**，由 `MockAdapter._load_applications()` 合并，
**原集排在前面**——这样 `next_outbound_target()`（取第一条待外呼）与 `get_application()`
（按单号精确取）的行为与只有原集时完全一致，新增数据只增覆盖、不改既有路径。

### 为什么是"并列新增"而不是"整份替换"

原集是**评测基线的一部分**：`verify` 证据 21 的 C5 断言、C4 的 340 条对抗用例、
`eval/seed_cases.json` 的 88 条用例，都按"尾号 / 申请单号"直接引用它。
整份替换等于把基线一起换掉，跑出来的分数就说不清是数据变了还是系统变了。

所以取舍是：**原集保留 + 官方场景另起一份**，两份合并成完整池。
代价是 188 条里有两套命名风格（`QZ20261106xxxx` / `QZ20261201xxxx`），
换来的是"任何既有断言都不用改"。

## 3. 接口与默认返回值

`BaseAdapter` 新增三个只读方法，**默认实现返回空结果，不抛异常**：

| 方法 | 返回 | provider 没接这张表时 |
|---|---|---|
| `reject_catalog()` | `{found, items[], count}` | `{found: False, items: [], count: 0}` |
| `reject_script(code)` | `{found, scene}`，`code` 支持场景 id 或二级分类关键词 | `{found: False, scene: None}` |
| `lookup_qa(question)` | `{found, answer, match, qid, source, score}` | `{found: False, answer: ""}` |

为什么要放默认实现：`call()` 里是 `getattr` 取方法，真实适配器没实现就会
**AttributeError 直接冒到编排层**——一通电话不该因为"这版适配器还没接某张表"崩掉。
只读方法出错/超时也会补 `found=False`（`READ_METHODS` 集合），与 `query_*` 同一口径。

`lookup_qa` 故意很笨：官方问句切 2/3/4 字片段做包含匹配，**必须命中至少一个 4 字片段**
才算找到。只命中"怎么""可以"这类 2 字片段宁可返回"没找到"——
这里要的是"能不能复述官方原话"，猜得像但没出处比不答更危险。

## 4. 一致性怎么保证

`scripts/check_mock_bundle.py` 查七类（都挂在 `verify` 证据 32）：

1. **文件齐全**（9 个文件）；
2. **官方目录**：68 条、id 连续、关单方式 电话 54 / 京麦 14、业务域在枚举内、每条有话术或显式标 `script_missing`；
3. **话术与 QA**：话术非空、QA 问题不重复且都有答案；
4. **覆盖与回溯**：68 个场景每个都有档案、`reject_code == catalog_id`、`close_mode`/`reject_category` 与目录一致；
5. **合并池唯一**：14 组字段（单号/尾号/公司名/电话/信用代码/身份证…）全局不重复；
6. **客户↔订单**：订单必须挂在存在的客户上、每个客户至少一单、C1001 最近一笔是 `O20261101001`；
7. **可复算**：重新跑三个生成器，产物 sha 必须一致。

带 `--self-test`：故意制造 6 种坏数据（少一条场景档案 / reject_code 不可回溯 /
关单方式不一致 / 尾号重复 / 订单挂空客户 / 目录缺一条），**每一种都必须被抓到**。
这条是为了防"校验器自己假绿"——校验器全绿但抓不到错，比没有校验器更危险。

### 校验器当场抓到的两个真问题

1. **原集 14 条「关单方式=电话 却标 call_status=无需外呼」**：
   `CALL_STATUSES` 轮转把"无需外呼"发给了电话单。这类记录永远不会进外呼名单，
   看板上却显示"电话单不用打"，归因时会被误判成系统漏呼。已在生成器里修掉
   （电话单遇到"无需外呼"改记"待外呼"），原集指纹随之变化，但字段结构与引用不变。
2. **QA 有一条问题重复**（"这个我补上来了就可以通过了吗"出现两次），已去重。

## 8. 官方 QA 接进对话（11-08）

### 8.1 为什么不是"直接调 lookup_qa 就完了"

`tools.lookup_qa()` 只能回答"这条问句像不像库里的某条"。接进对话要另外决定四件事，
这四件事才是这一节的全部内容：

| 决策 | 选择 | 理由 |
|---|---|---|
| 和 `kb.json` 谁优先 | **官方 QA 优先** | 官方是审核员原话，能逐字复述；kb 是我们自己的口径，可改写 |
| 播报要不要过措辞层 | **不过**（`_reply` 里 `qa_hit` 存在即冻结） | 改一个字就不再是"官方原话"，被追问依据时站不住 |
| 答案里有 `XX` / `【】` 怎么办 | **整条不播** | TTS 会念成"叉叉""左右括号"；自己补词是编造官方口径 |
| 同一条问两遍 | **第二遍不播原话**，退回原路径 | 逐字复读像卡带；但也不能沉默，所以给"记下了、稍后专员" |

### 8.2 接在哪几个出口

六个阶段、七个分支（GREETING 分了"已确认公司/未确认"两条），都是**用户提问**的出口，
且都只影响这一轮、不推进阶段：

| 阶段 | 原行为 | 现在 |
|---|---|---|
| GREETING（未确认公司） | 只重复"您是XX公司吗" | 先答，**仍把确认公司的问句放回去**（赛题四段式②不能省） |
| GREETING（已确认） | kb 命中就答 + 问尾号 | 官方优先，再 kb，最后问尾号 |
| IDENTITY | kb 命中就答 + 问尾号 | 同上 |
| NEED | 一律念整段驳回详情 | 先答具体问题；答不上才念详情 |
| OFFER | kb → fee → validity → reply_unknown | 官方 → kb → 同上 |
| CONFIRM | **提问被当成含糊**，两次就记 unknown | 答得上就先答 + "您看这样解释清楚了吗？"，**不计 `confirm_asks`** |
| DONE | 只念热线 + 再见 | 先答，热线与再见照旧（兜底路径不能丢） |

CONFIRM 那条是这轮顺手修的真实缺陷：商家问"这个会不会影响我店铺评分"，
旧行为回的是"您简单回我一句清楚了或者还有疑问"，两轮之后工单记 unknown 转专员。
现在只在**真的答得上**时才拦——答不上仍走原逻辑，否则任何带问号的句子都能免掉一次确认追问。

### 8.3 可观测

`agent_reply` 事件新增两个可选字段（只在真的引了资料时才写，不写空壳）：

- `qa`：`{id, source, match, score}`——命中的官方条目（如 `QA-HF-003` / `高频QA`）；
- `kb`：`{id, category, source_id, score, matched}`——命中的知识条目。

这两者分开记，是为了答辩时能分清"哪句是官方口径、哪句是我们的解释"。
被挡下的不播记录在 `session["answer_blocked"]`（`via=qa|kb`、`reason=placeholder|too_short|repeated`），
用于事后回答"这句为什么没答"。

### 8.4 自检

- `scripts/test_qa_dialogue.py`（15 条）：正向 7 条（各阶段播原话、不改写、不计含糊、热线仍在、
  确认公司不被吞、补齐后可播）+ 负向 6 条（占位不播（注入式）、kb 模板不播、闲聊不编、
  同句不复读、单通限额 4 条、接口异常降级）+ 工具 2 条。
- `verify.py` 新增 3 条证据：OFFER 逐字播 / CONFIRM 不计含糊 / 27 条答案无占位且补齐后可播。
- 语料侧的坑：`ASK_MARKS` 原来没有"哪些""如何"，于是官方问法"在职证明有哪些""如何上传联系方式"
  **判不成提问**，QA 永远接不上——这两个词是这轮补的。

## 9. 随机预览展示的公司信息：去机器痕迹 + 补 XX（11-08）

### 9.1 为什么动它

测试页的「随机预览」把一条档案的 34 个字段直接铺在卡片上，是演示里最显眼的一块。
接进来的数据本身齐全（34 个字段 188 条无空缺），但**名字是程序拼的**：

| 字段 | 改之前 | 改之后 |
|---|---|---|
| 公司名 | `…商贸有限公司第097分部`、`…百货经营部（001）`、`…商贸外商投资企业` | `…商贸有限公司`、`…百货经营部`、`…商贸合伙企业（有限合伙）` |
| 店铺名 | `麦冬官方旗舰店42`、`柏庐官方旗舰店场景01` | `麦冬官方旗舰店`、`柏庐官方旗舰店（二店）` |
| 注册地址 | **188 条共用** `…创新大道760号18层` | 真实省市区 + 常见路名 + 虚构门牌，如 `上海市普陀区中江路45号A座3层` |
| 商标注册号 | `TM90768143` | `30102947`（真实号段就是 8 位数字） |

机器痕迹的代价不是"不好看"，是**让人先怀疑数据、再怀疑系统**：
连着点三次随机预览，三次都看到"XX省创新大道 760 号 18 层"，
第一反应是"这系统在放同一份假数据"，而不是"这家公司被驳回了"。

### 9.2 怎么改的（三条约束）

1. **数据必须可复算**：改生成器（`gen_mock_applications.py` / `gen_mock_catalog_applications.py`），
   再重新生成 JSON/CSV，而不是手改数据文件。`check_mock_applications.py` 做字节级复算，
   `check_mock_bundle.py` 做跨文件一致性，两边都过才算改对。
2. **不碰被引用的键**：单号 / 尾号 / 电话 / 公司名唯一性 / 字段集一律不变，
   `verify` 的 C5 断言、88 条评测用例、340 条对抗用例都按这些键引用数据。
3. **名字要像真的，但不撞真实主体**：路名是地理信息（不指向企业），
   字号与品牌全部自造，地址门牌由序号算出，`fictional_marker` 保留。

### 9.3 校验器当场抓到的两个问题

- **`南京东路` 里含"京东"** → 虚构性黑名单（真实企业关键词）报红，已换成`信义路`。
  这正是"改数据必须过校验器"的价值：肉眼不会注意到两个字的重叠。
- **新疆两条地址只有两个元素**（少了"区"），地址拼装直接在 `unpack` 处抛异常——
  没有静默降级，坏数据进不来。

### 9.4 官方 QA 的 5 条 `XX` 补齐

| 条目 | 补什么 | 依据 |
|---|---|---|
| QA-TS-003 | 状态变为**已注册**后重新提交；提供**已注册**状态的**同类**有效商标 | 同一场景其他话术均以"已注册/初审公告"为可申请状态 |
| QA-TS-005 | 等待期**满之前**状态变更即可直接申请，**不用等满整段时间** | 原句逻辑：状态变更早于等待期结束即可 |
| QA-TS-012 | 没查到**直接持股或同一法人**关系 | 原句"XX%持股或同法人"的语义等价表述 |
| QA-TS-013 | 通过**品牌方官方渠道**联系**授权负责人** | 授权域通用口径，不指向具体人/渠道 |
| QA-TS-016 | 再授权**对应类别**商标 | 原句"XX类商标"= 与申请类目对应的商标 |

补齐的边界写死在代码里（`build_mock_bundle.QA_FILL`）：
**只补占位符，不新增业务结论**；每条的原文都留在 `answer_raw`，
校验器硬性要求"`answer` 里不许再有 `XX`、`filled_placeholder` 必须配 `answer_raw`、
补齐条数必须正好 5 条"——补多了补少了都会报红，不允许悄悄漂移。

## 10. 官方【】话术填槽：随机预览看得见场景、电话里听得见原话（11-08）

### 10.1 起点：一句"填不满的整条不播"留下的坑

上一轮的边界写得很清楚：`kb_pop.json` 的 96 条驳回话术全是 `【】` 模板，
填不满就整条不播。守住了"不把括号念出去"这条底线，但代价是
**商家问"为什么驳回"时客服几乎答不上来**——模板永远填不满，于是永远沉默。
队长的要求是"把这些都添置到随机预览中的随机场景，不要让语音空出来 XX"，
拆开是两件事：预览里要能看见这次随机到的**驳回场景**，语音里要能听见**填满的原话**。
两者必须共用同一套渲染，否则卡片上写一套、电话里念另一套，演示当场就穿帮。

### 10.2 填槽：词从哪来

`modules/official_script.render_script(answer, app, item_id)` 逐槽判断，
值全部来自本通档案，**不编事实**：

| 槽位上下文 | 填什么 | 来源 |
|---|---|---|
| `您申请的【】品牌` | 品牌名 | `brand_name` |
| `商标状态为【】故不符合要求` | `待审` | 当前状态（不合规） |
| `提供【】状态的【】类商标` | `已注册` / `对应` | 要补的状态 |
| `缺少【】到【】的授权关系` | `品牌方` → `贵公司` | 按前后文判第一/第二个空 |
| `【】资质上传错误` / `协助操作【】` | 需补材料第一项 / `重新上传正确的资质` | `required_materials` |
| `店铺名称【】不符合命名规则` | 店铺名 | `shop_name` |

两处语义坑是实测踩出来的，都写进了代码注释：

- **"状态为【】"和"提供【】状态"意思相反**，一开始都填 `已注册`，
  句子变成"状态为已注册故不符合要求，需提供已注册状态的商标"——自相矛盾。
- **"因商标注册时间【】，请【】后再重新提交"**：第二个空的上下文窗口里
  同样含"注册时间"，先判"注册时间"就把它填成"请不符合平台要求"。
  判据改成"前文以『请』结尾优先"，顺序换过来才对。

另外 5 条 S 系列话术原本带 `XX`（和 `qa.json` 的特殊场景问答是同一句话），
用 `SCRIPT_OVERRIDES` 做**播报替身**，文案与 `QA_FILL` 逐字一致——
同一个问题从 QA 通道问和从知识库通道问，不能听到两个版本。
原文仍留在 `kb_pop.json` 里供审计。

### 10.3 场景与档案对齐：原来 28 条指到了不存在的模板

legacy 档案的 `reject_code` 原来是 `(idx*7)%96` 硬取序号：
**28 条指向 `KB-POP-069..096`（kb_pop 根本没有这些 id）**，
剩下的一半串到别的业务域（"品牌-商标"的单子念"公司主体"的话术）。
改成 `official_script.best_code(业务域, 驳回原因)`：用模板自带的 `patterns`
在原因里做词长加权，本域只命中"品牌"这类 2 字泛词时跨域兜底。
效果是"原因说授权链不完整，就念授权链那一段"，而不是念商标注册时间。

生成器 `gen_mock_applications.py` 直接 import 这个模块取候选池——
**数据要能对着话术自洽**，在脚本里另抄一份 id 清单早晚会跟 `kb_pop.json` 漂移。

### 10.5 守住"不让语音空出来"的三道闸

1. **填不满就不播，两个分支都必须 `return`**：本轮实测漏过一个 return，
   结果把"您申请的【】品牌"原文送进 TTS。`test_qa_dialogue` 的
   `test_kb_template_is_filled_or_muted` 现在同时测"有档案"和"无档案"两种会话，
   断言语种里不许出现 `【`/`】`/`XX`。
2. `check_official_scripts.py`：电话单必须有话术、京麦单不许配、所有话术无残留占位、
   模板可追溯、跨文件一致；`--self-test` 三种变异（京麦单配话术 / 被引用模板塞 `XX` /
   删掉替身）**必须全部报红**才算校验器有效。
3. `verify.py` 挂 2 条证据：跑一遍 `--self-test`；NEED 阶段真实回复不许含占位。
