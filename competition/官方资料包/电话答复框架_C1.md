# C1 电话答复框架：POP 资质审核驳回外呼（v1.0，2026-11-06）

> 依据：`config/kb_pop.json`（96 条官方原文）+ 官方 docx 第七节必答要素。
> 用途：黄睿哲出场景包骨架、佟欣填话术的直接施工图。
> 三步产出：①拆分回答 → ②分类 → ③答复框架。

---

## 一、拆分回答：68 条官方话术的共有骨架

对 68 条场景话术逐条切段，**97% 的条目收敛到同一条 7 段骨架**：

```
①称呼        商家伙伴您好（39/68 显式，其余可补齐）
②自报身份    我是京东资质审核专员（建议统一，官方部分条目省略）
③定位申请    您申请的【品牌名】品牌 / 您提交的【类目】资质（53/68）
④驳回原因    因【驳回原因】…（33/68 显式"因"字句，其余同义）
⑤整改动作    请您提供/修改/重新提交【材料】（36/68）
⑥热线兜底    如有疑问可电话联系 4006180092（66/68）
⑦结束语      我们将竭诚为您服务（66/68）
```

**施工含义**：电话里不能照念书面语。⑦段书面腔（"竭诚为您服务"）在电话里改口语
（"还有问题随时打这个电话"）；⑥段热线保留（转人工兜底的合规依据）；①②③④⑤
是语音必答要素，缺一不可（官方评分标尺的前三项正好映射）。

### 占位符两套体系（官方最大的坑，必须先判别再渲染）

| 形态 | 数量 | 语义 | 电话渲染策略 |
|---|---|---|---|
| `【】`（空） | ×98 | **每单变量**：品牌名、类目、驳回原因细节、整改期限 | 运行时由申请单槽位填充；填不出 → 读"您的该笔申请"并降级 |
| `【XXX】/【XX】/【该品牌暂不招商…】` | ×21 | **原因话术的一部分**（如"需提供【XXX类】商标"） | 不是变量！原样读或按分支替换；**不能当变量填空** |

> C2 已实现占位符适配（#25），此表是它的赛题版判别规则。

## 二、分类：68 条怎么进对话

### 2.1 关单方式（第一刀，硬分支）

| 关单方式 | 条数 | 电话策略 |
|---|---|---|
| **电话外呼** | 54 | 走完整四段式（见第三部分） |
| **京麦驳回** | 14 | **不外呼**。若电话误触达：一句话告知"您该笔申请的驳回说明已发送至京麦后台，请查收站内消息"，直接进结束。kb_pop 已带 `_close_mode` 字段，检索层过滤 |

### 2.2 业务域（第二刀，槽位决定）

| 业务域 | 条数 | 核心槽位 | 例 |
|---|---|---|---|
| 品牌-授权 | 26 | 品牌名 + 授权链路环节 | 授权书过期、链路不完整、授权范围选错 |
| 商品/行业资质 | 20 | 类目 + 资质类型 | 行业资质缺失、单品资质、清场/管控 |
| 入驻-主体/店铺 | 10 | 公司主体 / 店铺名 | 法人证件类型错、税务号不符、店铺名违规 |
| 品牌-商标 | 6 | 品牌名 + 商标状态 | 状态不符、注册时间、资质造假 |
| 品牌-全球购 | 6 | 品牌名 + 采购链路 | 全球购特有链路要求 |

**检索键设计**：`业务域(5) → subcategory(68) → 关单方式`，三级路由。商家报不出
细分原因时，用「业务域 + 材料类型」二段匹配，命中多条则列菜单让商家选（"是授权书
的问题还是发票的问题？"）。

### 2.3 追问应对（17 条追问剧本 → 5 类问题 → 框架位置）

| 追问类型 | 官方剧本 | 答复框架位置 |
|---|---|---|
| 门槛标准（多少件/什么状态才行） | S01 S02 S05 | NEED 补充段：直接报门槛数字 |
| 知识来源（去哪查） | S03 S06 | OFFER：报查询渠道（国家商标网/权大师） |
| 操作路径（怎么传/怎么选） | S11 S16 S17 | OFFER：报操作位置（授权书位置下方方框） |
| 质疑合理性（为什么不行） | S04 S12 S15 | 致歉 + 复述规则依据 + 转品牌方核实路径 |
| 结果预期（传了多久过） | S07 S13 S14 | OFFER 收尾："上传后我们完整审核后才能确定，有问题会再联系您"——**不许承诺通过**（合规红线） |

## 三、电话答复框架（pop_reject 场景包施工图）

### 3.1 六阶段状态机（复用现有引擎，只换内容层）

```
GREETING ──▶ IDENTITY ──▶ NEED ──▶ OFFER ──▶ CONFIRM ──▶ WRITEBACK ──▶ DONE
 自报+来意    确认公司名    驳回告知    追问应对    复述确认      记录回写      结束
              +是否负责人   (胜负手)   (5类问题)   (必答要素4)
```

### 3.2 各阶段模板与槽位

**GREETING**
```
您好，我是京东资质审核专员，您提交的资质申请没有通过审核，
给您打个电话说明一下原因和后续怎么处理，您现在方便吗？
```
槽位：无。分支：不方便 → 改约/留短信，`DONE end_reason=callback`。

**IDENTITY**（双槽：公司名 + 是否负责人；**吸收 T17 三教训**）
```
想跟您核对一下，您是【公司名】的负责人吗？
```
- 裸报公司名（"是XX有限公司"）→ **直接收槽**（T7 路径，验收硬项）
- 公司名格式不全 → 原地引导"您再说一下公司全称"，**不轮换槽位**（T17-①）
- 反问"什么事/干什么" → 致歉 + 复述来意（T17-②）
- 非负责人 → "麻烦您转告负责人，或留个联系方式我们再约"，转留言路径
- 糊脸输入 → 致歉完整重问一次再考虑收尾（T17-③）

**NEED（胜负手，必答要素②③）**
```
是【品牌名】品牌的申请，因为【驳回原因④】，需要您【整改动作⑤】。
```
- 检索：业务域 → subcategory → ③定位。**驳回原因一句话说完，整改动作一句话说完**——
  分成两个短句是给 TTS 分段用的（每段 ≤60 字）
- 商家报不出是哪笔申请 → 列菜单："是商标的问题，还是授权书的问题？"

**OFFER（追问应对，见 2.3 表）**
```
（按追问类型路由到官方剧本答案；结束固定加）
您材料上传之后，我们会完整审核后才能确定结果，有问题会再跟您联系。
```

**CONFIRM（必答要素④）**
```
我跟您复述一下：您是【品牌名】因为【原因摘要】，需要【整改摘要】，
你看我说得对吗？
```
- 商家确认 → WRITEBACK；不确认 → 回 NEED 重讲一次；两次不确认 → 记录 + DONE

**WRITEBACK**
```json
{"reject_category": "业务域", "reject_code": "KB-POP-0XX",
 "close_mode": "电话|京麦", "merchant_understood": true|false,
 "callback_needed": false}
```

**DONE**：官方结束语口语版 + 热线 4006180092（⑦⑥段合并，不超 40 字）。

### 3.3 特殊路径（全部要有对抗用例，接 T17 素材风格）

| 路径 | 处理 |
|---|---|
| 查无此申请/公司名对不上 | 致歉 + "我核对一下再给您回电"，转留言，**不硬报原因** |
| 商家质疑造假判定（KB-003） | 特别柔："这边显示信息存在失真，如果您确认是真实的，请通过热线 4006180092 申诉复核"——不与商家争辩 |
| 商家情绪激动 | 现有 T8 情绪路径：致歉 + 暂停推进 |
| 京麦驳回误触达 | 一句话 + 结束（见 2.1） |
| 静音/含糊 ≥3 | 现有 T12 退出路径 |
