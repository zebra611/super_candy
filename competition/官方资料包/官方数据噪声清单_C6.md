# C6 · 官方数据噪声清单（逐条标注 + 答辩口径）

> 数据源：`competition/官方资料包/资料包提取.md` 第六节「数据特点与使用提示」
> 官方自曝 7 点；本清单补 2 类我们实测发现的问题，合计 **9 类**。
> 原则：**原文一字不改，噪声只在条目上标注，处理动作显式可查**，不静默清洗。
>
> 机器可读清单：`config/kb_pop.json` → `_meta.noise.classes`
> 条目级标注：每条的 `noise` 数组、`placeholder_style`、`no_call` 字段
> 生成/校验：`scripts/gen_c6_annotations.py` / `scripts/check_c6_annotations.py`

---

## 一、为什么先把噪声列清楚，而不是先清洗

官方给的是**真实业务文档，不是标注好的训练集**。直接当训练语料会把
评审批注、残缺半句、京麦站内指引一起念给商家听。更麻烦的是，静默清洗
之后没人能证明"哪些是官方原文、哪些是我们改的"——评委一问就答不上。

所以做法是三层：

1. `answer` 保留官方原文，**一个字不改**（校验器会逐条比对，改了就报红）；
2. 噪声写成条目上的 `noise: ["C6-01", ...]`、`placeholder_style`、`no_call`；
3. 处理动作发生在**检索层与渲染层**，且可枚举、可复算。

## 三、条目级标注统计（可复算）

`config/kb_pop.json` 共 **96 条**：场景汇总 68 + 高频 QA 11 + 特殊场景追问 17。

| 项 | 数值 |
|---|---|
| 带 `noise` 标注 | 85 条 |
| 标注次数 | C6-01 ×64、C6-05 ×68、C6-07 ×17、C6-04 ×2、C6-03 ×2（一条可多标，合计 153） |
| `placeholder_style` | `blank` 38 / `named` 10 / `mixed` 16 / 无占位符 32 |
| `no_call` | **16** = 京麦类目 14 + 空话术 2 |
| 空 `answer` | `KB-POP-016`、`KB-POP-047` |

**两套占位符体系必须分开**（C6-01 的核心）：
- 空 `【】` ×98：每单变量，`kb.render` 填入真值，填不上进 `missing`；
- 具名 `【XXX类商标】` ×21：是**原因话术的一部分**，原样念出，
  不替换、不删除、不编造。把两者一视同仁是这套数据最容易踩的坑。

**`no_call` 的语义**：电话场景检索层直接跳过，`match()` 永不返回，
`explain()` 里带 `reason=no_call` 可见。这样京麦站内指引和空话术都不
会被念出来，但原文仍在库里可查——不是删数据，是隔离。

## 四、校验与复算

```
python scripts/gen_c6_annotations.py        # 确定性重生成，重复跑逐字节一致
python scripts/check_c6_annotations.py      # 覆盖 / 原文完整性 / 空话术隔离 / 可复算 + 反向自测
python scripts/test_noise_robustness.py     # C6-09 连续 3 轮噪声实测
python scripts/test_noise_robustness.py --self-test
python scripts/verify.py                    # 证据 22 已挂总闸门
```

校验器自带 **4 类变异反向自测**（标错噪声码 / 删掉噪声类别 / 改写官方原文 /
重复生成不一致），防止校验器自己假绿。C6-09 另有 2 组变异
（容忍度退化、双通道失效），全绿之后必须能报红。

## 五、答辩展示口径

> **问：官方数据直接拿来用了吗？**
> 没有。我们逐条标注了 9 类噪声，原文一字不改，处理动作全部显式可查。

> **问：举个最危险的例子？**
> 占位符有两套：空的【】是每单变量，【XXX类商标】是话术正文。
> 把后者当变量替换，一句话就念坏了；还有 2 条场景只有分类没有话术，
> 直接检索命中会播出空回复——这 16 条现在在检索层隔离，转专员兜底。

> **问：你们自己发现了官方没提的问题吗？**
> 有。追问剧本 17 条只有答案没有问句，检索永远命中不了；以及关单总数
> 官方文字 55/13 与结构化数据 54/14 差 1，我们以数据为准并把差异写进清单。
> 另外真实通话里发现 ASR 噪声会挂断在线用户，这是官方数据完全没有的一类。

## 六、边界（不夸大的部分）

- 本清单**不修官方原文**，只标注与隔离；C6-04 的两条错配仍保留原分类，
  靠路由键规避，没有"纠正"数据。
- C6-08 的「工号」在官方 QA 原文里还在，本库 96 条已剔除；答辩时要说清
  剔除的是入库范围，不是官方文件被改了。
- C6-09 的文本层防护**不等于降噪**，做不到听清或区分旁人声与用户声，
  详见 `docs/25_噪声与降噪.md` 第六节。
